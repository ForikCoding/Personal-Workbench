# 运行级「运行指令」：卡片说做什么，运行说做哪个

> **状态：设计，未实现。这一轮只出原型，不动代码。**
> 原型：`docs/prototypes/workbench-run-note.html` · 截图：`docs/prototypes/shots/run-note-*.png`
>
> **怎么看**：直接打开 html。B 面板可以打字（改「运行指令」，预览跟着变），B、C、D、F 面板的步骤标签都能点。
> 验过的：点标签换步骤时，上面两块一字不变、最后一块每步不同；清空运行指令后该块消失、注脚回到"可以不填"；`{任务编号}` 换成本次的值；不认识的名字原样留着；没有值的流水线面板里没有「运行参数」这一块；老卡片面板在第 2 步出现迁移提示。

要解决的是这句话：

> 我不想在每一张卡片上指定任务编号，我在运行时指定如：完成 xxxx 任务从需求到交付，那任务分析卡片读取 xxxx 做任务分析，详细设计则读取 xxxx 做详细设计。

**前提（上一版我理解错的地方，已改）：卡片上的指令是必需的，而且每张卡不同。运行指令不许覆盖它。** 运行指令只补一件事：这一次是哪个任务。

## 二、需求（四条）

1. **卡片不被覆盖**：任务分析那张卡永远做任务分析，详细设计那张卡永远做详细设计。运行只补"哪个任务"。
2. **一次说清**：任务只在运行时说一次，不写进任何卡片。
3. **每步都收到**：这句话对这次运行的每一步都成立。
4. **不填也行、没值也问**：不填就是今天的行为；没有 `{token}` 的流水线也要弹这个框，因为那句话跟任务号无关。

---

## 三、方案

| 方案 | 做法 | 判定 |
|---|---|---|
| **A 运行级运行指令** | 弹框里加「运行指令」多行框，随这次运行进每一步的提示词，**与卡片指令并列** | **做** |
| **C 值作为文本交给模型** | 提示词里加 `<run_values>`，明写成 `任务编号: T202608242753` | **做** |
| **B 卡片指令里也支持 `{任务编号}`** | 卡片上写"以 {任务编号} 为准"，每次运行自动填 | **缓** |

**为什么 A 和 C 必须一起做。** A 只给"这一次做哪个"这句话；但模型手里从来没有一个叫"任务编号"的东西（事实 4）——它只在路径里见过那个号。只做 A 时，用户会写"完成 T202608242753 任务"，能生效；但如果他写的是"按这个任务号"，模型无从对应。C 让值和名字一起到，A 的那句话才站得住。

**为什么 B 缓。** 弹框里这个新字段**已经**支持 `{任务编号}`（预览里看得见替换结果），所以"一次写、每次自动填"这件事已经能做到了：把「完成 {任务编号} 任务，从需求到交付」填进运行指令，任务号一改，整句跟着变。B 只剩"卡片上那句也支持变量"这一半，收益小于它带来的语义变化（已存的卡片指令在运行时被改写）。

## 四、交互规格

### 4.1 弹框（640px）

```
运行 · 需求到交付                              3 个步骤 · 从头跑一遍
──────────────────────────────────────────────────────────────────
任务编号   [T202608242753          ]
           第 1–3 步的产出目录要用它
──────────────────────────────────────────────────────────────────
运行指令   ┌────────────────────────────────────────────────────┐
           │ 完成 {任务编号} 任务，从需求到交付                 │
           └────────────────────────────────────────────────────┘
           三步都会收到 · 只对这一次运行有效
──────────────────────────────────────────────────────────────────
每一步收到的话                          第 1 步  第 2 步  第 3 步
           <运行参数>  任务编号 T202608242753
         ▌ <运行指令>  完成 T202608242753 任务，从需求到交付
           ──────────────────────────────────────────────
           <这一步的指令> 输出详细设计，覆盖接口与异常分支
           上面两块每一步都一样，最后一块每步各是各的。
──────────────────────────────────────────────────────────────────
[取消]                                                  [开始运行]
```

三件新东西：

1. **「运行指令」框**：值下面、目录预览上面。2 行起，最多长到 5 行。
2. **「每一步收到的话」预览**：按步骤分页。上面两块（运行参数、运行指令）**每一步一字不变**，用一道虚线跟最后一块（这一步的指令，每步不同）分开。这就是"卡片没被覆盖"的证据，不用相信，直接看。
3. **老卡片迁移提示**：某一步的卡片指令里还抄着这次的值，就在那一步下面说一句；只提示，不动手。

没有值的流水线：整个框只剩「运行指令」一个字段，预览少一块「运行参数」，标题照旧。

### 4.2 状态与文案

| 状态 | 表现 |
|---|---|
| 未填（默认） | 框空，注脚「可以不填 · 填了三步都会收到」；预览只剩「运行参数」+「这一步的指令」，脚注「没有这一句时，每一步只拿到卡片上的指令」 |
| 有内容 | 注脚换成「三步都会收到 · 只对这一次运行有效」；预览多出 accent 竖线标出的「运行指令」块 |
| 写了 `{任务编号}` | 预览里显示替换后的值；写到不存在的名字，原样显示 |
| 超长（>2000 字） | 计数变红 +「太长了，最多 2000 字」，不开始运行 |
| 单步重跑，上次有指令 | 预填上次那句，上方 chip「沿用上次运行的指令」+「改」 |
| 单步重跑，上次没有 | 框空，上方一句「这次没有指令」+「加一句」 |
| 老卡片里还抄着号 | 那一步下面一句「这张卡的指令里还写着 T202608242753，这个号现在从运行参数来 —— 卡片里那句可以只留"做什么"」 |

### 4.3 什么时候问

**每次运行都问一次。** 整条运行、从第 K 步起跑、单步重跑，都先过这个框（「重新生成」走它自己那个框，见第九节第 2 条）：

- 有 `{token}`：先问值，再问运行指令（同一个框）。
- 没有 `{token}`：只问运行指令。**这一条改了今天的行为**（事实 8）。
- 代价是一次点击，回车确认。预填着上次那句，回车就是"就这样跑"。

### 4.4 这句跟着哪一次运行走

> **一句规则：运行指令是"这一次运行"的事实，存在这次运行的记录里；重跑同一条流水线时自动沿用上一次那句，并在弹框里看得见、能改。**

整条运行、从第 K 步起跑、单步重跑都带着它；关掉页面再回来还在；清空就没有了。**永远不写进卡片。**

## 五、提示词（实现时要一字不差）

插在 `instructionBlock` **之前**（先交代这一次是哪个任务，再说这张卡要干什么），两个块都可缺席：

```
The person running this pipeline gave these values once, for every step. They already fill
the deliverable directories below; quote them as written when a document has to name them:
<run_values>
任务编号: T202608242753
</run_values>

One instruction was given for this whole run. It names the task every step is about; it does
not replace your own instruction:
<pipeline_instruction>
完成 T202608242753 任务，从需求到交付
</pipeline_instruction>
```

- 值一个都没有 → `<run_values>` 不出现（没有值的流水线只有第二块）。
- 运行指令为空 → `<pipeline_instruction>` 不出现。
- 两句里的用户文本都过 `escapeText`。
- **卡片那句原样保留在自己的 `<run_instruction>` 块里，一个字不改**——这是需求第 1 条。
- 顺序固定：行数据 → **run_values** → **pipeline_instruction** → 这一步的指令 → 上游笔记 → 预算 → 文档 → 目录 → 尾句。

**为什么新块不叫 `<run_instruction>`。** 那个名字已被卡片指令占着。两块同名，模型分不清哪句属于这一步、哪句属于整次运行——而这正是要让模型分清的事。第二块的句式也写明了"不替换你自己的指令"。

## 六、不做

| 不做 | 为什么 |
|---|---|
| 运行指令覆盖卡片指令 | 卡片做的是"什么活"，每张卡不同；运行说的是"这一次做哪个"。覆盖等于让任务分析去干详细设计的活 |
| 运行时可"这次不带这句卡片指令" | 上一版我提过这个按钮，方向错了：运行时的口子一开，配置页就不再是唯一事实来源 |
| 顺手改掉卡片里重复的号 | 卡片可能还服务着别的流水线。只提示，删不删由人去配置页决定 |
| 每条流水线一个常驻「背景说明」 | "这一次做哪个"每次变，常驻字段是错的粒度 |
| 每步各自一个运行指令 | 那就回到用户抱怨的状态了 |
| 自动把上一步产出摘要成运行指令 | handoff 已经负责这件事，两套上下文会互相矛盾 |
| 静默记住指令 | 预填只出现在**同一条流水线的下一次运行**，标着「沿用上次运行的指令」；任务号会变，静默记住是把上上个任务写进新任务 |

---

## 七、名字（已定：都不动）

弹框里叫「运行指令」之后，**配置页那一行也叫「运行指令」**，指的是卡片上、长期有效的那句（事实 5）。同一个词两个作用域。

**决定（已有明确答复）：配置页那行不改，保持「运行指令」。** 我原本建议把它改成「这一步的指令」，用一次文案改动让三个词各一个意思；这一轮不做。

既然不改名，区分就全靠界面上的话，两条必须在：

1. 弹框注脚写作用域：「三步都会收到 · 只对这一次运行有效」。
2. 预览里把卡片那句标成「这一步的指令」，而不是再叫一次「运行指令」——同屏出现两次同名，用户没法判断哪句是卡片的。

---

## 八、验收

1. **卡片指令不被改写**：某个步骤的 `<run_instruction>` 内容与今天逐字节相同（快照比对）。
2. 没有值的流水线 + 不填运行指令 → 提示词与今天**逐字节相同**。
3. 有值的流水线 + 不填运行指令 → 提示词只多 `<run_values>`，没有 `<pipeline_instruction>`。
4. 填了运行指令 → 这一次运行的**每一步**都有 `<pipeline_instruction>`，位置在 `<run_instruction>` 之前。
5. 运行指令里写 `{任务编号}` → 替换成本次的值；写不存在的名字 → 原样保留。
6. 没有 `{token}` 的流水线，运行前也弹框；填了按第 4 条进提示词。
7. 上次有指令、这次单步重跑：记录里能看出沿用了哪一句。
8. 运行记录刷新后仍能读到这次的值和运行指令。
9. 指令含 `</pipeline_instruction>` 字面量 → 提示词不被截断。
10. 超过 2000 字 → 不开始运行，并说明原因与上限。

### 落地时定下来的三件事

1. **字段不叫 `instruction`。** `WorkbenchPipelineRun.instruction` 早被"评审意见"占用（`refine` 那次运行用），`WorkbenchRunRequest.instruction` 是卡片自己那句。所以线上的新字段叫 `directive`，界面上仍叫「运行指令」，提示词块叫 `<pipeline_instruction>`。
2. **「重新生成」这一轮不经过这个框。** 它的框问的是「改哪里」，任务本来没变，所以它既不填也不发 `directive`，refine 的提示词一个字没动。第四节里"每次都问"指的是整条运行、从第 K 步起跑、单步重跑这三条路。
3. **卡片指令只读不写。** 预览里的「这一步的指令」就是这次运行真要发出去的那句：步骤写了 `steps[].instruction` 用它，没写就用**卡片自己存的那句**（runner 的取法：请求里没有 `instruction` 时退回 `selection.instruction`）。2.9.26 修的就是这一条 —— 早先只读步骤，步骤没写时预览写「（这一步没有指令）」，实际却把卡片那句送进去了。弹框没有任何写回卡片的路径。

## 十、留给下一轮

1. 老卡片迁移提示要不要也给一个"跳到配置页那个步骤"的入口。这一轮只有提示文字——因为跳过去改的仍是卡片，不该在运行弹框里做。
2. （已定，记录在此）配置页那行不改名，见第七节。
3. 「重新生成」要不要也带这句（它现在不填也不发）。真要带的话，得在它那个"改哪里"的框里再加一个字段——那是另一个决定，这一轮没做。
