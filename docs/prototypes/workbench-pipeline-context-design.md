# 串行流水线的上下文传递：一条会话跑完整条链

> **状态：设计，未实现。** 编排层还不存在——`pipeline` 在 `dsh-workbench/src` 与 `tests` 的 127 个文件里出现 **0 次**。本文只回答一件事：流水线里第 N 步怎么拿到第 N−1 步的上下文。
>
> 界面按现有两栏原型（`docs/prototypes/workbench-pipeline-2col.html`）的交互，**本文不重新设计交互**。

**三条边界写在前头，后面的每个决定都是它们推出来的：**

1. **编排层要从零写。** 这不是"给现有运行加个参数"，是新增一层。本文只定这一层里**上下文怎么流**，不是它的全部。
2. **每一步仍然是一次 run。** 现有的启动、`{html}` 捕获、记录、活动流、重新生成全部复用，语义一行不改。
3. **界面只加两处展示**：配置页多一行「输入」，活动页那条预置的「上一节点输出（只读）」变成真话。其余不动。

## 一、范围

| | 内容 |
|---|---|
| 管 | 上下文的来源、载体、边界：第 N 步看得到什么，看不到什么 |
| 不管 | 画布怎么画、tab 怎么排、编排状态存在哪（见第十二节） |
| 不管 | 多上游、分支、并行——都是串行单链的后续问题 |

## 三、现有交互（基线，本文不改）

| 区域 | 职责 | 本文是否动 |
|---|---|---|
| 画布 | 步骤竖排、状态、运行号、连接线、底部「添加步骤」 | 不动 |
| 运行条 | 分段进度 + 「运行 / 停止 / 运行记录」 | 不动 |
| 检查器 · 活动 | 这一步做过什么（工具调用、读写、思考） | 只把预置的「上一节点输出（只读）」做成真话 |
| 检查器 · 配置 | 六行：技能 / 模型 / 权限模式 / 工作目录 / 运行指令 / 失败处理 | **多一行「输入」** |
| 检查器 · 结果 | 这次交出的文件清单 + 模板预览 / 源码 | 不动 |
| 阅读器 | 唯一读产物的地方，`live` 与 `snapshot` 两种模式 | 不动 |
| 运行记录 | 每条 run 一行 → 逐次详情 | 不动（仍然每一步一条） |
| 审核弹窗 | 提要求重新生成 | 不动 |

这些界面全都是"**一次 run**"的界面。编排层不做改它们这件事，做的是把 N 次 run 串起来——串起来之后它们各自照常工作。

## 四、决定：一条会话 + 落盘交接

### 4.1 主路径

```
step1   agents.create({ sessionId: S })      ← 今天的代码
        └─ finished（record 记 sessionId: S）
step2   attachRunSession(S)                  ← 今天的 refine 分支已经在做的事
        └─ finished（record 记 sessionId: S，与 step1 同一个）
step3   attachRunSession(S)
```

第 2 步的提示词和今天**一字不差**，仍然是 `renderWorkbenchSkillPrompt`——它前面已经有第 1 步的完整对话，不需要在 prompt 里塞任何东西。

这是"改动小"的关键所在：**上下文不需要被编码，它已经在会话里了。**

### 4.2 三条路的对照

| 维度 | 纯会话串联 | 纯交接单驱动 | 本文：会话串联 + 落盘兜底 |
|---|---|---|---|
| 上下文质量 | 最好（原始对话，无摘要损耗） | 取决于上游肯不肯认真写 | 主路径同左 |
| token 曲线 | O(N²)，第 5 步要重读前 4 步全部 | O(N)，线性可控 | O(N²) 但可用交接单裁剪 |
| 重跑语义 | 差（同会话追加，下游看得到两版产物） | 干净（新会话） | 主路径干净，重跑走隔离 |
| 可回看 | 差（会话是共享的，切不出"这一步的输入"） | 好 | 好（兜底那份就是输入） |
| 改动量 | 最小 | 中 | 小 |

**纯交接单为什么不够：** 交接单是有损的，而 `renderWorkbenchRefinePrompt` 的注释已经把这个道理写清楚了——"摘要是有损的第二真相"。让每一步都靠摘要接力，等于让第 5 步隔着四层转述工作。

**纯会话为什么不够：** 见 §4.3 和 §9.2。

### 4.3 那为什么还要落盘

三个理由，都不是"保险起见"：

1. **压缩。** 长会话一定会被 compaction 压缩。压完之后，第 1 步那句"决定用 scoping v2，不用旧方案"就变成了一句摘要，且你不知道它压掉了什么。交接单至少是你定格式、定长度、看得见的那一份。
2. **单跑与重跑必须开新会话**——否则重跑第 2 步就是在同一条对话里追加，第 3 步看到两份第 2 步的产物，分不清哪份是现在的。开新会话就没有会话历史，只有交接单。
3. **可回看。** 运行记录要能回答"这次结果基于哪份输入"，共享会话切不出来。

## 五、会话与记录的生命周期

### 5.1 一条会话，N 条记录

- 会话属于**一次流水线运行**（`pipelineRunId`），不属于某一步。
- 每一步仍然落一条 `WorkbenchResultRecord`，`sessionId` 相同。
- 记录之间的关系靠 `stepIndex` 与 `upstreamRunId` 表达。

### 5.2 时序（有一个硬要求）

```
编排器                      runner                      会话 S
  start(step0)  ──────────►  create ──────────────────► S = 新会话
                            settle(step0)
  ◄──────────── onSettled ──┤
  start(step1)  ──────────►  attach(S) ───────────────► S（复用）
```

**硬要求：上一步的 run 必须已经结算，才能发下一步。**

不是风格问题——`sessionBusy()` 会直接 reject `run-in-progress`。编排器因此必须由 `onSettled` 驱动，不能用 `await` 连着发。在测试里这一条要单独写一个用例，否则线上表现是"第 2 步随机不启动"。

### 5.3 归档语义变了（最容易漏）

今天：run 结算 → `archiveCardSession()` → 会话从侧边栏消失。
流水线里：第 1 步结算就归档，第 2 步要 `unarchiveSession` 再 `resume`——**能跑通，但侧边栏会闪，而且每一步都付一次归档/恢复的代价。**

规则改成：**会话被流水线持有时不归档，整条流水线结算（成功 / 失败 / 停止）后归档一次。**

这是本次改动里最容易出事的地方：判据不是"这次 run 结束了"，是"这条流水线用完了"。

### 5.4 失败、停止、取消

| 事件 | 编排器 |
|---|---|
| 某步 settle 为失败 | 后续步骤不启动，整条标 `failed`，归档会话，画布停在失败那一步 |
| 用户点停止 | 结束当前 run，后续不启动，标 `stopped` |
| 页面关闭 / 插件重载 | 见 §12 未决 3：内存里的编排器没了，会话留在磁盘 |

### 5.5 模型与权限：会话级，必须统一

会话创建时模型与 cwd 就定了，后续步骤 attach 上去改不了。所以：

- **一条流水线的模型 = 第 1 步卡片的模型**，后续步骤的卡片模型被忽略（界面要标出来，不能假装它生效）。
- **权限模式同理**，取第 1 步的。
- **工作目录必须一致。** 沙箱根取自父会话头（事实 9），目录不同的卡片串进来会**静默写到第 1 步的目录里**——这是所有边界情况里最危险的一条，必须在校验阶段拒绝：目录不一致的卡片不能进同一条流水线。

## 六、交接单

### 6.1 放哪：结构化输出的第二个可选字段

`WORKBENCH_OUTPUT_SCHEMA` 已经是 `additionalProperties: true`，所以加一个可选字段**不破坏现有契约**：

```js
{ html: "...", handoff: "上游需要知道的三五条" }   // handoff 可选
```

- 有 `handoff` → 存进记录的 `handoff?: string`，供单跑 / 重跑 / 回看使用；
- 没有 → 主路径照跑（会话里有全部上下文），只是单跑这条退路没了。
- **不阻塞主路径**，这是选它而不是"必填字段"的理由：让一个纯展示卡片（只画一张图）也去写交接单是错的。

### 6.2 形状与上限

四段，纯文本，`≤ 4KB`（约 1.5k token）：

```
产出：docs/详细设计/ 下 3 份（详细设计.md / 接口清单.md / 变更点.md）
决定：状态机用 guard 表驱动，不引入 xstate
约束：下发接口不能改签名，只在尾部加可选字段
未决：超时重试次数未定，下游别依赖
```

上限是硬的：超了由 runner 截断并在记录里标记 `handoffTruncated: true`，不在 prompt 里假装完整。

### 6.3 谁读它

只有两个读者：**单跑 / 重跑时拼 prompt 的 runner**，和**看运行记录的人**。主路径的模型不读——它读会话。

## 七、三条路径的输入来源

| 路径 | 会话 | 上下文来源 | 提示词 |
|---|---|---|---|
| 整条流水线运行 | 一条，串到底 | 会话本身 | `renderWorkbenchSkillPrompt`（不变） |
| 单独运行某一步 | 新建 | 上游**上一次成功**那一步的 `handoff` + 产物路径 | 新增 `renderWorkbenchStepPrompt`，多一个 `<upstream>` 块 |
| 审核重生成 | 沿用该次 run 的会话 | 会话（现状） | `renderWorkbenchRefinePrompt`（不变） |

单跑的 `<upstream>` 块长这样：

```
<upstream step="01 需求拆解" run="4" dir="docs/需求拆解">
  <handoff>…4KB 原文…</handoff>
  <files>需求拆解.md · 验收清单.md</files>
</upstream>
```

要细节让模型自己 `read`——`dsh.files.read` 本来就是工作区受限只读的，这条通路现成。

**注意这里喂的是"上一次成功那一次的 handoff 快照"，不是磁盘现在的文件。** 否则单跑第 3 步可能在用一份没人记得何时产生的输入。

## 九、边界情况

### 9.1 上游没跑成功

失败即停（现状）。下游**不能**拿"上一次成功"的 handoff 偷偷启动——那会让"失败即停"变成"失败后跳过"。整条标失败。

### 9.2 上游重跑了

第 2 步跑到第 5 次，第 3 步的结果还是基于第 4 次做的。**画布上标「上游已变」，不自动重跑**——自动重跑会让一条链在用户不知情时全部重来。

判据：`step[i].upstreamRunId !== step[i-1].runId`。

### 9.3 删步骤 / 移动步骤

依赖**按位置**（第 N 步的上游 = 第 N−1 步），不按技能。这不是随手选的：`zoomStepIndex` 曾经因为按技能反查而在同名技能上错位。删掉中间一步时，界面要明说"下游的输入会改指向"。

### 9.4 上下文超限

五步以上要实测。压缩发生时交接单是兜底；超过某一步数（待测，暂定 8）时在运行条上提示"这条链已经很长，考虑拆成两条"。

### 9.5 单跑时上游快照

见 §7 末。找不到"上一次成功"的记录时，单跑退化为**无输入**并在配置页明说"这一步没有上游输入"，不能静默空跑。

### 9.6 老数据

没有 `sessionId` 的老记录：重生成仍按现状新建会话（事实 2 的注释已经这么处理了）。没有 `handoff` 的老记录：单跑无输入。

## 十、验收

### 10.1 单测

1. 三步串行：三个 run 记录的 `sessionId` **相同**；
2. 上一步没结算就发下一步 → 必须 reject，且编排器不崩；
3. 流水线中途停止 → 会话不归档；跑完 → 只归档一次；
4. `handoff` 超 4KB → 截断 + 标记；
5. 卡片目录不一致 → 拒绝入列；
6. 单跑带 `upstream` → prompt 里有 `<upstream>` 块，且喂的是**快照**不是当前文件。

### 10.2 真机（这一条不能省）

单测全绿也只证明"机制被测量过"，不证明产品里跑通。至少要看见一次：

选两张卡 → 串成两步 → 点运行 → 第 2 步的活动里读到第 1 步写的文件 → 停止 → 单跑第 2 步 → 它用上了第 1 步的交接单 → 侧边栏始终没有多出一条会话。

## 十一、不做

- **不做"一条会话跑到黑还顺便把重跑也塞进去"**——重跑必须隔离，理由见 §4.3。
- **不做自动级联重跑**——用户没同意的事不做。
- **不把交接单做成必填**——那会让纯展示卡片没法跑。
- **不在这一步做多上游 / 并行**——串行单链都还没落地。

## 十二、要你拍板的四件

1. **步骤 = 卡片？** 建议是。卡片已经是"技能 + 模板 + 目录 + 权限 + 模型"，正好是一步所需的全部，不用再发明一套步骤配置。代价：同一个技能跑两次要两张卡。
2. **交接单由模型写，还是 runner 从产物里提取？** 建议模型写（可选字段）。runner 提取不了语义，只能提取文件清单，那正好是 `<files>` 已经有的东西。
3. **编排状态存哪？** 内存 + 卡片存储各存一份，还是只存磁盘？这决定"页面关了流水线还跑不跑"。**这是本文唯一一个会影响用户体验的整体决定，也是我唯一没法替你拍的。**
4. **一句话不对齐：** 你说"现有交互"是指 `workbench-pipeline-2col.html`（配置页六行平铺、模板在结果页），还是指我改出来的 `workbench-pipeline-v2.html`（配置分三层、模板挪到配置）？本文按 **2col** 写；如果你要的是 v2，第三、八、九节都要跟着改，请先说一句。
