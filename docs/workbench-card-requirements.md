# 工作台卡片需求方案

[工作台概要设计](workbench-design.md)确定了卡片式工作台的位置、展示与存储归属，[工作台详细设计](workbench-detailed-design.md)把它落到了模块级并完成了 P1–P4。本文处理下一层诉求：**让卡片可配置、可执行、外观由用户自己写**。

本文是需求方案，不是实现设计。它只回答"要什么、为什么、什么算做完了"，实现级拆分留给后续的详细设计续篇。

> **修订说明。** 本文第五版。
>
> - **第二版**把外观控制权整体交给用户：**用户写 HTML 模板，skill 只负责把数据填进去**。同版内又把模板从「可选、缺省时自动推导」改为「**使用卡片的前置条件**」，当时的理由是"契约由模板反推，无模板时既不存在契约，也没有可供自动推导的结构化结果"。**这条理由在第三版已失效，但"模板是前置条件"的结论保留**（新理由见 §7）。
> - **第三版**删除了占位符与循环语法，也删除了"从模板反推契约"。模板不再声明字段：**整份文档就是规格**，宿主把它原样发给子代理，子代理只回填 `<!-- template-begin -->` 与 `<!-- template-end -->` 之间的一对区间，代码再把回填结果拼回骨架。**没有兼容模式**——仍写 `{{字段}}` 的模板会被明确拒绝（`placeholder-syntax`），而不是把花括号当字面量渲染出来。§3 中标注「改(本次)」的条目是本次变更；文中保留的旧表述都已就地标为**已废弃**。
> - **第四版**做两件事。其一，**隐藏能力从源码整体移除**：卡片外壳只在提供 `onRemove` 时画出 X，X 永远表示删除；布局记录只剩排序一维，宿主也不再解析 `hidden`，旧记录里写着 `hidden: true` 的卡片按可见读回而不做迁移（§13、验收标准 16）。其二，**§14 增加第 16 条验收标准**，把卡片模型（创建、正面、结果页、配置页、X 的删除语义、不提供隐藏）写成可验收的一条，并新增[附录 A](#附录-a验收标准映射)记录逐条映射；条数从那时起是 16，详细设计的 M13 / M14 / 附录 B 同步。
> - **第五版（当前）新增一节「技能卡按钮触发执行」，而它 ⏳ 尚未实现。** §12 与 FR-14～FR-23、验收标准 17～34 都是**待实现的需求规格**，不是对现有能力的描述，也**不是**验收证据。本轮**没有改动任何源码**：这一节写下的每一条都还没有对应的实现与测试。请把它读成"要做什么"，不要读成"已经能做什么"——把未实现的东西写成现状，正是本文第四版花大力气清理掉的那类缺陷。
>
> **一句话区分：** §1–§11 与 §13–§16 描述**已实现并被验收**的行为（验收标准 1–16，见[附录 A](#附录-a验收标准映射)）；§12 与验收标准 17–34 描述**尚未实现**的行为。附录 A 用分组把两者分开。

## 1. 需求陈述

一句话：

> 工作台上有一张**技能卡**。用户在它的配置里选一个 skill，**用 HTML 写整份文档**（表格、列表、任意排版）——用 `<!-- template-begin -->` / `<!-- template-end -->` 标出子代理要填的那一段，并在那一段的注释里写明填什么。点「运行」，宿主把这份文档**原样**交给一个**独立子代理**，让它按这个 skill 的指令执行、只回填那段区间并以 HTML 交回；代码把回填结果拼回骨架、清洗后渲染出来。结果落盘并带时间戳，只有用户主动点「运行」才会产生模型调用。

**模板是使用这张卡的前置条件**：没有模板就没有可交给子代理的规格，也没有可供拼回的骨架。卡片在无模板时给出明确引导，而不是替用户猜一个呈现方式。

它要解决的原问题是"卡片太死"：现有卡片由插件包在编译期注册，展示什么、怎么展示都写死在插件里。而用户想要的是**加一张卡就能看到一类新信息，并且外观自己说了算**——不需要为每个信息源写一个插件包，也不需要迁就系统的固定排版。

## 4. 使用流程

**配置。** 用户在工作台看到技能卡的空态，点齿轮，从 skill 列表里选一个 skill。

**写模板。** 用户写这张卡的**整份 HTML 文档**：骨架（标题、样式、排版）自己定，用 `<!-- template-begin -->` / `<!-- template-end -->` 标出子代理要填的那一段，并在那一段里用注释写明它要产出什么。编辑器**实时预览**正在编辑的这份文档，就地列出违例（标记缺失/未闭合/重复、仍写占位符语法、禁止构造、超体积）。**没有模板，卡片就不提供「运行」。**

**运行。** 用户点「运行」，宿主把整份文档（注释在内，逐字不改）连同 skill 正文交给一个独立子代理，要求它只回填区间，并只回报那一段 HTML。

**看结果。** 执行完成后，代码把回填的区间拼回骨架、清洗后渲染出来，并显示执行时间。骨架是用户写的那一份，逐字节不变。

**修订模板。** 用户点齿轮重新打开编辑器。结果不对时改两处之一：**区间里的注释**（说明写得不清楚，模型就会填错）或**骨架的排版**。这是修正结果的唯一手段——契约只有一个 `html` 字段，它不会替你发现内容填错了。

**日常使用。** 打开工作台直接看到上次结果，不触发任何模型调用。点「运行」或「重跑」才刷新。

**结果不能用。** 模型没有按契约返回（结果里没有 `html`）时，宿主自动重试一次；仍失败则卡片显示错误态，并提供「查看原始输出」。如果失败来自子代理自身，卡片还能带上从宿主事件总线捕获到的失败原因。

**换了 skill。** 模板按 skill 分别保存；切回原来的 skill，原来的模板还在。新 skill 在没有模板之前不能运行。

**旧模板。** 第二版写的模板（含 `{{字段}}`、`data-dsh-each`，或压根没有区间标记）**不能运行**：保存会被拒并给出可操作提示，用户必须改写成区间标记的写法。旧版本存下的结果（结构化值里没有 `html`）按**尚未运行**显示，而不是渲染一个空框。

## 5. 功能需求

### FR-1 技能卡注册

技能卡作为 `dsh-workbench` 的一张卡注册，遵循既有卡片契约（`workbench.card` 工厂 + `workbench.cards` 列表槽）。它与其它卡片一样参与排序，但**不参与隐藏**：外壳只在卡片提供 `onRemove` 时画出那个 X，而 X 永远表示删除。**隐藏不是本产品的能力**，布局记录里也没有这一维（详见 §12 与验收标准 16）。

### FR-2 配置：选择 skill

- 卡片提供齿轮入口，打开该卡自己声明的配置表单。
- 技能卡的配置分为两部分：**选择 skill** 与 **编写模板**（FR-3）。
- 配置提交后由宿主校验并持久化（见 FR-13），失败时不静默丢弃。

### FR-3 模板编写与存储

- 模板以**当前选中的 skill 为键**分别保存（决策 15）。
- 模板内容持久化，与卡片配置同一存储归属。
- 模板有体积上限，超限时拒绝保存并说明。

### FR-4 模板分析与区间标记

- **客户端**用 `analyzeTemplate(html)` 分析模板，得到 `{ region, violations }`（决策 8、16）。它只回答两个问题：
  1. **有没有恰好一对可用的区间？** 缺失、未闭合、重复、闭合标记出现在开启标记之前，都拒绝（`region-missing`、`region-unclosed`、`region-repeated`）。
  2. **文档有没有夹带它不该有的东西？** 见 6.4 的禁止清单（`script`、`event-attribute`、`unsafe-url`、`external-element`、`external-css`）。
- 模板里仍写着 `{{...}}` 时，分析器报 `placeholder-syntax`：**明确失败，而不是把花括号当字面量渲染出来**。没有兼容模式。
- **不再推导任何东西。** 第二版的"占位符 + 循环标记 → 输出契约（字段名与结构）"已整体删除，随之删除的还有占位符文法、循环文法与它们的违规码。契约是固定的一份，见 FR-6。
- 分析必须走**真正的 HTML 解析器**：内容策略要遍历元素与属性，而 HTML 允许省略结束标签，字符串扫描会误判嵌套。解析用惰性的 `template` 元素，注释会原样保留——注释正是要读的说明。
- 分析在**保存前与点「运行」前**都在客户端跑，违例就地展示、不提交。宿主半跑在 Node 里没有 DOM，不承担模板分析。
- 违例通过**封闭码集合**表达，编辑器为每个码给一条本地化文案与一个位置。

### FR-5 执行

- 用户在卡片上点「运行」触发执行。
- 执行在**独立子代理**中进行（决策 9），携带该 skill 的指令正文。
- 子代理的模型跟随当前活跃会话的默认模型（决策 12）。
- 一次执行只对应一次子代理运行；同一张卡不并发执行。
- 执行中提供**取消**。

### FR-6 结果校验

- 输出契约是**固定的一份**：`WORKBENCH_OUTPUT_SCHEMA = { type: 'object', properties: { html: { type: 'string' } }, required: ['html'], additionalProperties: true }`。每次运行都相同，没有按模板生成的契约，也没有字段清单。
- `html` 是唯一必需项，因此**结果里没有 `html` 就是不可用**：上游不会提交这样的捕获，宿主自动重试一次；仍失败 → 错误态 + 保留原始输出（决策 11）。
- 除"有没有 `html`"之外，结果**没有任何形状可以校验失败**。内容对不对不由契约负责（见 §9.4）。
- **"拿不到合规结果"是预期结果而非异常**：上游明确说明请求结构化输出不保证一定得到合规值，因此这条路径必须有产品表现。
- 子代理**自身报错**时，它的失败文本会被单独捕获并写进结果的诊断字段，供「查看原始输出」展示（见 FR-9 与 §8），不再是一次黑箱失败。
- 旧版本存下的结果（结构化值里没有 `html`）按**尚未运行**呈现，而不是渲染一个空框。

### FR-7 渲染与隔离

- 渲染分两步：**拼接**——`filledTemplate(template, html)` 把结果里的 `html` 放回模板的区间（纯字符串操作）；**清洗并挂载**——`renderTemplate(root, html)` 解析拼好的整份文档，移除禁止构造，再放进影子根。
- **骨架按构造逐字节不变**：子代理从不书写样式、标题与外壳，它们只存在于用户写的那份文档里，代码只替换区间那一段。因此两次运行之间骨架不可能漂移，**不需要漂移检查**。
- 清洗是**承重环节而非兜底**：片段来自一个读过模板、skill 以及 skill 工具输出的模型（决策 19）。
- **没有模板时不执行、不渲染结果**，卡片显示引导去配置模板的空态（决策 20）。
- 渲染发生在 **Shadow DOM** 中（决策 17），用户样式不外泄，也不受外部样式干扰。
- 应用主题 token 通过 CSS 自定义属性的继承穿过影子边界，无需手动桥接。

### FR-8 模板编辑器与实时预览

- 齿轮里提供一个 HTML 编辑器（决策 21）。
- **就地校验**：随输入跑 `analyzeTemplate`，把每一条违例连同位置列在编辑器里；有违例时保存按钮不可用。
- **实时预览**：渲染**正在编辑的这份文档本身**，与正式渲染走**完全相同**的隔离与清洗路径。没有"占位样值"，也没有字段清单——没有运行就没有可填的区间，预览展示的是骨架。这样可以避免"预览好看、真跑起来不一样"。
- 保存后回到卡片，有模板才提供「运行」。

### FR-9 动作集

卡片提供：**运行 / 取消 / 重跑 / 查看原始输出**。

- 「查看原始输出」是"诚实报错"的必要配套，不可省略。子代理**自身报错**时，宿主从事件总线捕获到的失败原因也会写进结果的诊断字段，由这个面板一并展示——没有它，每一次失败都只是一个 `stopReason: 'error'`。
- 「重跑」让用户无需改配置即可重新执行。
- **「运行」是会改状态的操作**（决策 13）：子代理持有完整工具权限，重跑不是幂等的。这一点必须在交互上可感知。

### FR-10 持久化与新鲜度

- 结构化结果、执行时间、所用 skill 一并落盘。
- 打开工作台**只读缓存，绝不触发模型调用**（决策 10）。
- 卡片显示上次执行时间；超过阈值时给出"已过期"提示，但不自动重跑。

### FR-11 降级态

各类降级各自独立、各自可操作（决策 `degraded_states`），详见 §8。

### FR-12 权限与审批

- 子代理继承当前活跃会话的**完整工具权限**（决策 13）。
- 同时**继承会话的审批流**：危险操作仍会停下询问。
- 卡片上**标注权限等级**，让用户知道自己按下去的是什么。

### FR-13 通用配置机制

技能卡不应该是特例。宿主提供通用机制（决策 5）：

- 卡片**声明**自己的配置字段；
- 宿主负责**校验 + 存储 + 下发**；
- 技能卡作为第一个使用者落地。

第一版字段类型可以收窄到"枚举选择 + 长文本"，但机制本身是真的。

## 6. HTML 模板规范

### 6.1 位置与归属

模板存在卡片配置里，**按 skill 分别保存**（决策 15）。skill 本身不携带模板，也不声明任何字段信息。模板是**一整份文档**，不是片段或片段集合——只有标明的那一段区间会随运行被替换。

### 6.2 区间标记

模板里用一对注释标出子代理要填的那一段：

```html
<!-- template-begin -->
<!-- template-end -->
```

- 标记内部的空白可有可无：`<!--template-begin-->` 与 `<!-- template-begin -->` 等价。
- **v1 只支持一对。** 缺失（`region-missing`）、未闭合（`region-unclosed`）、重复（`region-repeated`）、闭合标记出现在开启标记之前，全部拒绝。两个标记之间的那一段就是**区间**，是整份文档里唯一会被替换的部分。
- 模板里已经存在的那一对标记原样保留在拼好的文档里，注释不被删除。
- 仍写 `{{字段}}` 的模板报 `placeholder-syntax`：**明确失败，绝不把花括号当字面量渲染**。

### 6.3 注释即需求

**文档整体是规格，区间里的注释是说明。** 整份模板逐字发给子代理（从不重新序列化——那样会把注释删掉，而注释正是要读的东西），提示词要求它读区间里的注释、按注释填写、只回报那一段 HTML。

因此"要填什么"写在注释里，例如：

```html
<section>
  <h2>本次提交</h2>
  <!-- template-begin -->
  <!-- 每个提交一行：一列短 hash，一列提交说明。 -->
  <!-- template-end -->
</section>
```

几条纪律：

- 注释要说清**产出的形态**（每个条目一行、哪些内容、什么顺序），因为没有任何字段名或类型可以替代它。
- 骨架（样式、标题、外壳）不进区间：它由用户持有、逐字节不变，子代理改不到。
- 区间位置由标记界定，不靠 HTML 结构自定界，也不需要成对的元素闭合。

### 6.4 允许与禁止

| 项 | 允许 | 说明 |
| --- | --- | --- |
| HTML 标签 | **全部** | 决定"外观完全自由" |
| CSS | **全部**，含 `<style>` 块 | 作用域由 Shadow DOM 兜住，不会外泄 |
| `<script>` | **禁止** | 对"配置显示样式"毫无必要 |
| 事件属性 `on*` | **禁止** | 同上，且是代码执行入口 |
| `javascript:` 等危险 URL | **禁止** | 同上 |
| 外部图片 / 字体 / 外部 CSS | **禁止**（决策 18） | 卡片离线可用；不会变成追踪像素 |
| 子代理回填的片段 | **渲染前清洗** | 片段来自模型，是比模板更不可信的一侧（决策 19） |

被禁止的内容在保存模板时即被拒绝并指出位置，不做静默剥离——静默剥离会让用户以为样式生效了，但实际没有。**子代理回填的片段是另一回事**：它没有"保存"这一步，所以在渲染前统一清洗（见 FR-7 与[详细设计 · M3 隔离渲染](workbench-skill-card-detailed-design.md)）。其中 `<style>` 里出现 `@import` 或非片段 `url(...)` 时**整块移除**：只删掉那一条引用会留下一份只生效一半的样式表。

### 6.5 输出契约

契约只有一份，与模板无关：

```ts
export const WORKBENCH_OUTPUT_SCHEMA = {
  type: 'object',
  properties: { html: { type: 'string' } },
  required: ['html'],
  additionalProperties: true,
}
```

- **没有从模板推导出来的契约，也没有字段清单。** 第二版的"从模板反推契约"（`deriveTemplate` → `{ fields, schema, violations }`）已删除。
- 子代理唯一要交回的是 `html`：**它填好的那一段区间**，不是一组命名值，也不是描述。
- `required: ['html']` 意味着**没有 `html` 的结果不可用**：上游不会提交它，宿主据此重试一次（FR-6）。
- 整份文档随提示词放在 `<output_document>…</output_document>` 里发给子代理，并告知它：只填区间、只回报那一段、区间之外的内容不要复述或改动。
- 模板体积上限 `WORKBENCH_TEMPLATE_MAX_BYTES = 32 * 1024` 在**存储时**强制，所以提示词的最坏情况是有界的。

### 6.6 模板问题时的行为

| 情况 | 行为 |
| --- | --- |
| 用了被禁止的标签/属性/外链 | 保存前拒绝并指出位置 |
| 缺少区间标记 / 标记未闭合 / 标记重复 | 保存前拒绝并指出原因 |
| 仍写 `{{...}}` 占位符语法（旧模板） | 保存前拒绝，提示改用区间标记并在注释里写明要求 |
| 模板超体积上限（32 KiB） | 保存时拒绝 |
| 子代理回填里夹带禁止构造 | 渲染前清洗移除，不报错（模板本身没有被违反） |
| 结果里没有 `html` | 重试一次；仍失败 → 错误态 + 原始输出 |
| 旧结果（结构化值里没有 `html`） | 按"尚未运行"呈现，不渲染空框 |

## 7. 模板是前置条件（本节原为"无模板兜底推导"）

**本节在第二版修订中被整体替换过一次，第三版又把理由换掉了。** 原方案是"用户尚未写模板时，卡片按结果结构自动推导呈现"；第二版改成"没有模板就没有契约"，因为契约当时由模板反推。

第三版里**理由变了，结论没变**：契约不再由模板反推（它是固定的一份，见 6.5），但模板仍然是运行的前置条件——**没有模板就没有可交给子代理的规格，也没有可供拼回结果的骨架**。没有这两样，一次运行产出什么都不可能显示成用户要的样子。

因此：**没有模板就不能运行**（决策 20）。卡片此时显示引导用户去配置模板的空态，不猜测呈现方式，也不发起任何模型调用。

这带来一个明确的代价，必须承认：**用户必须自己写出这份文档，并在区间注释里说清"要填什么"。** 系统无法在首次运行前告诉他该产出什么形态——这不是可以靠"列出字段"缓解的问题，因为已经不存在字段这一层（决策 22）。缓解手段是把注释当成可核对的说明来写，并在结果不对时先回来改注释。

约束与边界（仍然适用）：

- 结构化结果的体积要有上限，建议与既有工作台布局契约保持同一量级（64 KiB）。
- 表格列数过多时横向滚动，不压缩到不可读。

## 8. 失败与降级矩阵

| 情况 | 卡片表现 | 用户可做的动作 |
| --- | --- | --- |
| 未配置 skill | 空态：提示去配置 | 打开齿轮选择 skill |
| 已配置 skill、未写模板 | 空态：提示先写模板才能运行；「运行」不可用 | 去写模板 |
| 已配置且已写模板、未运行 | 提示"尚未运行" | 运行 |
| 无活跃会话 | 空态：说明需要先有会话 | 跳去开会话 |
| skill 被删除或改名 | 标记失效，保留原选择供识别 | 重新选择 skill |
| 模板保存被拒（标记缺失/未闭合/重复、占位符语法、禁止构造、超体积） | 编辑器内就地报错并指出位置或原因 | 修正模板 |
| 执行失败（子代理报错） | 错误态 + 原因（诊断来自宿主事件总线，可在原始输出面板查看） | 重跑 / 查看原始输出 |
| 结果里没有 `html`（重试后仍失败） | 错误态 | 查看原始输出 / 重跑 |
| 结果是旧格式（结构化值里没有 `html`） | 按"尚未运行"呈现，不显示空框 | 重新运行 |
| 结果过期 | 显示"已过期"与上次执行时间 | 重跑 |
| 执行中被取消 | 回到上一次结果或空态，并说明已取消 | 重新运行 |

设计原则：**每一种失败都要让用户能自己修好**，不允许出现"出错了但你不知道该干什么"或"卡片悄悄消失了"。

## 9. 风险与限制

### 9.1 权限是最高风险项（决策 13）

用户选择了继承完整工具权限。这条选择的能力收益明确（卡片能真正查仓库、跑测试），但它与"结果只读缓存"的印象存在张力，必须显式承认：

- skill 是**磁盘上的自然语言**，第三方 skill 根目录里已有现成内容；
- 完整权限意味着子代理能**写仓库、执行命令、发网络请求**；
- 真正的注入面是：skill 正文 + skill 在执行中读到的任何文件内容，都是不可信输入，而执行者持有写权限。

因此 FR-12 的三项配套（继承审批流、标注权限等级、运行是可改状态的操作）**不是可选项**，是这条决策的组成部分。

### 9.2 HTML 面已被四项约束封住

用户写的 HTML 是自伤面（自己写的东西），但它同时是**复制粘贴面**——模板会被从别处粘贴、将来会被分享导入，那时它就是第三方内容。因此本方案用四条约束把它封住，且这四条都不牺牲"外观自由"：

1. **Shadow DOM 隔离** —— 用户样式不外泄，不会出现"抄了一段表格样式结果整个应用白屏"；
2. **禁止脚本** —— 剥离代码执行路径，样式配置不会变成任意代码；
3. **禁止外链** —— 卡片不会变成追踪像素，也保证离线可用；
4. **片段清洗** —— 子代理回填的 HTML 在进 DOM 前被清洗（禁止元素与属性移除，外部 CSS 整块移除），而骨架与外壳始终由用户持有的那份文档提供，模型写不到它们（决策 19）。

第 4 条在第三版**变重了**：第二版里"值永远是纯文本"是最后一道保险，代价只是呈现略死板；现在进 DOM 的是一段模型产出的 HTML，所以清洗不再是纵深防御式的兜底，而是**承重环节**。这也是把分析器从"反推契约"收缩成"查区间 + 查禁止构造"之后，唯一一处必须逐次运行的检查。

已核实的背景：本应用的 Electron 安全开关均为正确设置（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`），注入脚本够不到 Node；但它与应用 Web 客户端同源，**能以内置客户端身份调用宿主 HTTP API**——而那个 API 背后是有文件与工具权限的宿主。这是"禁止脚本"这条不可协商的原因。

### 9.3 结果交付的只有一份 HTML，因此没有字段与类型

第三版删掉了字段这一层：子代理交回的是**填好的区间 HTML**，不是 `{字段: 值}`。随之消失的是第二版记录的"类型推不出来"问题——没有字段名，就没有字段类型可推。语义由两处共同约定：

- **skill 正文**约定它产出什么（"dirty 输出 是/否"、"体积写成人读的 1.2 GB"）；
- **区间注释**约定这段区间要怎么呈现（每条一行、哪些列、什么顺序）。

模板本身仍然**没有逻辑语法**：不能对内容做条件判断或数值运算，也没有表达式位置。这不是缺陷而是分工：**skill 正文与注释负责语义，模板负责外观，契约只负责"有没有 `html`"。**

### 9.4 注释写得不对不会被拦住

第二版在这里记录的是"字段名写错不会被拦住"。**字段名已经不存在了，但同一类限制换了个位置存在，而且更宽**：契约只有一个 `html` 字段，它只回答"有没有交回一段 HTML"，**不回答内容对不对**。

具体后果：区间里的注释写得含糊，或者与 skill 正文的约定不符，模型会按自己的理解填出一段**看起来合理实则无意义**的内容，而校验不会失败——因为契约这一层根本没有东西可以失败。文档里也没有任何可写的字段名可供"校验"。

这正是决策 22 存在的理由：把注释写成可核对的说明（产出形态、条数来源、顺序），并在结果不对时**先回来改注释**，而不是反复重跑。用户还能拿结果与「查看原始输出」对照，判断是模型没按 skill 执行，还是注释没说清楚。这条缓解措施不可省略，因为契约永远不会替他发现这件事。

### 9.5 单实例的张力（决策 3）

"一种卡只有一张"让架构清明，但意味着用户不能同时开三张技能卡看三件事。本方案的答案是决策 14：**技能卡负责长尾，专用卡负责高频且需要专用交互的场景**。如果实践中发现用户反复在齿轮里来回切换，那就是专用卡该出现的信号。

### 9.6 模板不受设计系统约束

用户模板可以有任意颜色和字号，因此它可能与应用的深浅色主题不一致、可能在切换主题时显得突兀。方案不做强制（那会牺牲外观自由），但有一条现成的缓解：**应用的主题 token 是 CSS 自定义属性，本来就继承穿过影子边界**，用户模板直接写 `var(--dsw-…)` 即可，不需要额外桥接。唯一要守的纪律是不要在 `:host` 上写 `all: initial`。

## 10. 与现有架构的关系

### 10.1 零上游改动

本方案**不需要修改 `deepseek-harness/` 子模块**。所有需要的设施都已存在：

| 需要的能力 | 既有设施 |
| --- | --- |
| 宿主读出 skill 指令正文 | `ctx.skills.get(name, { scope: agent })` 返回的 `content` |
| 执行并强制结构 | 子代理的 `outputSchema`（本次固定为 `{ html: string }`）+ `structured_output` 工具 |
| 拿到已校验结果 | 子代理结果里的结构化值 |
| **拿到子代理自身的失败原因** | 宿主事件总线 `agent/error`：子代理这条缝只留下 `stopReason: 'error'`，错误对象被丢掉，事件是唯一来源 |
| 结果落盘 | 复用工作台已有的 storage domain |
| 读盘通知 | 上游 skill 文件系统已有 watcher |

### 10.2 需要新增的东西

| 新增物 | 归属 |
| --- | --- |
| 子代理执行的宿主服务（读 skill、发起执行、收结果） | `dsh-workbench` Host 半 |
| 子代理失败捕获（`agent/error` → 结果的诊断字段） | `dsh-workbench` Host 半 |
| 模板分析（区间定位 + 内容策略）与保存前的违例清单 | `dsh-workbench` Client 半 |
| 骨架拼接与片段清洗（`filledTemplate` / `renderTemplate`） | `dsh-workbench` Client 半 |
| 结构化结果与模板的存储读取通道 | `dsh-workbench` Host 半（复用 storage domain + 私域同源路由先例） |
| 配置的声明、校验、下发机制 | `dsh-workbench` Host + Client |
| 模板编辑器与实时预览 | `dsh-workbench` Client |
| Shadow DOM 渲染器 | `dsh-workbench` Client |
| 技能卡本身 | `dsh-workbench` Client |

> **已废弃（第二版）：** "模板解析与契约反推"（Client 半）与"宿主侧对反推契约做二次校验"。契约现在是两端共享的一个常量，没有可反推、也没有需要二次校验的东西；宿主仍会对送来的契约做一次廉价的形状预检，因为这是进程边界。

### 10.3 与原决策的关系

概要设计中确定过"不做卡片元数据通道，slot 账本是卡片唯一来源"。第二版方案与它不冲突：技能卡不增删卡片实例，只配置已有卡片的内容。

> **已被 P10 推翻（详见[详细设计 · P10](workbench-skill-card-detailed-design.md)）：** 技能卡现在支持"用户自己加卡"——用户可以创建多张具名卡片，也可以把一张卡连同它的模板与结果一起删掉。落地方式是**注册表仍只登记卡片类型**（slot 账本表达"有哪些类型的卡"），**卡片实例改为存盘的用户数据**，网格是那份存储的投影。因此"slot 账本是卡片集合的唯一来源"这条只对**类型**成立；实例的来源是存储，`WorkbenchCardFact` 也就分成了"类型"与"实例"两层。这条修订随 P10 落地，不是待办。

## 11. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 成本 | 只有点「运行」/「重跑」才产生模型调用；打开工作台、切换面板、刷新界面都不花钱；卡片显示上次执行时间让成本可追溯 |
| 性能 | 打开工作台是纯读缓存路径，不得有网络或模型等待；模板分析与预览必须即时，不阻塞输入 |
| 并发 | 同一张卡不并发执行；多张卡的并发上限需要在实现时定一个明确值（建议串行或很小的上限），不做无限并发 |
| 可访问性 | 执行中、完成、失败三种状态对读屏可见；取消可键盘触达；用户模板的无障碍质量由用户自己负责 |
| 国际化 | 卡片自身文案（含权限等级标注、各类空态与错误态）走 locale 字典；**用户模板内容与 skill 产出内容不翻译** |
| 数据体积 | 模板、结构化结果、原始输出的存储都要有上限，超限截断或拒绝并提示 |
| 安全 | 见 §9.1 与 §9.2 |

## 12. 技能卡按钮触发执行 ⏳ 待实现 · 未实现

> **状态：⏳ 待实现（未实现）。** 本节是**新需求规格**，不是现状描述。需求已与产品负责人定案，**代码里一行都还没有**：没有实现、没有测试、没有验收证据。FR-14～FR-23 全部是待做项，对应的验收标准是 17～34，在 §14 中单列为**未通过的待验收项**。
>
> 本节出现的"会 / 不会"一律读作**规格约定**，不读作"现在是这样"。判断一条东西是否已经存在于产品里，看的是源码与验收标准 1～16，不是这一节。

### 12.1 需求陈述

**要做的是：** 技能卡渲染出的模板区间里**可以有按钮**。用户点其中一个按钮，**先确认、再触发一次执行**；这次执行的目标由该按钮**声明**的目标决定。按钮的个数**跟着数据走**：子代理把多少行数据放进区间，就有多少个按钮。

**执行期间，这张卡自己的按钮不可点。**

这句话里有两个不同的东西，必须分开：**用户在模板里声明的目标**（`card "名称"` 或 `skill "名称"`），以及**模型在回填区间时写在按钮上的动作键**。前者是能力边界，后者只是从前者里挑一个。

> 以上是**规格**，不是现状。今天技能卡的区间里渲染不出可触发的按钮，相关代码一行都还没有。

### 12.2 术语

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 目标 | target | 一次按钮执行要触发的对象。只有两种：**卡片**（按名称）与 **skill**（按名称） |
| 动作键 | action key | 按钮携带的短标识；它**指向**一个声明好的目标，本身不描述目标。模型只能写键，不能写目标 |
| 动作声明 | action declaration | 用户写在模板里的声明块：`动作键: 目标类型 "目标名称"`。声明一次，多行按钮反复引用 |
| 整行数据 | payload | 触发那一行在回填区间里的**原始字段值**。它随确认面板**全文展示**，并进入被触发那次运行的提示词 |

### 12.3 目标类型

**下表的每一格描述"实现之后应当如此"，不描述当前行为。**

| 目标类型 | 用什么解析 | 点击后（规格） | 结果落在哪（规格） |
| --- | --- | --- | --- |
| **卡片** | 卡片**名称**（不是 id，见 12.4） | 跳到那张卡，并**立即让它运行一次** | **存在那张卡上**（与手动点「运行」同一条落盘路径） |
| **skill** | skill **名称** | 用**当前会话**起一次运行，**完全不携带模板文档** | **只有成功 / 失败**，什么都不持久化 |

两种目标共用同一套"确认 → 执行"外壳，差别只在上面这三个格子里。

### 12.4 决策汇总（本功能）

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| B1 | 卡片目标的行为 | 跳转 + **立即运行**；结果存在那张卡上 | 一次点击会消耗一次模型调用，且发生在用户刚跳过去的那张卡上 |
| B2 | 卡片目标的解析键 | 卡片**名称**；重名 → 报错；找不到 → 报错并**列出候选卡片**。**不使用卡片 id** | 用户改一次卡片名，所有引用它的模板就失效了；这是**已接受的代价** |
| B3 | skill 目标的结果 | **不持久化**，纯瞬态；重新加载后就没了 | 同一个 skill 目标跑两次，只有最后一次的结果可见，且刷新即失 |
| B4 | skill 目标的输入 | **不带模板文档**：没有 `<output_document>`、不填区间、不要 `{html}` 契约 | 这次运行没有任何呈现结构可依托，输出只用于判定成败 |
| B5 | skill 目标显示什么 | **只有成功或失败**：不显示执行过程、不显示模型推理、不显示输出文本 | 用户无法从卡片上判断"为什么是这个结果"，只能看结果本身 |
| B6 | 成功与失败的判据 | 成功 = 子代理**正常结束**；失败 = `agent/error` **或**超时，且失败**要显示诊断信息** | 诊断取自既有的 `agent/error` 通道（FR-21），不新增失败来源 |
| B7 | 确认 | **每次点击都要确认**；没有"不再询问" | 高频点击的场景会显得啰嗦；这是为 B8 的展示义务付的代价 |
| B8 | 确认内容 | **目标类型与名称 / 将运行的 skill / 参数全文 / 运行所属会话**，且**参数必须全文展示** | 这是一条**安全要求**，不是偏好：整行数据是模型基于远端工具输出生成的，马上要进下一次运行的提示词 |
| B9 | 确认的形态 | **就地面板**，替换卡片的显示区域；**不是模态框** | 共享原语没有对话框（现有编辑器也是就地面板，原因相同） |
| B10 | 参数取什么 | 那一行的**原始字段值**，不是渲染后的文本 | 渲染文本已经丢掉了字段边界，拼出来的参数无法追溯 |
| B11 | 一个按钮几个目标 | **恰好一个** | 想触发两件事就放两个按钮 |
| B12 | 占用 | **本卡运行中** → 本卡按钮不可点；**别的卡正在运行**时被触发 → **立即报错**（不排队、不等待） | 并发上限仍是 `maxConcurrentRuns`（决策与 M7 一致）；用户点快了会看到错误而不是排队 |
| B13 | 重复触发 | 同一行**可以反复触发**；按钮**从不消耗** | 每点一次就是一次新的运行，成本可累积 |
| B14 | 动作属性 | **白名单**：只有本功能定义的 `data-dsh-*` 属性生效，其它"像动作"的属性**什么也不做** | 用户或模型写下别的属性时不会得到意外行为，但也不会得到提示 |

### 12.5 功能需求（FR-14～FR-23）

> **FR-14～FR-23 全部是待做项。** 下面每条都写成"要做到什么"（祈使/规格口气），没有一条描述现有行为；它们与验收标准 17～34 一一对应。

#### FR-14 动作声明（模板侧）

- **声明与引用分开**是这一节的核心设计。用户在**模板里**声明目标，一次声明、多行引用；模型在**回填区间时**只能写**动作键**。
- 模板里携带一个声明块，形状是"动作键 : 目标类型 目标名称"：

  ```html
  <!-- dsh-actions
    提交: card "评审结果"
    归档: skill "git-commit"
  -->
  ```

  - 动作键是短标识，同一份模板内**不得重复**；重复即拒绝保存。
  - 目标类型只有 `card` 与 `skill` 两种；写别的类型即拒绝保存。
  - 目标名称是**非空**文本；空名称即拒绝保存。
  - 声明块本身**不渲染**（它是注释），也不进入区间。

- 用户在配置页写声明，与写模板是同一处、同一次保存。
- 声明是**模板的一部分**，因此按 skill 分别保存（决策 15），并随模板一起受体积上限约束。

#### FR-15 按钮与数据（区间侧）

- 子代理回填的区间里**可以有按钮**。每个按钮携带：
  1. 一个**动作键**（引用 FR-14 声明过的目标）；
  2. **那一行的原始字段值**（整行数据）。
- 按钮的**个数跟着数据走**：数据有几行就渲染几个按钮，由子代理在区间里产出。
- **一个按钮恰好一个目标**（B11）：按钮上没有"同时触发两个目标"的写法。
- 按钮只写**键与数据**，**不写目标类型与目标名称**——目标只能来自 FR-14 的声明。因此模型可以决定**哪一行用哪个已声明的目标**，但**永远无法凭空造出一个目标**。

**模型返回的样子。** 契约是 `{ html: string }`，`html` 里就是区间内容——**不含** `<!-- template-begin -->` / `<!-- template-end -->`，那对标记属于骨架，由代码保留：

```html
<tr>
  <td><span class="task-id">CP-2025-001</span></td>
  <td class="task-name">登录模块联调</td>
  <td><span class="status-badge status-active">进行中</span></td>
  <td>
    <button type="button"
            data-dsh-action="finish"
            data-dsh-row='{"task_number":"CP-2025-001","task_name":"登录模块联调","task_status":1}'>▶ 完成</button>
  </td>
</tr>
```

对照上例的两点：`data-dsh-action` 引用的是 FR-14 声明的**键**（不是 skill 名或卡片名）；`data-dsh-row` 里是**原始字段**（`task_status: 1`），不是同一行显示的中文（`进行中`）。

**引号转义。** `data-dsh-row` 用单引号包裹属性、JSON 内部用双引号，因此**字段值里出现的单引号必须转义为 `&#39;`**：

```html
data-dsh-row='{"task_name":"O'Reilly 重构"}'      ❌ 属性在此断开
data-dsh-row='{"task_name":"O&#39;Reilly 重构"}'   ✅ 转义后属性完整
```

属性一旦断开，读到的是**残损载荷**而不是完整数据。这会直接破坏 B8 的「参数全文展示」，而那条是本功能**唯一**的安全缓解。因此**载荷解析失败必须报错拒绝执行**，不能拿能读到的部分继续——部分载荷意味着确认面板展示的参数与实际执行的参数不是同一份。

**载荷体积上限。** 整行字段可能包含长文本，因此 `data-dsh-row` 必须受体积上限约束，且这个上限应当是**配置项**，与既有的几处上限同一套机制（模板 32 KiB、请求体上限、结果记录上限），不引入魔数。

**超限一律报错拒绝，不截断。** 理由同上：截断后的载荷会让确认面板展示的参数与实际执行的参数不是同一份，等于绕过 B8。因此这里的"超限"是**拒绝执行**，而不是"截断后继续"。

#### FR-16 点击与解析

- 绑定**必须是卡片容器上的事件委托**，**绝不能是逐按钮监听**：区间在**每次运行后都会被重新生成**，逐按钮绑定在重新生成后就会失效（验收标准 32）。
- 按钮在**影子根**里。`click` 是**组合事件**，会穿过影子边界，所以事件能到达卡片容器；但 `event.target` 会被**重定向到影子宿主**，因此真实按钮**必须从 `event.composedPath()` 里取**，不能读 `event.target`。
- 解析顺序：从 `composedPath()` 找到真实按钮 → 取动作键 → 在声明里查这个键 → 取目标。
- 找不到动作键对应声明时：**报错，不执行**（验收标准 19）。这是"声明与引用分开"的兜底：模型写错键不会变成一次误执行。

#### FR-17 目标存在性检查

- **卡片目标**：按**名称**解析。
  - 名称**重复** → 报错（B2）。
  - 名称**找不到** → 报错，并**列出候选卡片**（B2）。
  - **不使用卡片 id**；改名导致的失效是已接受的代价。
- **skill 目标**：按**名称**在**当前会话**的 skill 目录里解析；找不到 → 报错，并**列出已安装的 skill**。
- 两类检查都在**确认之前**完成：目标不存在就没有可确认的东西，也就不会走到执行。

#### FR-18 占用检查

- **本卡正在运行**：本卡的所有按钮**不可点**（不是"点了报错"，而是不可点）。
- **别的卡正在运行**：被触发时**立即报错**——不排队、不等待、不静默丢弃（B12）。
- 并发上限沿用 `maxConcurrentRuns`，本功能不新增第二条并发规则。

#### FR-19 用户确认

- **每次点击都打开确认**（B7），没有"不再询问"。
- 确认是**就地面板**，替换卡片的显示区域，**不是模态框**（B9）。
- 面板必须展示四项（B8）：
  1. **目标类型与名称**；
  2. **将运行的 skill**（卡片目标就是那张卡选的 skill）；
  3. **参数全文**——**必须全文**，不得截断、不得折叠、不得只显示摘要；
  4. **运行所属会话**。
- 面板提供**确认**与**取消**两个动作。取消**不产生任何副作用**（验收标准 25）。

#### FR-20 卡片目标执行

- 确认后：**跳到那张卡**（整栏切到它的结果页），并**立即让它运行一次**。
- 结果走**与手动点「运行」完全相同的那条路径**落在**那张卡**上：同一种存储记录、同一种时间戳、同一种"已过期"判定。
- 因此那张卡此前的结果被这一次覆盖，这不是缺陷，是"同一张卡的一次运行"。

#### FR-21 skill 目标执行

- 用**当前会话**起一次执行（会话选定规则沿用现有实现：`origin !== 'subagent'`、`blank !== true`，取 `updatedAt` 最新）。
- **完全不携带模板文档**（B4）：提示词里**没有** `<output_document>`，**不填区间**，**不使用** `{html}` 输出契约。
- **只显示成功或失败**（B5）：不显示执行过程、不显示模型推理、不显示输出文本。
- 判据（B6）：**成功** = 子代理**正常结束**；**失败** = `agent/error` 或**超时**，并且失败**要显示诊断信息**。
  - 诊断信息来自**既有的** `agent/error` 通道（宿主按子代理 id 归因到本次运行的 `diagnostic`），本功能**不新增**失败来源。
- **什么都不持久化**（B3）：不写结果、不写模板、不改卡片配置；**重新加载后卡片回到它自己的结果**（验收标准 28）。

#### FR-22 重复触发

- 同一行**可以反复触发**（B13）：按钮**从不消耗**，点第二次与第一次走完全相同的路径（包括再一次确认）。
- 重复触发**仍然受占用检查约束**（FR-18）：第一次还在跑时，本卡按钮不可点。

#### FR-23 动作属性白名单

- 只有本功能定义的 `data-dsh-*` 属性**生效**；其它任何"看起来像动作"的属性**什么也不做**（B14）。
- 白名单是**封闭**的：新增一个生效属性必须改这一节，而不是在模板里写出来就生效。

### 12.6 实现前必须知道的四个事实

这四条改变了做法，都是查证过的机制事实，先记在这里，免得实现时踩：

| 事实 | 为什么重要 |
| --- | --- |
| `data-*` 属性**不在清洗黑名单里** | 按钮可以携带动作声明而不被清洗掉（§6.4 的禁用清单管的是脚本、事件属性、危险 URL 与外链，不管 `data-*`）。**这是本功能能成立的前提** |
| `click` 是**组合事件**，会穿过影子边界；但 `event.target` **被重定向到影子宿主** | 事件委托能收到点击，但**必须从 `event.composedPath()` 取真实按钮**；读 `event.target` 会拿到宿主元素 |
| 区间**每次运行都会重新生成** | 绑定**必须**是卡片容器上的**事件委托**，逐按钮监听在重新生成后必然失效 |
| **`data-*` 可以携带动作声明，正好也是风险所在** | 整行数据是模型基于远端工具输出生成的，它**马上要进下一次运行的提示词**；这条"远端数据 → 参数 → 下一次运行"的路径是**本功能最大的风险**，B8 的"参数全文展示"就是它的唯一缓解——因此那条不是可选的偏好 |

### 12.7 风险

- **注入面变宽了一层。** 现状里进提示词的是**用户自己写的模板**（§9.1、§9.2 的自伤面）；本功能之后，**模型基于远端数据生成的一整行字段**也会进提示词。缓解只有一条：**B8 的全文展示**——用户必须在按下确认之前，把将要进入运行的那段参数**完整看一遍**。截断、折叠、摘要都会让这条缓解失效。
- **卡片名是夹具。** 引用按名称解析，所以一次改名会让模板里的引用失效（B2 已接受）。解析失败必须**报错并列出候选**，而不是猜一个最像的。
- **skill 目标没有可追溯的产物。** 结果不落盘（B3），卡片上只有成败（B5）。这是刻意的，代价是排障只能靠当时的屏幕与宿主日志。
- **点击成本可累积。** 每次点击都是一次模型调用（B7、B13），没有批量、没有"不再询问"。若实践中出现连点，先看的是确认面板是否足够清楚，而不是加一个跳过开关。

### 12.8 本节的验收标准

见 §14 中**验收标准 17～34**（标注为**未通过的待验收项**）。本节**没有**已通过的验收项：功能未实现。

## 13. 明确不做

- **不做**模板里的逻辑语法（没有条件判断、循环与表达式位置；重复由子代理在区间里产出）。
- **不做**在卡片里编辑 SKILL.md。
- **不做**执行历史列表与导出（决策 `card_actions` 只到"查看原始输出"）。
- **不做**卡片级模型选择（决策 12）。
- **不做**定时或条件触发的自动执行（决策 10）。
- ~~**不做**用户自行增删卡片实例（决策 3）。~~ **已由 P10 推翻**：用户可以创建多张具名卡片（网格末尾的「创建卡片」磁贴，选类型即在建卡时起一个可改的默认名），也可以把一张卡连同它的模板与结果**物理删除**。
- **不做隐藏。** 这条不是"暂不做"而是**能力已移除**：卡片外壳只在卡片提供 `onRemove` 时画出 X，X 只表示删除；布局记录只剩排序一维，宿主也不再解析 `hidden`。旧记录里仍写着 `hidden: true` 的卡片按可见读回，不做迁移（验收标准 16）。
- ~~**不做**skill 参数传入。~~ **§12 部分改变这一条（未实现）**：skill 目标仍然**不接受用户填写的参数**，但会把**整行数据**（模型回填的原始字段值）带进那次运行。这是"带一段数据"，不是"给 skill 传参数"，但两者的边界必须在实现时守住：整行数据只来自回填区间，且必须先经 §12 的确认面板全文展示。
- **不做**模板的分享、导入、导出（模板按 skill 存在本地配置里）。
- **不做**除技能卡外的其它可配置卡片（决策 5 的机制要通用，但使用者只落地技能卡）。

## 14. 验收标准

方案共 **34 条**验收标准，分两组，**状态完全不同**：

| 组 | 条数 | 状态 |
| --- | --- | --- |
| 14.1 已实现并验收（1–16） | 16 | ✅ **已通过**：对应的代码与包级测试都在 `dsh-workbench/` 里，`corepack yarn workspace dsh-workbench check` 通过 |
| 14.2 待实现、待验收（17–34） | 18 | ⏳ **未通过 / 未实现**：它们属于 §12 的按钮触发执行功能，代码里还没有对应实现，因此**不是验收证据** |

逐条与功能需求、设计模块的对应关系见 [附录 A](#附录-a验收标准映射) 与[技能卡详细设计 · 附录 B](workbench-skill-card-detailed-design.md#附录-b验收映射)。

### 14.1 已实现并验收（1–16）

1. 用户选一个 skill、写一份带区间标记的 HTML 文档并保存后，点「运行」，卡片按模板渲染出结果（骨架 + 回填区间）。
2. 子代理**只回填区间**：区间之外的内容不被改动，骨架在多次运行之间**逐字节不变**。
3. 模板缺区间标记、标记未闭合、标记重复，或仍写 `{{字段}}` 占位符语法时，**保存前被拒并说明原因**。
4. 模板里写了 `<script>`、`on*` 事件属性、外部资源元素或外部 CSS 时，**保存被拒绝并指出位置**。
5. 用户样式**不会影响影子根之外**：模板里写全局选择器（如 `* { display: none }`）后，应用其余部分正常。
6. 子代理回填的片段里若夹带 `<script>`、`onerror=` 之类的构造，**渲染前被清除**，不会执行、不会加载。
7. 打开工作台**不产生任何模型调用**（可用网络/调用计数验证）。
8. 结果里没有 `html` 时，恰好重试一次；仍失败则显示错误态且「查看原始输出」可用。
9. 编辑器随输入就地列出违例并禁用保存，并实时预览正在编辑的文档；预览与正式渲染走同一条隔离与清洗路径。
10. 未写模板时**不能运行**，卡片给出可操作的引导，且不发起任何模型调用。
11. 各类降级态（无活跃会话、skill 失效、模板被拒、结果过期、旧结果无 `html` 等）各自给出可操作的指引，无一处是"通用错误"。
12. 子代理自身报错时，失败原因被捕获并写入结果的诊断字段，能在「查看原始输出」中看到，而不是只剩一个 `error`。
13. 执行中可取消，取消后卡片状态与文案正确。
14. 卡片上有权限等级标注；危险操作仍走会话的审批流。
15. 契约与结果的处理不修改 `deepseek-harness/` 子模块（`git status` 中子模块无改动）。
16. **卡片模型成立**：全新安装的工作台上只有「创建卡片」磁贴；点它**只选一个类型**就建卡（磁贴里不起名）；卡片正面只显示**卡片名称、skill 名称与「配置」**；点卡片本体整栏切到**该卡的结果页**，「运行」就在那一页；点「配置」整栏切到**该卡的配置页**（名称、skill、模板）；X 是**物理删除**，把卡片连同它的模板与结果一起删掉；**任何位置都不提供隐藏**（卡片正面、配置页与布局域都没有这条路径），旧记录里仍写着 `hidden` 的卡片按可见读回。

### 14.2 待实现、待验收（17–34）⏳ 未实现

> **这一组是待验收项，不是证据。** 它们描述 §12 的按钮触发执行功能在**做完之后**应当满足什么；此刻代码里没有对应实现，包级测试里也没有对应用例。任何"本文档列了它，所以它存在"的读法都是错的——这正是第四版清理掉的那类缺陷。

17. **动作声明在保存时被校验**：同一份模板内动作键重复、目标类型未知、目标名称为空，均在保存前被拒绝并说明原因。
18. **每个按钮最多携带一个目标**，并携带**它那一行的原始字段值**。
19. **按钮引用了未声明的动作键时**：报错，**不执行**。
20. **卡片目标找不到时**报错并**列出候选卡片**；卡片名**重复时**报错。
21. **skill 目标找不到时**报错并**列出已安装的 skill**。
22. **本卡运行中时，本卡按钮不可点。**
23. **目标卡正在运行时被触发 → 立即报错**，不排队、不等待。
24. **每次点击都打开就地面板确认**，面板展示四项（目标类型与名称 / 将运行的 skill / 参数全文 / 运行所属会话），且**参数全文展示**（不截断、不折叠）。
25. **取消确认不产生任何副作用**：不发起运行、不写存储、不改卡片状态。
26. **卡片目标**：确认后跳到那张卡、**立即运行**，结果**存在那张卡上**。
27. **skill 目标**：用**当前会话**运行，且**不携带任何模板文档**。
28. **skill 目标只显示成功或失败**，且**什么都不持久化**；重新加载后卡片回到它自己的结果。
29. **子代理正常结束算成功**；`agent/error` **或超时算失败**，并**显示诊断信息**。
30. **同一行可以反复触发**（按钮不消耗）。
31. **未声明的动作属性不产生任何行为**（白名单之外什么也不做）。
32. **区间重新生成后按钮仍然可用**（事件委托生效，不是逐按钮绑定）。
33. **载荷无法完整解析时**（引号未转义等原因导致属性断开）→ **拒绝执行并报错**，确认面板**不出现**；**不得**按能读到的部分继续。
34. **载荷超过配置的上限时** → **拒绝执行并报错**，**不截断**。
