# 工作台卡片需求方案

[工作台概要设计](workbench-design.md)确定了卡片式工作台的位置、展示与存储归属，[工作台详细设计](workbench-detailed-design.md)把它落到了模块级并完成了 P1–P4。本文处理下一层诉求：**让卡片可配置、可执行、外观由用户自己写**。

本文是需求方案，不是实现设计。它只回答"要什么、为什么、什么算做完了"，实现级拆分留给后续的详细设计续篇。

> **修订说明。** 本文第十一版。
>
> - **第二版**把外观控制权整体交给用户：**用户写 HTML 模板，skill 只负责把数据填进去**。同版内又把模板从「可选、缺省时自动推导」改为「**使用卡片的前置条件**」，当时的理由是"契约由模板反推，无模板时既不存在契约，也没有可供自动推导的结构化结果"。**这条理由在第三版已失效，但"模板是前置条件"的结论保留**（新理由见 §7）。
> - **第三版**删除了占位符与循环语法，也删除了"从模板反推契约"。模板不再声明字段：**整份文档就是规格**，宿主把它原样发给子代理，子代理只回填 `<!-- template-begin -->` 与 `<!-- template-end -->` 之间的一对区间，代码再把回填结果拼回骨架。**没有兼容模式**——仍写 `{{字段}}` 的模板会被明确拒绝（`placeholder-syntax`），而不是把花括号当字面量渲染出来。§3 中标注「改(本次)」的条目是本次变更；文中保留的旧表述都已就地标为**已废弃**。
> - **第四版**做两件事。其一，**隐藏能力从源码整体移除**：卡片外壳只在提供 `onRemove` 时画出 X，X 永远表示删除；布局记录只剩排序一维，宿主也不再解析 `hidden`，旧记录里写着 `hidden: true` 的卡片按可见读回而不做迁移（§13、验收标准 16）。其二，**§14 增加第 16 条验收标准**，把卡片模型（创建、正面、结果页、配置页、X 的删除语义、不提供隐藏）写成可验收的一条，并新增[附录 A](#附录-a验收标准映射)记录逐条映射；条数从那时起是 16，详细设计的 M13 / M14 / 附录 B 同步。
> - **第五版**新增一节「技能卡按钮触发执行」（§12、FR-14～FR-23、验收标准 17～34）。该版交付时这一节**只是需求规格**，代码里没有对应实现。
> - **第六版**这一节**已实现并验收**：`dsh-workbench` 的 M5（就地确认面板）、M7（skill 目标轻量运行）、M6（卡片目标：跳转 + 运行 + 存储）全部落地，实现与验收证据在包级测试里，`corepack yarn workspace dsh-workbench check` 通过。**验收标准 17～34 因此翻为已验收**，[附录 A.2](#a2-已实现并验收1734)逐条注明覆盖它的 spec 文件。本轮还修掉了第五版留下的一个真缺陷：§12.2 与 FR-15 都要求**整行数据进入被触发那次运行的提示词**，而实现前的设计文档漏了这一步，导致"参数全文展示"变成只展示不使用；现在两种运行模式的提示词都携带 `<row_data>`，确认面板展示的载荷与运行收到的载荷逐字节相同（`tests/skill-card-row-data.spec.ts`）。实现过程中对设计做的每一处补充都记在[技能卡按钮触发执行 · 详细设计](workbench-skill-card-actions-design.md)的对应模块里。
> - **第七版**补上编辑器与配置页的需求。行号栏、状态行、键盘、违例定位、动作声明构建器、缺失目标告警、骨架插入、并排/切换，以及配置页的布局、粘性页脚与两段式删除，此前只写在[详细设计 · M10](workbench-skill-card-detailed-design.md#m10-编辑器与配置页)里，需求侧没有对应条目——**这正是本版补的两件事**：新增 [§17](#17-模板编辑器与配置页)（FR-24～FR-36、本功能的决策表 E1～E11），并在 §14 增加验收标准 **35～48**，逐条覆盖见[附录 A.3](#a3-已实现并验收3548)。同版还记下三条由缺陷反推的约束（存储 schema 必须声明 store 写入的每个字段、CSS 只能用主题实际定义的令牌、页头不再放「刷新」），见 [§17.5](#175-由缺陷反推的三条约束)。**1～34 的状态不变**：仍然全部已实现并验收。
> - **第八版**补上结果页。结果页此前只写在详细设计的 M10 / P10 里，需求侧没有条目。本版新增 [§18](#18-结果页可读性与对话式微调)（FR-37～FR-42、决策 R1～R8），并在 §14 增加验收标准 **49～56**，逐条覆盖见[附录 A.4](#a4-已实现并验收4956)。这一版有三件事：**① 把调试区做成能读的**（`html` 按真实换行渲染、缺失字段整行不出现、默认折叠、状态并成一行）；**② 给结果一个框**（有边框表面——当时还带一行「结果」标题，权限说明降为页脚、与调试区之间一条细线）；**③ 加上对话式微调**——运行模式多一种 `refine`，请求带一句修改要求和上一版 HTML，结果仍由存盘的那份模板承载，输出契约仍是 `{html}`，所以解析、清洗、拼接全部复用。修改记录与「上一版」**只在内存里**，重新加载就没了，这是明确接受的代价（R5）。**1～48 的状态不变**：仍然全部已实现并验收。（这一版加的那行状态与那个「结果」标题，第十一版已按产品决定移除，见下一条与 §18。）
> - **第九版**是结果页的一批打磨，并推翻第七版的一条决定。**（这一版的五件事与验收标准 57～60 见 §14.5。）** 这一版五件事，都写在 §17 与 §18 里：**① 微调那句话原本写在一个单行文本框里，现在换成与聊天输入区同形的多行编辑区**（一到四行、随内容长高，`Enter` 提交、`Shift+Enter` 换行，输入法组字时不提交；尺寸不是拍出来的，是从 `@deepseek-ai/dsh-client-ui-conversation` 的 `InputBar.module.css` 读来的，见 FR-41）；**② 运行中那块主控件变成「停止」**，而不是禁用（FR-44）——长任务必须在用户正在看的地方可以中断，页面头部的取消在结果把页面撑高之后已经滚出视野；**③ 运行详情能读了**（标题改为「运行详情」、代码块去掉模板区间的公共缩进、结束原因本地化，见 FR-37）；**④ 修改记录有了头部行**（`修改记录 · N 次` + 「回到上一版」在同一行，「只在本次会话」是整块的最后一行，见 FR-42）；**⑤ 面板标题回归**——每个视图（含结果页与配置页）都重新带「工作台」标题，卡片页自己的头部在它下面（FR-43）。第五条**明确推翻了第七版**"卡片页不画面板标题"的决定，理由见 FR-43。**1～56 的状态不变**：仍然全部已实现并验收。
> - **第十版**让结果可以手工编辑。一次运行的结果并不总是对的，而有时候要改的只是两个字符，不是再花一次模型调用。结果页头部在「运行」左边多一个次级「编辑」，把结果表面就地切成一个编辑器：它编辑的**只有存盘的区间片段**（`stored.result.structured.html`），保存后这段 HTML 就是这张卡的结果。编辑器与模板编辑器同一套键盘（Tab / Shift+Tab 缩进、Escape 之后 Tab 离开、Ctrl/Cmd+S 保存），但**没有**区间染色、动作声明构建器与骨架插入——片段没有这些东西。保存前拒绝三件事：五个内容策略构造（渲染器会静默剥掉它们，存进去会读成"存了却没生效"）、空内容（空区间渲染出来像坏卡）、超过 `WORKBENCH_RESULT_MAX_BYTES`（拒绝，绝不截断）。结果记录新增 `editedAt`，运行详情里多一行「手工编辑」；它**刻意不进修改记录**（那份记录记的是指令），但「回到上一版」仍能退回编辑前那一版。新增 [§19](#19-手工编辑结果)（FR-45、决策 E13～E18）与验收标准 **61～70**，逐条覆盖见[附录 A.6](#a6-已实现并验收6170)。**1～60 的状态不变**：仍然全部已实现并验收。
> - **第十一版**撤掉结果页的两处噪音，并撤回一条验收标准。产品负责人判定两样东西都是噪音：结果面上方那行**状态行**（`✓ 已完成 · 14:28:36 · 用时 42s`），以及结果表面里那行**「结果」标题**。两处都整行移除，**没有被任何东西替代**；结果表面的边框、圆角与内边距留下，容器的边界从此只靠内边距把渲染文档挡在边框之外。状态与时间这两个事实没有丢：结束原因与开始时间仍在「运行详情」里（FR-37）。因此**撤回验收标准 52**——它规定那一行显示什么，现在没有那一行——**编号保留、不顺移**（见 §14.4）。这是一次产品决定，**不是回归**：后来的人不要把它加回去。
> - **第十二版让每张卡自己选模型。** 卡片配置的「基本信息」多一个字段：**模型**——按 provider 分组的 `select`，选项文本是 `ModelCatalogModel.name`，默认选中**当前会话的模型**（不是空选项：一张卡永远显示一个具体模型）。模型以 **`{ provider, model }` 这一对**存储，不存 `"provider/model"` 字符串（provider id 本身可能带斜杠，拆回去一定出错）；v1 **不带 `reasoningEffort`**。运行路径把这对值作为子代理的 `agentOptions` 传下去，结果记录以 `model?` **记下这次运行用的路由**，运行详情里因此多一行「模型」——用户不该猜一份结果出自哪个模型。**不可用就拒绝，不回退**：卡片写了模型而该 provider 不存在、模型不在其目录里、或子代理后端不支持 `agentOptions` 时，宿主在启动前就拒绝，并在消息里点名那条路由，**不会悄悄跑在会话的模型上**。新增验收标准 **71～79**，逐条覆盖见[附录 A.7](#a7-已实现并验收7179)。**1～70 的状态不变**：仍然全部已实现并验收（52 仍是撤回态）。
> - **第十三版（当前）给每张卡一个自己的工作目录，并且运行前必须先有它。** 配置页「基本信息」从三个控件变成四个，排版改成**两行两列**（名称 / 技能，模型 / 工作目录）：新字段的主值是**目录名的最后一段**，完整路径是它下面那行次要文字，旁边一个按钮打开目录选择器。存的是**一条完整绝对路径**（`workspace?: { path: string }`），**不是工作区 id**——产品要的是"用户选哪个目录就是哪个目录"，而那个目录不必是已注册的工作区。**选择器按平台分派**：Windows 走 Desktop 插件发布在窗口上的 `__DSH_DESKTOP_PICK_DIRECTORY__`（桌面自己的同源路由），其他平台走应用自己的 `uiWorkspace.pickDirectory()`；**没有自由文本输入**——产品负责人明确否掉了手打路径，也否掉了工作区下拉，理由是手打出来的目录没有被任何选择器确认过。**一个纯函数 `resolveWorkspaceField()` 拥有三种状态**（`missing` / `invalid` / `ready`），字段与运行控件读的是同一个值，所以不会出现"字段说没有、按钮还能按"。**拒绝，绝不回退**：没有目录、或目录已不存在时运行被拒，失效的那条消息点名**完整路径**，绝不会悄悄跑在会话的目录里。**没有迁移**：已有卡片读回来没有工作目录，在配上之前不能运行——这是产品负责人的明确决定。**除运行以外全都照常**：打开卡片、改名称 / skill / 模型 / 模板、预览、手工编辑结果、读已存结果都不要这个字段。新增验收标准 **80～92**，逐条覆盖见[附录 A.8](#a8-已实现并验收8092)。**1～79 的状态不变**：仍然全部已实现并验收（52 仍是撤回态）。
> - **第十三版有一条必须先读的缺口，写在这里而不是留给读者自己发现：工作目录还没有约束运行写到哪里。** 卡片记下这个目录、并据此放行或拒绝一次运行，但**运行仍然在父会话的目录里执行**：执行底座仍是 `ctx.subagents.startActivation`，它的 `cwd` 只改子代理的有效工作目录，**不改文件沙箱的根**（实测过两件事：子代理的 `session.header.cwd` 仍是父会话的，`sandboxPolicy.resolve().workspaceRoot` 也仍是父会话的；机制见[详细设计 M5 的「工作目录」](workbench-skill-card-detailed-design.md#工作目录一道门还不是一间房第十三版)与它附录 C 的四条出处）。真正的收口需要一次基于 `agents.create({ meta: { cwd } })` 的运行，**这一版没有实现**。所以这张卡的目录目前是**一道门**，不是**一间房**：任何一句话都不该读成"写入被限制在所选目录里"，它也不是沙箱隔离。另一条既有约束照旧：卡片能跑起来依赖宿主提供 `subagents.startActivation`（`0.2.1-alpha.2` / beta 通道；`0.2.0-rc.2` 能加载、能编辑，不能运行），见 `dsh-workbench/INSTALL.md` 第 0 节「前提」与 FR-5，这里不重复。已知限制的完整三条见 [§14.8](#148-已实现并验收8092)。**（第十四版更新：这条缺口的插件侧已经落地——运行现在挂在一个根在卡片目录的 agent 上；但栅栏本身仍未被验证，也没有任何真实应用跑过，见 §14.9 的第 100、101 条。那段"这一版没有实现"读作历史。）**
> - **第十四版把"一道门"往"一间房"推了一步，但只推到插件这一侧，而且两重限制必须先说。** 插件现在给每张卡**自己造一个 agent**，根在卡片目录（`agents.create({ sessionId, meta: { cwd } })`），并把它作为这次运行的**父**：文件沙箱的 `workspaceRoot` 取自 `session.header.cwd`，而子代理这条缝**把父的会话头复制给子**，所以父根在哪个目录，子就落在哪个目录。seam 本身一行没改——提示词投递、`{html}` 捕获、那一次重试、取消与 `agent/error` 归因都是它的。**每次运行建一个、结算后退役**（第十六版修正：原先是"建一次、之后复用"，但 harness 的 `ArchivedSessionGate` 会拒绝已归档会话的后代，复用归档过的 agent 让第二次运行直接以 `refusal` 结束）；**存的那条路径变了就拆掉旧的、按新目录重建**；`dispose()` 释放仍在缓存里的卡片 agent；每次运行结算后**归档**该 agent 的会话并**释放它**，让 `workbench-card-*` 不进侧边栏（归档失败只 `warn`，**绝不把已经捕获的结果变成一次失败**）。宿主表面因此多两项：`agents.create`（返回 `{ agent, dispose }`）与 **`workspaceRegistry.archiveSession`**——宿主对象是 `ctx` 的**宽 cast**，所以这个名字**没有任何一层能检查**：写成 `workspaces`（那是**客户端**服务名）照样编译、照样测试全绿，运行时只会走进那条 `warn`；同理它还必须写进插件的 `inject`，漏了会在运行时抛 `cannot get property … without inject`。这两件事都只能靠读源码与一次真实运行保证（见 §14.9 第 99 条）。**新增验收标准 93～101**，逐条覆盖见[附录 A.9](#a9-运行被钉在卡片目录上93101)。
> - **第十四版的两重限制，写在这里而不是留给读者自己发现。** 其一，说"写入真的被限制在卡片目录里"的那个 spec —— `dsh-workbench/tests/skill-card-workspace-sandbox.spec.ts` —— 是**故意 skip 的 3 条**：它需要真实宿主、真实会话与真实文件写入，**它是规格，不是一条通过的测试**。其二，本功能**每一条结论都来自单元测试或探针脚本**（`dsh-plugin-desktop/scratch/agent-cwd-probe.mjs`），**从来没有在应用里点过一次**。所以准确的说法只有一句：**插件把运行挂在一个根在卡片目录的 agent 上；那之后沙箱是否真的拒绝越界写入，没有人验过。**
> - **第十五版（当前）给每张卡一个自己的权限模式。** 配置页「基本信息」多出**第三行**：三种模式（`read-only` / `workspace-write` / `danger-full-access`），文字与**应用自己的权限选择器**一致（仅可查看 / 工作区内修改 / 完全权限）；选「完全权限」时，同一格里就地写明**工作目录不再限制写入**。存的是卡片记录上的 `permission?`，**不写就是 `workspace-write`**——不是"跟随会话"，而是一个具体默认值，所以**已有卡片会变严**，这是产品负责人明确要的结果。模式落在**卡片自己的那个 agent 上**（一条 `sandbox/mode` 会话事件）：子代理继承父的显式 override，所以这一次写入就是"这张卡的运行都按它跑"的全部机制。**换模式就重建 agent**（缓存键含模式，旧 agent 先 `dispose`）；**应用不了就拒绝这次运行**（`permission-unavailable`，消息点名卡片与模式），绝不悄悄按别的模式跑。`danger-full-access` **允许**，代价写在选择它的那一格。新增验收标准 **102～108**，逐条覆盖见[附录 A.10](#a10-每张卡自己的权限模式102108)。
> - **第十五版那句必须一起读的话：这一整套权限机制，压在一条从来没有在真实应用里验证过的围栏上。** 模式只决定**沙箱允许写到哪里**，而沙箱的根来自卡片 agent 的会话头——也就是第十四版造的那间"房"。第十四版已经写明：那间房**没有被验证过**（`tests/skill-card-workspace-sandbox.spec.ts` 是 3 条故意 skip 的规格，第 100 条），**也没有任何真实应用跑过**（第 101 条）。所以本版能主张的只有两句：**卡片把用户选的模式写进了它自己 agent 的会话**；**沙箱是否因此真的收紧或放开写入，没有人验过**。任何一句话都不该读成"写入已被限制在所选目录里"。（`read-only` 相对最硬：它在宿主自己的写路径上就拒绝；`workspace-write` 与 `danger-full-access` 的差别完全取决于那个根。）

## 1. 需求陈述

一句话：

> 工作台上有一张**技能卡**。用户在它的配置里选一个 skill，**用 HTML 写整份文档**（表格、列表、任意排版）——用 `<!-- template-begin -->` / `<!-- template-end -->` 标出子代理要填的那一段，并在那一段的注释里写明填什么。点「运行」，宿主把这份文档**原样**交给一个**独立子代理**，让它按这个 skill 的指令执行、只回填那段区间并以 HTML 交回；代码把回填结果拼回骨架、清洗后渲染出来。结果落盘并带时间戳，只有用户主动点「运行」才会产生模型调用。

**模板是使用这张卡的前置条件**：没有模板就没有可交给子代理的规格，也没有可供拼回的骨架。卡片在无模板时给出明确引导，而不是替用户猜一个呈现方式。

它要解决的原问题是"卡片太死"：现有卡片由插件包在编译期注册，展示什么、怎么展示都写死在插件里。而用户想要的是**加一张卡就能看到一类新信息，并且外观自己说了算**——不需要为每个信息源写一个插件包，也不需要迁就系统的固定排版。

## 4. 使用流程

**配置。** 用户在工作台看到技能卡的空态，点卡片上的「配置」，从 skill 列表里选一个 skill。

**写模板。** 用户写这张卡的**整份 HTML 文档**：骨架（标题、样式、排版）自己定，用 `<!-- template-begin -->` / `<!-- template-end -->` 标出子代理要填的那一段，并在那一段里用注释写明它要产出什么。编辑器**实时预览**正在编辑的这份文档，就地列出违例（标记缺失/未闭合/重复、仍写占位符语法、禁止构造、超体积）。**没有模板，卡片就不提供「运行」。**

**运行。** 用户点「运行」，宿主把整份文档（注释在内，逐字不改）连同 skill 正文交给一个独立子代理，要求它只回填区间，并只回报那一段 HTML。

**看结果。** 执行完成后，代码把回填的区间拼回骨架、清洗后渲染出来，放进结果表面这块有边框的表层里（§18）。这一页不再另起一行说运行状态：结束原因与开始时间在下方的「运行详情」里，结果本身就在框里。骨架是用户写的那一份，逐字节不变。

**改结果。** 结果不满意时不必重跑：在结果下面写一句要求（例如"按时间倒序"），子代理在**上一版结果**的基础上只改这一处，结果就地替换。那句话写在一块**会随内容长高的编辑区**里（与应用的聊天输入区同形，`Enter` 提交、`Shift+Enter` 换行）；运行中它旁边的主控件变成「停止」，长任务不必回到页面顶部去中断。本次会话里保留一份上一版与一份修改记录，所以可以退一步（§18）。要改的是"产出的规则"而不是这一次产出时，仍然回到编辑器改注释或骨架。

**修订模板。** 用户点「配置」重新打开编辑器（整栏的配置页，见 §17）。结果不对时改两处之一：**区间里的注释**（说明写得不清楚，模型就会填错）或**骨架的排版**。契约只有一个 `html` 字段，它不会替你发现内容填错了。

**日常使用。** 打开工作台直接看到上次结果，不触发任何模型调用。点「运行」或「重跑」才刷新。

**结果不能用。** 模型没有按契约返回（结果里没有 `html`）时，宿主自动重试一次；仍失败则卡片显示错误态，结果页的「运行详情」里能读到原始输出。如果失败来自子代理自身，卡片还能带上从宿主事件总线捕获到的失败原因。

**换了 skill。** 模板按 skill 分别保存；切回原来的 skill，原来的模板还在。新 skill 在没有模板之前不能运行。

**旧模板。** 第二版写的模板（含 `{{字段}}`、`data-dsh-each`，或压根没有区间标记）**不能运行**：保存会被拒并给出可操作提示，用户必须改写成区间标记的写法。旧版本存下的结果（结构化值里没有 `html`）按**尚未运行**显示，而不是渲染一个空框。

## 5. 功能需求

### FR-1 技能卡注册

技能卡作为 `dsh-workbench` 的一张卡注册，遵循既有卡片契约（`workbench.card` 工厂 + `workbench.cards` 列表槽）。它与其它卡片一样参与排序，但**不参与隐藏**：外壳只在卡片提供 `onRemove` 时画出那个 X，而 X 永远表示删除。**隐藏不是本产品的能力**，布局记录里也没有这一维（详见 §12 与验收标准 16）。

### FR-2 配置：选择 skill

- 卡片提供**配置入口**，打开该卡自己声明的配置表单。入口在卡片正面头部动作里，是一个写着「配置」的按钮（决策 4 记的"右上角齿轮"是 P10 之前的位置；表单与职责没有变，整栏的配置页见 §17）。
- 技能卡的配置分为两部分：**选择 skill** 与 **编写模板**（FR-3）。
- 配置提交后由宿主校验并持久化（见 FR-13），失败时不静默丢弃。

### FR-3 模板编写与存储

- 模板以**当前选中的 skill 为键**分别保存（决策 15）。
- 模板内容持久化，与卡片配置同一存储归属。
- 模板有体积上限，超限时拒绝保存并说明。

### FR-4 模板分析与区间标记

- **客户端**用 `analyzeTemplate(html)` 分析模板，得到 `{ region, violations }`（决策 8、16）。它只回答两个问题：
  1. **有没有恰好一对可用的区间？** 缺失、未闭合、重复、闭合标记出现在开启标记之前，都拒绝（`region-missing`、`region-unclosed`、`region-repeated`）。
  2. **文档有没有夹带它不该有的东西？** 见 6.4 的禁止清单（`script`、`event-attribute`、`unsafe-url`、`external-element`、`external-css`）。
- 模板里仍写着 `{{...}}` 时，分析器报 `placeholder-syntax`：**明确失败，而不是把花括号当字面量渲染出来**。没有兼容模式。
- **不再推导任何东西。** 第二版的"占位符 + 循环标记 → 输出契约（字段名与结构）"已整体删除，随之删除的还有占位符文法、循环文法与它们的违规码。契约是固定的一份，见 FR-6。
- 分析必须走**真正的 HTML 解析器**：内容策略要遍历元素与属性，而 HTML 允许省略结束标签，字符串扫描会误判嵌套。解析用惰性的 `template` 元素，注释会原样保留——注释正是要读的说明。
- 分析在**保存前与点「运行」前**都在客户端跑，违例就地展示、不提交。宿主半跑在 Node 里没有 DOM，不承担模板分析。
- 违例通过**封闭码集合**表达，编辑器为每个码给一条本地化文案与一个位置。

### FR-5 执行

- 用户在卡片上点「运行」触发执行。
- **运行需要宿主提供子代理的运行入口之一。**（**第十五版更新：`0.2.0-rc.2` 从本版起支持运行。**）两条入口是 `startActivation`（`0.2.1-alpha.2` / beta 通道）和一次性 `start`（`0.2.0-rc.2` / 稳定通道）。`start` 接受与激活入口同样的 `prompt`/`parent`/`signal`/`outputSchema`/`agentOptions`（没有 `cwd`，没有 `delivery`——子代理从父继承会话头，结果以 caller 可等待的结构化值返回），这些都在真实宿主组合上分别测过。两条入口都没有的 harness 上**「运行」不可用**：工作台照常加载，卡片、模板与已存结果照常可读可改，只有运行控件被禁用，并在旁边写明两条入口各自需要的版本；绕过界面直接调运行路由得到的是 `run-unavailable` 的说明，而不是 `undefined is not a function`。改宿主版本是用户的事，插件不伪装其中任何一条存在。
- 执行在**独立子代理**中进行（决策 9），携带该 skill 的指令正文。
- 子代理的模型跟随当前活跃会话的默认模型（决策 12）。
- 一次执行只对应一次子代理运行；同一张卡不并发执行。
- 执行中提供**取消**。

### FR-6 结果校验

- 输出契约是**固定的一份**：`WORKBENCH_OUTPUT_SCHEMA = { type: 'object', properties: { html: { type: 'string' } }, required: ['html'], additionalProperties: true }`。每次运行都相同，没有按模板生成的契约，也没有字段清单。
- `html` 是唯一必需项，因此**结果里没有 `html` 就是不可用**：上游不会提交这样的捕获，宿主自动重试一次；仍失败 → 错误态 + 保留原始输出（决策 11）。
- 除"有没有 `html`"之外，结果**没有任何形状可以校验失败**。内容对不对不由契约负责（见 §9.4）。
- **"拿不到合规结果"是预期结果而非异常**：上游明确说明请求结构化输出不保证一定得到合规值，因此这条路径必须有产品表现。
- 子代理**自身报错**时，它的失败文本会被单独捕获并写进结果的诊断字段，供结果页的「运行详情」展示（见 FR-9 与 §8），不再是一次黑箱失败。
- 旧版本存下的结果（结构化值里没有 `html`）按**尚未运行**呈现，而不是渲染一个空框。

### FR-7 渲染与隔离

- 渲染分两步：**拼接**——`filledTemplate(template, html)` 把结果里的 `html` 放回模板的区间（纯字符串操作）；**清洗并挂载**——`renderTemplate(root, html)` 解析拼好的整份文档，移除禁止构造，再放进影子根。
- **骨架按构造逐字节不变**：子代理从不书写样式、标题与外壳，它们只存在于用户写的那份文档里，代码只替换区间那一段。因此两次运行之间骨架不可能漂移，**不需要漂移检查**。
- 清洗是**承重环节而非兜底**：片段来自一个读过模板、skill 以及 skill 工具输出的模型（决策 19）。
- **没有模板时不执行、不渲染结果**，卡片显示引导去配置模板的空态（决策 20）。
- 渲染发生在 **Shadow DOM** 中（决策 17），用户样式不外泄，也不受外部样式干扰。
- 应用主题 token 通过 CSS 自定义属性的继承穿过影子边界，无需手动桥接。

### FR-8 模板编辑器与实时预览

- **配置页**里提供一个 HTML 编辑器（决策 21）：整栏的配置页，不是浮层（§17、FR-24）。
- **就地校验**：随输入跑 `analyzeTemplate`，把每一条违例连同位置列在编辑器里；有违例时保存按钮不可用。
- **实时预览**：渲染**正在编辑的这份文档本身**，与正式渲染走**完全相同**的隔离与清洗路径。没有"占位样值"，也没有字段清单——没有运行就没有可填的区间，预览展示的是骨架。这样可以避免"预览好看、真跑起来不一样"。
- 保存后回到卡片，有模板才提供「运行」。

### FR-9 动作集

结果页提供：**运行 / 取消 / 重跑 / 重新生成（微调）/ 停止 / 运行详情**。卡片正面只有「配置」与整卡进入结果页（决策 3 的 P10 形态，见验收 16）。

- 「运行详情」是"诚实报错"的必要配套，不可省略：结束原因、开始时间、结构化值、原始输出与诊断都在里面，默认折叠。子代理**自身报错**时，宿主从事件总线捕获到的失败原因也会写进结果的诊断字段，由这块一并展示——没有它，每一次失败都只是一个 `stopReason: 'error'`。
- 「停止」是运行中那块主控件的位置（FR-44）：运行中它**取代**「重新生成」，而不是把后者禁用，因此中断长任务不必回到页面顶部。
- 「重跑」让用户无需改配置即可重新执行。
- **「运行」是会改状态的操作**（决策 13）：子代理持有完整工具权限，重跑不是幂等的。这一点必须在交互上可感知。

### FR-10 持久化与新鲜度

- 结构化结果、执行时间、所用 skill 一并落盘。
- 打开工作台**只读缓存，绝不触发模型调用**（决策 10）。
- 卡片显示上次执行时间；超过阈值时给出"已过期"提示，但不自动重跑。

### FR-11 降级态

各类降级各自独立、各自可操作（决策 `degraded_states`），详见 §8。

### FR-12 权限与审批

- 子代理继承当前活跃会话的**完整工具权限**（决策 13）。
- 同时**继承会话的审批流**：危险操作仍会停下询问。
- 卡片上**标注权限等级**，让用户知道自己按下去的是什么。

### FR-13 通用配置机制

技能卡不应该是特例。宿主提供通用机制（决策 5）：

- 卡片**声明**自己的配置字段；
- 宿主负责**校验 + 存储 + 下发**；
- 技能卡作为第一个使用者落地。

第一版字段类型可以收窄到"枚举选择 + 长文本"，但机制本身是真的。

## 6. HTML 模板规范

### 6.1 位置与归属

模板存在卡片配置里，**按 skill 分别保存**（决策 15）。skill 本身不携带模板，也不声明任何字段信息。模板是**一整份文档**，不是片段或片段集合——只有标明的那一段区间会随运行被替换。

### 6.2 区间标记

模板里用一对注释标出子代理要填的那一段：

```html
<!-- template-begin -->
<!-- template-end -->
```

- 标记内部的空白可有可无：`<!--template-begin-->` 与 `<!-- template-begin -->` 等价。
- **v1 只支持一对。** 缺失（`region-missing`）、未闭合（`region-unclosed`）、重复（`region-repeated`）、闭合标记出现在开启标记之前，全部拒绝。两个标记之间的那一段就是**区间**，是整份文档里唯一会被替换的部分。
- 模板里已经存在的那一对标记原样保留在拼好的文档里，注释不被删除。
- 仍写 `{{字段}}` 的模板报 `placeholder-syntax`：**明确失败，绝不把花括号当字面量渲染**。

### 6.3 注释即需求

**文档整体是规格，区间里的注释是说明。** 整份模板逐字发给子代理（从不重新序列化——那样会把注释删掉，而注释正是要读的东西），提示词要求它读区间里的注释、按注释填写、只回报那一段 HTML。

因此"要填什么"写在注释里，例如：

```html
<section>
  <h2>本次提交</h2>
  <!-- template-begin -->
  <!-- 每个提交一行：一列短 hash，一列提交说明。 -->
  <!-- template-end -->
</section>
```

几条纪律：

- 注释要说清**产出的形态**（每个条目一行、哪些内容、什么顺序），因为没有任何字段名或类型可以替代它。
- 骨架（样式、标题、外壳）不进区间：它由用户持有、逐字节不变，子代理改不到。
- 区间位置由标记界定，不靠 HTML 结构自定界，也不需要成对的元素闭合。

### 6.4 允许与禁止

| 项 | 允许 | 说明 |
| --- | --- | --- |
| HTML 标签 | **全部** | 决定"外观完全自由" |
| CSS | **全部**，含 `<style>` 块 | 作用域由 Shadow DOM 兜住，不会外泄 |
| `<script>` | **禁止** | 对"配置显示样式"毫无必要 |
| 事件属性 `on*` | **禁止** | 同上，且是代码执行入口 |
| `javascript:` 等危险 URL | **禁止** | 同上 |
| 外部图片 / 字体 / 外部 CSS | **禁止**（决策 18） | 卡片离线可用；不会变成追踪像素 |
| 子代理回填的片段 | **渲染前清洗** | 片段来自模型，是比模板更不可信的一侧（决策 19） |

被禁止的内容在保存模板时即被拒绝并指出位置，不做静默剥离——静默剥离会让用户以为样式生效了，但实际没有。**子代理回填的片段是另一回事**：它没有"保存"这一步，所以在渲染前统一清洗（见 FR-7 与[详细设计 · M3 隔离渲染](workbench-skill-card-detailed-design.md)）。其中 `<style>` 里出现 `@import` 或非片段 `url(...)` 时**整块移除**：只删掉那一条引用会留下一份只生效一半的样式表。

### 6.5 输出契约

契约只有一份，与模板无关：

```ts
export const WORKBENCH_OUTPUT_SCHEMA = {
  type: 'object',
  properties: { html: { type: 'string' } },
  required: ['html'],
  additionalProperties: true,
}
```

- **没有从模板推导出来的契约，也没有字段清单。** 第二版的"从模板反推契约"（`deriveTemplate` → `{ fields, schema, violations }`）已删除。
- 子代理唯一要交回的是 `html`：**它填好的那一段区间**，不是一组命名值，也不是描述。
- `required: ['html']` 意味着**没有 `html` 的结果不可用**：上游不会提交它，宿主据此重试一次（FR-6）。
- 整份文档随提示词放在 `<output_document>…</output_document>` 里发给子代理，并告知它：只填区间、只回报那一段、区间之外的内容不要复述或改动。
- 模板体积上限 `WORKBENCH_TEMPLATE_MAX_BYTES = 32 * 1024` 在**存储时**强制，所以提示词的最坏情况是有界的。

### 6.6 模板问题时的行为

| 情况 | 行为 |
| --- | --- |
| 用了被禁止的标签/属性/外链 | 保存前拒绝并指出位置 |
| 缺少区间标记 / 标记未闭合 / 标记重复 | 保存前拒绝并指出原因 |
| 仍写 `{{...}}` 占位符语法（旧模板） | 保存前拒绝，提示改用区间标记并在注释里写明要求 |
| 模板超体积上限（32 KiB） | 保存时拒绝 |
| 子代理回填里夹带禁止构造 | 渲染前清洗移除，不报错（模板本身没有被违反） |
| 结果里没有 `html` | 重试一次；仍失败 → 错误态 + 原始输出 |
| 旧结果（结构化值里没有 `html`） | 按"尚未运行"呈现，不渲染空框 |

## 7. 模板是前置条件（本节原为"无模板兜底推导"）

**本节在第二版修订中被整体替换过一次，第三版又把理由换掉了。** 原方案是"用户尚未写模板时，卡片按结果结构自动推导呈现"；第二版改成"没有模板就没有契约"，因为契约当时由模板反推。

第三版里**理由变了，结论没变**：契约不再由模板反推（它是固定的一份，见 6.5），但模板仍然是运行的前置条件——**没有模板就没有可交给子代理的规格，也没有可供拼回结果的骨架**。没有这两样，一次运行产出什么都不可能显示成用户要的样子。

因此：**没有模板就不能运行**（决策 20）。卡片此时显示引导用户去配置模板的空态，不猜测呈现方式，也不发起任何模型调用。

这带来一个明确的代价，必须承认：**用户必须自己写出这份文档，并在区间注释里说清"要填什么"。** 系统无法在首次运行前告诉他该产出什么形态——这不是可以靠"列出字段"缓解的问题，因为已经不存在字段这一层（决策 22）。缓解手段是把注释当成可核对的说明来写，并在结果不对时先回来改注释。

约束与边界（仍然适用）：

- 结构化结果的体积要有上限，建议与既有工作台布局契约保持同一量级（64 KiB）。
- 表格列数过多时横向滚动，不压缩到不可读。

## 8. 失败与降级矩阵

| 情况 | 卡片表现 | 用户可做的动作 |
| --- | --- | --- |
| 未配置 skill | 空态：提示去配置 | 打开「配置」选择 skill |
| 已配置 skill、未写模板 | 空态：提示先写模板才能运行；「运行」不可用 | 去写模板 |
| 已配置且已写模板、未运行 | 提示"尚未运行" | 运行 |
| 无活跃会话 | 空态：说明需要先有会话 | 跳去开会话 |
| skill 被删除或改名 | 标记失效，保留原选择供识别 | 重新选择 skill |
| 模板保存被拒（标记缺失/未闭合/重复、占位符语法、禁止构造、超体积） | 编辑器内就地报错并指出位置或原因 | 修正模板 |
| 执行失败（子代理报错） | 错误态 + 原因（诊断来自宿主事件总线，可在运行详情里查看） | 重跑 / 打开运行详情 |
| 结果里没有 `html`（重试后仍失败） | 错误态 | 打开运行详情 / 重跑 |
| 结果是旧格式（结构化值里没有 `html`） | 按"尚未运行"呈现，不显示空框 | 重新运行 |
| 结果过期 | 显示"已过期"与上次执行时间 | 重跑 |
| 执行中被取消 | 回到上一次结果或空态，并说明已取消 | 重新运行 |

设计原则：**每一种失败都要让用户能自己修好**，不允许出现"出错了但你不知道该干什么"或"卡片悄悄消失了"。

## 9. 风险与限制

### 9.1 权限是最高风险项（决策 13）

用户选择了继承完整工具权限。这条选择的能力收益明确（卡片能真正查仓库、跑测试），但它与"结果只读缓存"的印象存在张力，必须显式承认：

- skill 是**磁盘上的自然语言**，第三方 skill 根目录里已有现成内容；
- 完整权限意味着子代理能**写仓库、执行命令、发网络请求**；
- 真正的注入面是：skill 正文 + skill 在执行中读到的任何文件内容，都是不可信输入，而执行者持有写权限。

因此 FR-12 的三项配套（继承审批流、标注权限等级、运行是可改状态的操作）**不是可选项**，是这条决策的组成部分。

### 9.2 HTML 面已被四项约束封住

用户写的 HTML 是自伤面（自己写的东西），但它同时是**复制粘贴面**——模板会被从别处粘贴、将来会被分享导入，那时它就是第三方内容。因此本方案用四条约束把它封住，且这四条都不牺牲"外观自由"：

1. **Shadow DOM 隔离** —— 用户样式不外泄，不会出现"抄了一段表格样式结果整个应用白屏"；
2. **禁止脚本** —— 剥离代码执行路径，样式配置不会变成任意代码；
3. **禁止外链** —— 卡片不会变成追踪像素，也保证离线可用；
4. **片段清洗** —— 子代理回填的 HTML 在进 DOM 前被清洗（禁止元素与属性移除，外部 CSS 整块移除），而骨架与外壳始终由用户持有的那份文档提供，模型写不到它们（决策 19）。

第 4 条在第三版**变重了**：第二版里"值永远是纯文本"是最后一道保险，代价只是呈现略死板；现在进 DOM 的是一段模型产出的 HTML，所以清洗不再是纵深防御式的兜底，而是**承重环节**。这也是把分析器从"反推契约"收缩成"查区间 + 查禁止构造"之后，唯一一处必须逐次运行的检查。

已核实的背景：本应用的 Electron 安全开关均为正确设置（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`），注入脚本够不到 Node；但它与应用 Web 客户端同源，**能以内置客户端身份调用宿主 HTTP API**——而那个 API 背后是有文件与工具权限的宿主。这是"禁止脚本"这条不可协商的原因。

### 9.3 结果交付的只有一份 HTML，因此没有字段与类型

第三版删掉了字段这一层：子代理交回的是**填好的区间 HTML**，不是 `{字段: 值}`。随之消失的是第二版记录的"类型推不出来"问题——没有字段名，就没有字段类型可推。语义由两处共同约定：

- **skill 正文**约定它产出什么（"dirty 输出 是/否"、"体积写成人读的 1.2 GB"）；
- **区间注释**约定这段区间要怎么呈现（每条一行、哪些列、什么顺序）。

模板本身仍然**没有逻辑语法**：不能对内容做条件判断或数值运算，也没有表达式位置。这不是缺陷而是分工：**skill 正文与注释负责语义，模板负责外观，契约只负责"有没有 `html`"。**

### 9.4 注释写得不对不会被拦住

第二版在这里记录的是"字段名写错不会被拦住"。**字段名已经不存在了，但同一类限制换了个位置存在，而且更宽**：契约只有一个 `html` 字段，它只回答"有没有交回一段 HTML"，**不回答内容对不对**。

具体后果：区间里的注释写得含糊，或者与 skill 正文的约定不符，模型会按自己的理解填出一段**看起来合理实则无意义**的内容，而校验不会失败——因为契约这一层根本没有东西可以失败。文档里也没有任何可写的字段名可供"校验"。

这正是决策 22 存在的理由：把注释写成可核对的说明（产出形态、条数来源、顺序），并在结果不对时**先回来改注释**，而不是反复重跑。用户还能拿结果与「运行详情」里的原始输出对照，判断是模型没按 skill 执行，还是注释没说清楚。这条缓解措施不可省略，因为契约永远不会替他发现这件事。

### 9.5 单实例的张力（决策 3）

"一种卡只有一张"让架构清明，但意味着用户不能同时开三张技能卡看三件事。本方案的答案是决策 14：**技能卡负责长尾，专用卡负责高频且需要专用交互的场景**。如果实践中发现用户反复在配置页与结果页之间来回切换，那就是专用卡该出现的信号。

### 9.6 模板不受设计系统约束

用户模板可以有任意颜色和字号，因此它可能与应用的深浅色主题不一致、可能在切换主题时显得突兀。方案不做强制（那会牺牲外观自由），但有一条现成的缓解：**应用的主题 token 是 CSS 自定义属性，本来就继承穿过影子边界**，用户模板直接写 `var(--dsw-…)` 即可，不需要额外桥接。唯一要守的纪律是不要在 `:host` 上写 `all: initial`。

## 10. 与现有架构的关系

### 10.1 零上游改动

本方案**不需要修改 `deepseek-harness/` 子模块**。所有需要的设施都已存在：

| 需要的能力 | 既有设施 |
| --- | --- |
| 宿主读出 skill 指令正文 | `ctx.skills.get(name, { scope: agent })` 返回的 `content` |
| 执行并强制结构 | 子代理的 `outputSchema`（本次固定为 `{ html: string }`）+ `structured_output` 工具 |
| 拿到已校验结果 | 子代理结果里的结构化值 |
| **拿到子代理自身的失败原因** | 宿主事件总线 `agent/error`：子代理这条缝只留下 `stopReason: 'error'`，错误对象被丢掉，事件是唯一来源 |
| 结果落盘 | 复用工作台已有的 storage domain |
| 读盘通知 | 上游 skill 文件系统已有 watcher |

### 10.2 需要新增的东西

| 新增物 | 归属 |
| --- | --- |
| 子代理执行的宿主服务（读 skill、发起执行、收结果） | `dsh-workbench` Host 半 |
| 子代理失败捕获（`agent/error` → 结果的诊断字段） | `dsh-workbench` Host 半 |
| 模板分析（区间定位 + 内容策略）与保存前的违例清单 | `dsh-workbench` Client 半 |
| 骨架拼接与片段清洗（`filledTemplate` / `renderTemplate`） | `dsh-workbench` Client 半 |
| 结构化结果与模板的存储读取通道 | `dsh-workbench` Host 半（复用 storage domain + 私域同源路由先例） |
| 配置的声明、校验、下发机制 | `dsh-workbench` Host + Client |
| 模板编辑器与实时预览 | `dsh-workbench` Client |
| Shadow DOM 渲染器 | `dsh-workbench` Client |
| 技能卡本身 | `dsh-workbench` Client |

> **已废弃（第二版）：** "模板解析与契约反推"（Client 半）与"宿主侧对反推契约做二次校验"。契约现在是两端共享的一个常量，没有可反推、也没有需要二次校验的东西；宿主仍会对送来的契约做一次廉价的形状预检，因为这是进程边界。

### 10.3 与原决策的关系

概要设计中确定过"不做卡片元数据通道，slot 账本是卡片唯一来源"。第二版方案与它不冲突：技能卡不增删卡片实例，只配置已有卡片的内容。

> **已被 P10 推翻（详见[详细设计 · P10](workbench-skill-card-detailed-design.md)）：** 技能卡现在支持"用户自己加卡"——用户可以创建多张具名卡片，也可以把一张卡连同它的模板与结果一起删掉。落地方式是**注册表仍只登记卡片类型**（slot 账本表达"有哪些类型的卡"），**卡片实例改为存盘的用户数据**，网格是那份存储的投影。因此"slot 账本是卡片集合的唯一来源"这条只对**类型**成立；实例的来源是存储，`WorkbenchCardFact` 也就分成了"类型"与"实例"两层。这条修订随 P10 落地，不是待办。

| --- | --- |
| 成本 | 只有点「运行」/「重跑」才产生模型调用；打开工作台、切换面板、刷新界面都不花钱；卡片显示上次执行时间让成本可追溯 |
| 性能 | 打开工作台是纯读缓存路径，不得有网络或模型等待；模板分析与预览必须即时，不阻塞输入 |
| 并发 | 同一张卡不并发执行；多张卡的并发上限需要在实现时定一个明确值（建议串行或很小的上限），不做无限并发 |
| 可访问性 | 执行中、完成、失败三种状态对读屏可见；取消可键盘触达；**编辑器不困住键盘**（Tab 缩进必须配一个离开字段的出口）、每个标签用 `for`/`id` 与控件配对、破坏性操作的确认态经 `aria-live` 播报、**焦点环必须可见**；用户模板的无障碍质量由用户自己负责 |
| 国际化 | 卡片自身文案（含权限等级标注、各类空态与错误态）走 locale 字典；**用户模板内容与 skill 产出内容不翻译** |
| 数据体积 | 模板、结构化结果、原始输出的存储都要有上限，超限截断或拒绝并提示 |
| 安全 | 见 §9.1 与 §9.2 |

## 12. 技能卡按钮触发执行 ✅ 已实现并验收

> **状态：✅ 已实现并验收。** 本节是需求规格，现在**每一条都有对应的实现与包级测试**：FR-14～FR-23 落地在 `dsh-workbench` 的 M1–M8 里（模块与文件的对应见[技能卡按钮触发执行 · 详细设计](workbench-skill-card-actions-design.md)），验收标准 17～34 逐条由[附录 A.2](#a2-已实现并验收1734)里注明的 spec 覆盖，`corepack yarn workspace dsh-workbench check` 通过。
>
> 本节出现的"会 / 不会"仍然读作**规格约定**：判断一条东西是否存在于产品里，看的是源码与验收标准，不是这一节。

### 12.1 需求陈述

技能卡渲染出的模板区间里**可以有按钮**。用户点其中一个按钮，**先确认、再触发一次执行**；这次执行的目标由该按钮**声明**的目标决定。按钮的个数**跟着数据走**：子代理把多少行数据放进区间，就有多少个按钮。

**执行期间，这张卡自己的按钮不可点。**

这句话里有两个不同的东西，必须分开：**用户在模板里声明的目标**（`card "名称"` 或 `skill "名称"`），以及**模型在回填区间时写在按钮上的动作键**。前者是能力边界，后者只是从前者里挑一个。

> 以上是规格。它现在成立：点击走 `ShadowHtml` 的委托监听 → `readActionEvent` 解析键与载荷 → `resolveAction` 查声明与实体 → 就地确认面板 → 按目标类型执行（卡片目标跳转并运行，skill 目标在当前会话裸运行）。

### 12.2 术语

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 目标 | target | 一次按钮执行要触发的对象。只有两种：**卡片**（按名称）与 **skill**（按名称） |
| 动作键 | action key | 按钮携带的短标识；它**指向**一个声明好的目标，本身不描述目标。模型只能写键，不能写目标 |
| 动作声明 | action declaration | 用户写在模板里的声明块：`动作键: 目标类型 "目标名称"`。声明一次，多行按钮反复引用 |
| 整行数据 | payload | 触发那一行在回填区间里的**原始字段值**。它随确认面板**全文展示**，并进入被触发那次运行的提示词 |

### 12.3 目标类型

**下表描述已实现的行为。**

| 目标类型 | 用什么解析 | 点击后 | 结果落在哪 |
| --- | --- | --- | --- |
| **卡片** | 卡片**名称**（不是 id，见 12.4） | 跳到那张卡，并**立即让它运行一次** | **存在那张卡上**（与手动点「运行」同一条落盘路径） |
| **skill** | skill **名称** | 用**当前会话**起一次运行，**完全不携带模板文档** | **只有成功 / 失败**，什么都不持久化 |

两种目标共用同一套"确认 → 执行"外壳，差别只在上面这三个格子里。两种目标的运行都会把**整行数据**（§12.2）作为 `<row_data>` 带进提示词。

### 12.4 决策汇总（本功能）

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| B1 | 卡片目标的行为 | 跳转 + **立即运行**；结果存在那张卡上 | 一次点击会消耗一次模型调用，且发生在用户刚跳过去的那张卡上 |
| B2 | 卡片目标的解析键 | 卡片**名称**；重名 → 报错；找不到 → 报错并**列出候选卡片**。**不使用卡片 id** | 用户改一次卡片名，所有引用它的模板就失效了；这是**已接受的代价** |
| B3 | skill 目标的结果 | **不持久化**，纯瞬态；重新加载后就没了 | 同一个 skill 目标跑两次，只有最后一次的结果可见，且刷新即失 |
| B4 | skill 目标的输入 | **不带模板文档**：没有 `<output_document>`、不填区间、不要 `{html}` 契约 | 这次运行没有任何呈现结构可依托，输出只用于判定成败 |
| B5 | skill 目标显示什么 | **只有成功或失败**：不显示执行过程、不显示模型推理、不显示输出文本 | 用户无法从卡片上判断"为什么是这个结果"，只能看结果本身 |
| B6 | 成功与失败的判据 | 成功 = 子代理**正常结束**；失败 = `agent/error` **或**超时，且失败**要显示诊断信息** | 诊断取自既有的 `agent/error` 通道（FR-21），不新增失败来源 |
| B7 | 确认 | **每次点击都要确认**；没有"不再询问" | 高频点击的场景会显得啰嗦；这是为 B8 的展示义务付的代价 |
| B8 | 确认内容 | **目标类型与名称 / 将运行的 skill / 参数全文 / 运行所属会话**，且**参数必须全文展示** | 这是一条**安全要求**，不是偏好：整行数据是模型基于远端工具输出生成的，马上要进下一次运行的提示词 |
| B9 | 确认的形态 | **就地面板**，替换卡片的显示区域；**不是模态框** | 共享原语没有对话框（现有编辑器也是就地面板，原因相同） |
| B10 | 参数取什么 | 那一行的**原始字段值**，不是渲染后的文本 | 渲染文本已经丢掉了字段边界，拼出来的参数无法追溯 |
| B11 | 一个按钮几个目标 | **恰好一个** | 想触发两件事就放两个按钮 |
| B12 | 占用 | **本卡运行中** → 本卡按钮不可点；**别的卡正在运行**时被触发 → **立即报错**（不排队、不等待） | 并发上限仍是 `maxConcurrentRuns`（决策与 M7 一致）；用户点快了会看到错误而不是排队 |
| B13 | 重复触发 | 同一行**可以反复触发**；按钮**从不消耗** | 每点一次就是一次新的运行，成本可累积 |
| B14 | 动作属性 | **白名单**：只有本功能定义的 `data-dsh-*` 属性生效，其它"像动作"的属性**什么也不做** | 用户或模型写下别的属性时不会得到意外行为，但也不会得到提示 |

### 12.5 功能需求（FR-14～FR-23）

> **FR-14～FR-23 全部已落地。** 下面每条都写成"要做到什么"，而每一条现在都有实现与包级测试；它们与验收标准 17～34 一一对应，覆盖它们的 spec 见[附录 A.2](#a2-已实现并验收1734)。

#### FR-14 动作声明（模板侧）

- **声明与引用分开**是这一节的核心设计。用户在**模板里**声明目标，一次声明、多行引用；模型在**回填区间时**只能写**动作键**。
- 模板里携带一个声明块，形状是"动作键 : 目标类型 目标名称"：

  ```html
  <!-- dsh-actions
    提交: card "评审结果"
    归档: skill "git-commit"
  -->
  ```

  - 动作键是短标识，同一份模板内**不得重复**；重复即拒绝保存。
  - 目标类型只有 `card` 与 `skill` 两种；写别的类型即拒绝保存。
  - 目标名称是**非空**文本；空名称即拒绝保存。
  - 声明块本身**不渲染**（它是注释），也不进入区间。

- 用户在配置页写声明，与写模板是同一处、同一次保存。
- 声明是**模板的一部分**，因此按 skill 分别保存（决策 15），并随模板一起受体积上限约束。

#### FR-15 按钮与数据（区间侧）

- 子代理回填的区间里**可以有按钮**。每个按钮携带：
  1. 一个**动作键**（引用 FR-14 声明过的目标）；
  2. **那一行的原始字段值**（整行数据）。
- 按钮的**个数跟着数据走**：数据有几行就渲染几个按钮，由子代理在区间里产出。
- **一个按钮恰好一个目标**（B11）：按钮上没有"同时触发两个目标"的写法。
- 按钮只写**键与数据**，**不写目标类型与目标名称**——目标只能来自 FR-14 的声明。因此模型可以决定**哪一行用哪个已声明的目标**，但**永远无法凭空造出一个目标**。

**模型返回的样子。** 契约是 `{ html: string }`，`html` 里就是区间内容——**不含** `<!-- template-begin -->` / `<!-- template-end -->`，那对标记属于骨架，由代码保留：

```html
<tr>
  <td><span class="task-id">CP-2025-001</span></td>
  <td class="task-name">登录模块联调</td>
  <td><span class="status-badge status-active">进行中</span></td>
  <td>
    <button type="button"
            data-dsh-action="finish"
            data-dsh-row='{"task_number":"CP-2025-001","task_name":"登录模块联调","task_status":1}'>▶ 完成</button>
  </td>
</tr>
```

对照上例的两点：`data-dsh-action` 引用的是 FR-14 声明的**键**（不是 skill 名或卡片名）；`data-dsh-row` 里是**原始字段**（`task_status: 1`），不是同一行显示的中文（`进行中`）。

**引号转义。** `data-dsh-row` 用单引号包裹属性、JSON 内部用双引号，因此**字段值里出现的单引号必须转义为 `&#39;`**：

```html
data-dsh-row='{"task_name":"O'Reilly 重构"}'      ❌ 属性在此断开
data-dsh-row='{"task_name":"O&#39;Reilly 重构"}'   ✅ 转义后属性完整
```

属性一旦断开，读到的是**残损载荷**而不是完整数据。这会直接破坏 B8 的「参数全文展示」，而那条是本功能**唯一**的安全缓解。因此**载荷解析失败必须报错拒绝执行**，不能拿能读到的部分继续——部分载荷意味着确认面板展示的参数与实际执行的参数不是同一份。

**载荷体积上限。** 整行字段可能包含长文本，因此 `data-dsh-row` 必须受体积上限约束，且这个上限应当是**配置项**，与既有的几处上限同一套机制（模板 32 KiB、请求体上限、结果记录上限），不引入魔数。

**超限一律报错拒绝，不截断。** 理由同上：截断后的载荷会让确认面板展示的参数与实际执行的参数不是同一份，等于绕过 B8。因此这里的"超限"是**拒绝执行**，而不是"截断后继续"。

#### FR-16 点击与解析

- 绑定**必须是卡片容器上的事件委托**，**绝不能是逐按钮监听**：区间在**每次运行后都会被重新生成**，逐按钮绑定在重新生成后就会失效（验收标准 32）。
- 按钮在**影子根**里。`click` 是**组合事件**，会穿过影子边界，所以事件能到达卡片容器；但 `event.target` 会被**重定向到影子宿主**，因此真实按钮**必须从 `event.composedPath()` 里取**，不能读 `event.target`。
- 解析顺序：从 `composedPath()` 找到真实按钮 → 取动作键 → 在声明里查这个键 → 取目标。
- 找不到动作键对应声明时：**报错，不执行**（验收标准 19）。这是"声明与引用分开"的兜底：模型写错键不会变成一次误执行。

#### FR-17 目标存在性检查

- **卡片目标**：按**名称**解析。
  - 名称**重复** → 报错（B2）。
  - 名称**找不到** → 报错，并**列出候选卡片**（B2）。
  - **不使用卡片 id**；改名导致的失效是已接受的代价。
- **skill 目标**：按**名称**在**当前会话**的 skill 目录里解析；找不到 → 报错，并**列出已安装的 skill**。
- 两类检查都在**确认之前**完成：目标不存在就没有可确认的东西，也就不会走到执行。

#### FR-18 占用检查

- **本卡正在运行**：本卡的所有按钮**不可点**（不是"点了报错"，而是不可点）。
- **别的卡正在运行**：被触发时**立即报错**——不排队、不等待、不静默丢弃（B12）。
- 并发上限沿用 `maxConcurrentRuns`，本功能不新增第二条并发规则。

#### FR-19 用户确认

- **每次点击都打开确认**（B7），没有"不再询问"。
- 确认是**就地面板**，替换卡片的显示区域，**不是模态框**（B9）。
- 面板必须展示四项（B8）：
  1. **目标类型与名称**；
  2. **将运行的 skill**（卡片目标就是那张卡选的 skill）；
  3. **参数全文**——**必须全文**，不得截断、不得折叠、不得只显示摘要；
  4. **运行所属会话**。
- 面板提供**确认**与**取消**两个动作。取消**不产生任何副作用**（验收标准 25）。

#### FR-20 卡片目标执行

- 确认后：**跳到那张卡**（整栏切到它的结果页），并**立即让它运行一次**。
- 结果走**与手动点「运行」完全相同的那条路径**落在**那张卡**上：同一种存储记录、同一种时间戳、同一种"已过期"判定。
- 因此那张卡此前的结果被这一次覆盖，这不是缺陷，是"同一张卡的一次运行"。

#### FR-21 skill 目标执行

- 用**当前会话**起一次执行（会话选定规则沿用现有实现：`origin !== 'subagent'`、`blank !== true`，取 `updatedAt` 最新）。
- **完全不携带模板文档**（B4）：提示词里**没有** `<output_document>`，**不填区间**，**不使用** `{html}` 输出契约。
- **只显示成功或失败**（B5）：不显示执行过程、不显示模型推理、不显示输出文本。
- 判据（B6）：**成功** = 子代理**正常结束**；**失败** = `agent/error` 或**超时**，并且失败**要显示诊断信息**。
  - 诊断信息来自**既有的** `agent/error` 通道（宿主按子代理 id 归因到本次运行的 `diagnostic`），本功能**不新增**失败来源。
- **什么都不持久化**（B3）：不写结果、不写模板、不改卡片配置；**重新加载后卡片回到它自己的结果**（验收标准 28）。

#### FR-22 重复触发

- 同一行**可以反复触发**（B13）：按钮**从不消耗**，点第二次与第一次走完全相同的路径（包括再一次确认）。
- 重复触发**仍然受占用检查约束**（FR-18）：第一次还在跑时，本卡按钮不可点。

#### FR-23 动作属性白名单

- 只有本功能定义的 `data-dsh-*` 属性**生效**；其它任何"看起来像动作"的属性**什么也不做**（B14）。
- 白名单是**封闭**的：新增一个生效属性必须改这一节，而不是在模板里写出来就生效。

### 12.6 实现前必须知道的四个事实

这四条改变了做法，都是查证过的机制事实，先记在这里，免得实现时踩：

| 事实 | 为什么重要 |
| --- | --- |
| `data-*` 属性**不在清洗黑名单里** | 按钮可以携带动作声明而不被清洗掉（§6.4 的禁用清单管的是脚本、事件属性、危险 URL 与外链，不管 `data-*`）。**这是本功能能成立的前提** |
| `click` 是**组合事件**，会穿过影子边界；但 `event.target` **被重定向到影子宿主** | 事件委托能收到点击，但**必须从 `event.composedPath()` 取真实按钮**；读 `event.target` 会拿到宿主元素 |
| 区间**每次运行都会重新生成** | 绑定**必须**是卡片容器上的**事件委托**，逐按钮监听在重新生成后必然失效 |
| **`data-*` 可以携带动作声明，正好也是风险所在** | 整行数据是模型基于远端工具输出生成的，它**马上要进下一次运行的提示词**；这条"远端数据 → 参数 → 下一次运行"的路径是**本功能最大的风险**，B8 的"参数全文展示"就是它的唯一缓解——因此那条不是可选的偏好 |

### 12.7 风险

- **注入面变宽了一层。** 在按钮触发执行之前，进提示词的只有**用户自己写的模板**（§9.1、§9.2 的自伤面）；现在，**模型基于远端数据生成的一整行字段**也会作为 `<row_data>` 进提示词。缓解只有一条：**B8 的全文展示**——用户必须在按下确认之前，把将要进入运行的那段参数**完整看一遍**。截断、折叠、摘要都会让这条缓解失效，所以展示的那份与运行收到的那份必须逐字节相同（`tests/skill-card-row-data.spec.ts`）。
- **卡片名是夹具。** 引用按名称解析，所以一次改名会让模板里的引用失效（B2 已接受）。解析失败必须**报错并列出候选**，而不是猜一个最像的。
- **skill 目标没有可追溯的产物。** 结果不落盘（B3），卡片上只有成败（B5）。这是刻意的，代价是排障只能靠当时的屏幕与宿主日志。
- **点击成本可累积。** 每次点击都是一次模型调用（B7、B13），没有批量、没有"不再询问"。若实践中出现连点，先看的是确认面板是否足够清楚，而不是加一个跳过开关。

## 13. 明确不做

- **不做**模板里的逻辑语法（没有条件判断、循环与表达式位置；重复由子代理在区间里产出）。
- **不做**在卡片里编辑 SKILL.md。
- **不做**执行历史列表与导出（决策 `card_actions` 只到「运行详情」）。
- **不做**卡片级模型选择（决策 12）。
- **不做**定时或条件触发的自动执行（决策 10）。
- ~~**不做**用户自行增删卡片实例（决策 3）。~~ **已由 P10 推翻**：用户可以创建多张具名卡片（网格末尾的「创建卡片」磁贴，选类型即在建卡时起一个可改的默认名），也可以把一张卡连同它的模板与结果**物理删除**。
- **不做隐藏。** 这条不是"暂不做"而是**能力已移除**：卡片外壳只在卡片提供 `onRemove` 时画出 X，X 只表示删除；布局记录只剩排序一维，宿主也不再解析 `hidden`。旧记录里仍写着 `hidden: true` 的卡片按可见读回，不做迁移（验收标准 16）。
- ~~**不做**skill 参数传入。~~ **§12 部分改变这一条（已实现）**：skill 目标仍然**不接受用户填写的参数**，但会把**整行数据**（模型回填的原始字段值）作为 `<row_data>` 带进那次运行。这是"带一段数据"，不是"给 skill 传参数"；边界由实现守住：整行数据只来自回填区间，必须先经 §12 的确认面板全文展示，展示的那份与运行收到的那份逐字节相同（`tests/skill-card-row-data.spec.ts`）。
- **不做**模板的分享、导入、导出（模板按 skill 存在本地配置里）。
- **不做**除技能卡外的其它可配置卡片（决策 5 的机制要通用，但使用者只落地技能卡）。
- **不做**编辑器里的语法高亮与自动补全（行号栏与两处染色是唯一的视觉辅助，见 FR-25）。
- **不做**精确到字符的违例定位：五个内容策略码来自解析后的 DOM，没有源码区间，只能给该标签名首次出现的位置（FR-28）。
- **不做**删除确认的模态对话框：共享原语没有对话框原语，确认在页脚里就地完成（FR-34）。
- **不做**工作台页头的「刷新」按钮：它只重读排版顺序，没有可见效果，名字却许诺了更多。它的 locale 键保留，因为卡片外壳自己的刷新控件拿它当 `aria-label`（§17.5）。
- **不做**修改记录与「上一版」的持久化：两者都只在本次会话的内存里，重新加载即消失，回退也不写盘（§18.3 R4–R6、§18.6）。
- **不做**把手工编辑写进修改记录（§19）：那份记录记的是**用户提出的指令**，而一次手工编辑不是指令——结果记录上的 `editedAt` 与运行详情里的「手工编辑」一行才是它的痕迹。
- **不做**结果编辑器里的区间染色、动作声明构建器与骨架插入：这三样都是**文档级**的东西，而结果编辑器编辑的是一段区间片段，片段里没有区间标记，也声明不了任何动作（§19.3 E16）。
- **不做**结果编辑器的多步撤销：与微调共用「回到上一版」这一层，**一步**，用掉即消失（§19.3 E17）。
- **不做**运行详情里代码块的「复制」按钮：那段 `html` 是**程序的产物**——它会被原样拼回模板的区间，复制出来没有任何用处（要复制的对象是模板，那是编辑器的事）。给一段只读产物配一个复制键，是把调试区当成工作区（FR-37）。**注意**：手工编辑结果之后，结果页上的编辑器就是那段产物的编辑处，这一条仍然成立——不该做的只是"复制一份到别处"。

### 14.1 已实现并验收（1–16）

1. 用户选一个 skill、写一份带区间标记的 HTML 文档并保存后，点「运行」，卡片按模板渲染出结果（骨架 + 回填区间）。
2. 子代理**只回填区间**：区间之外的内容不被改动，骨架在多次运行之间**逐字节不变**。
3. 模板缺区间标记、标记未闭合、标记重复，或仍写 `{{字段}}` 占位符语法时，**保存前被拒并说明原因**。
4. 模板里写了 `<script>`、`on*` 事件属性、外部资源元素或外部 CSS 时，**保存被拒绝并指出位置**。
5. 用户样式**不会影响影子根之外**：模板里写全局选择器（如 `* { display: none }`）后，应用其余部分正常。
6. 子代理回填的片段里若夹带 `<script>`、`onerror=` 之类的构造，**渲染前被清除**，不会执行、不会加载。
7. 打开工作台**不产生任何模型调用**（可用网络/调用计数验证）。
8. 结果里没有 `html` 时，恰好重试一次；仍失败则显示错误态且「运行详情」可用。
9. 编辑器随输入就地列出违例并禁用保存，并实时预览正在编辑的文档；预览与正式渲染走同一条隔离与清洗路径。
10. 未写模板时**不能运行**，卡片给出可操作的引导，且不发起任何模型调用。
11. 各类降级态（无活跃会话、skill 失效、模板被拒、结果过期、旧结果无 `html` 等）各自给出可操作的指引，无一处是"通用错误"。
12. 子代理自身报错时，失败原因被捕获并写入结果的诊断字段，能在「运行详情」里看到，而不是只剩一个 `error`。
13. 执行中可取消，取消后卡片状态与文案正确。
14. 卡片上有权限等级标注；危险操作仍走会话的审批流。
15. 契约与结果的处理不修改 `deepseek-harness/` 子模块（`git status` 中子模块无改动）。
16. **卡片模型成立**：全新安装的工作台上只有「创建卡片」磁贴；点它**只选一个类型**就建卡（磁贴里不起名）；卡片正面只显示**卡片名称、skill 名称与「配置」**；点卡片本体整栏切到**该卡的结果页**，「运行」就在那一页；点「配置」整栏切到**该卡的配置页**（名称、skill、模板）；X 是**物理删除**，把卡片连同它的模板与结果一起删掉；**任何位置都不提供隐藏**（卡片正面、配置页与布局域都没有这条路径），旧记录里仍写着 `hidden` 的卡片按可见读回。

### 14.9 运行被钉在卡片目录上（93–101）

> **这一组接在第十三版那道门后面，但只有前六条是"实现了并被测试证明"的东西，99–101 不是。** 93–98 由 `tests/skill-card-runner.spec.ts` 里「the card agent that fences a run」那四个用例覆盖，跑在今天 `corepack yarn workspace dsh-workbench check`（**609 个测试 / 40 个 spec 文件 / 3 跳过**，exit 0）里。**99 是一条命名约束，100 与 101 是两条验证限制**——三条都不主张"已通过"，读法写在条目里，本节末尾再说一遍。

93. **运行挂在一个根在卡片目录的 agent 上。** 卡片有目录时，插件为它建一个 agent（`agents.create({ sessionId, meta: { cwd: 目录 } })`），并把它作为这次运行的 **`parent`**；seam 本身一行没改——提示词投递、`{html}` 捕获、那一次重试、取消与 `agent/error` 归因照旧是它的。**为什么这样就能限定**：文件沙箱的 `workspaceRoot` 取自 `session.header.cwd`，而子代理这条缝**把父的会话头复制给子**，所以父根在哪个目录，子就落在哪个目录；`startActivation` 的 `cwd` 只写子代理的"有效工作目录"、**不改会话头**，所以靠传 `cwd` 到不了沙箱根（三条出处见 §16）。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（`createdAgents[0].session.header.cwd` 就是卡片目录，第二次运行的 `request.parent` 仍带着那个目录）。**只证明到"父的会话头里是那个目录"为止**：`sandboxPolicy.resolve().workspaceRoot` 是进程外的事实，本包没有一条用例断言它——见第 100 条。
94. **每次运行有自己的卡片 agent；运行结算后它就退役。** 新建 agent 的会话在结算后被**归档并释放**，下一次运行重新建一个（新会话）。**不是优化取舍，是硬约束**：harness 的 `ArchivedSessionGate` 拒绝「已归档会话及其子代理后代」的每一个模型步，把它以 `blocked` 收口、对外报成 `refusal`——所以「归档之后继续复用」在这里根本行不通（2.0.30/2.0.31 真实踩过：第二次运行直接以 `refusal` 结束，一步都没跑）。同一张卡**运行中**仍然只用一个 agent，路径/模式的重建逻辑照旧服务于这次运行。
    <br>覆盖：同文件（第一次结算后 `disposedAgents` 含刚建那个 agent；第二次运行后 `createdAgents` 长度 2，且两个 id 不同；第二次运行的 `request.parent` 仍是根在卡片目录的 agent）。
95. **存的那条路径变了就拆掉旧的、按新目录重建。** 已存的路径与当前路径不一致时，旧 agent 先 `dispose`，再按新目录建一个新的；**不能就地改**——根在创建时固定，留着旧的等于把运行围在用户没有选择的目录里。（第十六版起每个结算过的运行都会换新 agent，所以这条真正的含义变成"绝不复用根不对的 agent"，重建逻辑仍在 `cardAgent()` 里为运行中的缓存服务。）
    <br>覆盖：同文件（目录从 `/repo` 改成 `/elsewhere` 之后：`createdAgents` 长度 2，新 agent 的根是 `/elsewhere`）。
96. **`dispose()` 释放仍在缓存里的卡片 agent。** 结算过的运行自己退役（第 94、97 条），所以 teardown 要收的是**没有结算就卸载**的那一类：一次还在飞的运行所用的 agent。runner 的 `dispose()` 在等全部运行收尾之后，逐个拆掉剩下的。
    <br>覆盖：`tests/skill-card-runner.spec.ts`「releases a card agent a run in flight still hangs from」——挂起中的运行，`runner.dispose()` 之后 `disposedAgents` 恰好等于刚建那个 agent 的 id。
97. **每次运行结算后归档那张卡的会话，并释放它的 agent。** 建一个已发布的 agent 也建了一个会话，而侧边栏列的是会话，所以结算之后插件调一次归档，让 `workbench-card-*` 不进默认列表。**归档是记账，不是删除**：会话仍可读；但**它不能再被复用**——归档会把整条血缘挡在模型步之外（第 94 条），所以同一个动作里把 agent 也 `dispose` 掉，下一次运行换新会话。**归档失败只 `warn`**：它绝不能把一次已经捕获的结果变成一次失败（`retireCardAgent()` 自己吞掉归档与释放两处的异常，位置在 `finish` 之后）。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（一次结算之后 `archivedSessions` 恰好等于刚建那个 agent 的 id，同时它是被释放的）。**"侧边栏里真的少了这一行"没有断言**：那是应用与宿主的行为，本包只证明调用了归档。**而这条调用在真实宿主上能不能落地，见第 99 条。**
98. **没写目录的卡片不建 agent，运行在它之前就被拒。** 没有工作目录时运行被拒（`workspace-missing`），**没有任何 activation，也没有任何 agent**。runner 里"没有目录就退回会话的 agent"那一步，是**用户到不了的状态**的兜底，不是一条行为；能断言的只有拒绝本身。
    <br>覆盖：同文件（`workspace-missing`；`createdAgents` 与 `activations` 都为空）。

### 14.10 每张卡自己的权限模式（102–108）

> **这一组是第十五版的映射，七条都是"实现了并被测试证明"的东西。** 但它们压在同一条从未被验证的围栏上（第 100、101 条）：模式只决定沙箱允许写到哪里，而那个根是第十四版造的那间没验过的房。第 108 条把这件事写在条目里，本节末尾再说一遍。

102. **卡片记录多一个 `permission` 字段，`skill-card-spec.ts` 在同一次改动里声明它。** 这是按"store 写入的每个字段都必须在 schema 里声明"这条约束加的**第四个字段**（前三个是 `name`、`model`、`workspace`）。丢掉它比丢别的三个更糟：卡片会以默认模式回来，用户特意收窄过的那张卡于是按更宽的模式跑，而页面上没有任何一处会说这件事。
    <br>覆盖：`tests/skill-card-spec.spec.ts`（带模式的整条往返、没有该字段的记录不会被凭空补上、不认识的模式被拒）。

103. **不写就是 `workspace-write`，是一个具体默认值，不是"跟随会话"。** `effectiveWorkbenchSandboxMode()` 是唯一一处把"缺席"变成模式的地方：配置页显示它、runner 应用它、agent 的缓存键用它。**后果是已有卡片变严**——升级上来的卡片读回来没有这个字段，于是按 `workspace-write` 跑，而不是按会话当时的模式；这是产品负责人的明确决定，不是迁移遗漏。
    <br>覆盖：`tests/skill-card-contract.spec.ts`（`undefined` 解析成 `workspace-write`、三个模式原样返回、别的值都不认）、`tests/skill-card-runner.spec.ts`（没写模式的卡片，`setMode` 收到 `workspace-write`）、`tests/SkillCardSettings.spec.tsx`（没有模式时选择器显示 `workspace-write`，不是空选项）。

104. **配置页「基本信息」的第三行是权限模式，标签与应用自己的权限选择器一致；选「完全权限」时就地说明工作目录不再限制写入。** 三个标签是「仅可查看 / 工作区内修改 / 完全权限」，与 `ui-permission-presets` 的产品文案同一套词——同一个模式在产品的两个地方叫两个名字，读起来就是两种权限。**`danger-full-access` 允许**，但代价写在选择它的那一格里。
    <br>覆盖：`tests/SkillCardSettings.spec.tsx`（三个选项的值与文案、默认选中 `workspace-write`、`danger-full-access` 时的 `data-permission-warning` 文案、选择后回调收到模式、契约外的值不写）。

105. **模式在创建卡片 agent 时应用一次。** 宿主窄接口多一项 `sandbox.setMode(sessionId, mode)`，`src/index.ts` 把它接到**真实 Session** 的 `append('sandbox/mode', { mode })`；子代理继承父的显式 override，所以这一次写入就是"这张卡的运行都按它跑"的全部机制。**一次，不是每次**：agent 被复用时不再追加事件，因为继承发生在每次启动，而模式已经在父的会话里了。首次运行、重跑、微调与模板按钮触发的运行都走同一个父，所以四种运行一起生效；手工编辑结果不跑模型，也没有沙箱。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（两次运行只有一次 `setMode`，且第二次运行的 `request.parent` 仍是那个 agent；以及把卡片记录投影成"这次运行读什么"的那个纯函数把 `permission` 一起带过去）。

106. **换模式不必重建一个还活着的 agent：每次运行的 agent 本来就只服务那一次运行。** 本插件**不去改一个活着的 agent 的模式**——旧 agent 先 `dispose`，新模式在新会话上建立。**而且一次会被拒绝的启动不会拆掉正在被运行使用的 agent**：重叠检查在解析 agent **之前**先跑一次，否则"运行中改模式再点运行"会把正在跑的子的父会话拆掉。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（`read-only` → `danger-full-access`：`disposedAgents` 1、`createdAgents` 2、新的 `setMode` 落在新 agent 上；什么都没变时仍是一个 agent；运行中改模式再点运行 → `run-in-progress`，且没有任何 dispose）。

107. **应用不了就拒绝，绝不回退。** `permission-unavailable` 进的是**封闭联合**，于是路由的 `STATUS_BY_CODE`（409）、客户端的 `LOCALIZED_CODES`、卡片的失败文案表都必须表态。拒绝时消息点名**卡片与模式**，建到一半的 agent 被 `dispose` 掉——它不会留在缓存里等下一次尝试，也没有任何一次运行在"模式没生效"的情况下发生。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（`permission-unavailable`；detail 含卡片 id、模式与原因；`activations` 为空；刚建的 agent 被 dispose；该卡没有 run 状态）、`tests/locales.spec.ts` + 三张 `Record<码, …>` 映射表（**"漏一个编译不过"是类型系统的事，没有运行时用例**）。

108. **`danger-full-access` 允许，但它不是隔离。** 选了它，runner 如常应用并放行，配置页说明代价。**工作目录只在 `read-only` 与 `workspace-write` 下限制写入；`danger-full-access` 下它不再限制**——但这句话还有一层前提：**限制本身**来自第十四版那条栅栏，而那条栅栏**没有被验证过**（第 100 条）、**也没有任何真实应用跑过**（第 101 条）。所以"这张卡被限制在它的目录里"这句话今天仍然不能说；能说的是**卡片把用户选的模式写进了它自己 agent 的会话**。
    <br>覆盖：`tests/skill-card-runner.spec.ts`（`danger-full-access` 的卡片照常跑完、`setMode` 收到该模式）；**边界那一半没有用例能证明它，它和第 100、101 条是同一件事。**

> **本组的已知限制（一条，写在这里不留给读者猜）。** 三种模式的**写入效果**没有被验证：`read-only` 相对最硬（宿主自己的写路径就拒绝），而 `workspace-write` 与 `danger-full-access` 的差别**完全取决于那条未被验证的沙箱根**。本组证到的是"插件把模式应用到了哪、应用几次、应用不了会怎样"，不是"写入被限制住了"。

### 17.1 需求陈述

用户在配置页里做三件事：**给卡片起名、选一个 skill、写整份 HTML 文档**，然后**看着它**决定改哪里。

这三件事的分量不一样。前两件是一次选择，第三件是一份**别人无法替他写的文档**：填什么写在区间注释里，外观写在骨架里，系统既不推导也不猜测（§7）。因此编辑器的职责不是"帮他写"，而是**让他写得下去**：

- 一份几十行的 HTML，**没有行号就找不到自己刚写的那一行**；
- 体积上限是宿主的硬限制，**写到一半才发现超了**是最坏的发现时机；
- Tab 在文本框里默认是"离开"，而写嵌套 HTML 的人需要的是"缩进"——给了一个就得给另一个的出口；
- 违例清单如果不能指到出错的那一处，它就只是一段让人重读全文的散文；
- 动作声明块是**唯一需要背语法**的地方，写错一个键的结果是"卡片看着正常、点了没反应"；
- 声明的目标可能**现在还不存在**（卡片可以后建、skill 可以后装），这不该拦住保存；
- 空文本框教不会任何人那两处语法。

配置页本身也是一份需求：它是**用户停留最久的一屏**，字段横跨整行、保存按钮被预览顶出视野、删除一次点击就生效——每一条都是"能用但难用"。

> **第七版在这里多写了一条，第九版把它推翻了。** 第七版把"标题带上叠三层"也算进这份清单，并因此把**面板标题**从卡片页上拿掉（只留卡片页自己的头部）。第九版把它装回来：真正叠三层的是"面板标题 → 卡片页头部再重复一遍卡片名与 skill → 字段标签"，问题在**卡片页头部那份重复且不可编辑的卡片名**，不在面板标题本身。今天面板标题在每个视图上都有，卡片页自己的头部在它下面（配置页那份仍然只有「返回」），见 FR-43 与决策 E12。

| --- | --- | --- |
| 行号栏 | gutter | 文本区左侧那条行号；每行一个元素，与文本区同步滚动 |
| 状态行 | status line | 文本区上方那一行事实：区间行号、声明条数、已用字节 / 上限 |
| 骨架 | skeleton | 空模板时可一键插入的起手文档：样式、空声明块、区间标记、区间内的注释说明与一行示例按钮 |
| 缺失目标 | missing target | 已被声明、但当前不存在的卡片或 skill；**告警不阻塞保存** |
| 声明构建器 | declaration builder | 选键 / 类型 / 目标、由编辑器代写声明行的面板 |
| 三段 | the three groups | 配置页的三个分组：基本信息 / 模板 / 预览 |

### 17.3 决策汇总（本功能）

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| E1 | 尺寸读数的单位 | **UTF-8 字节**，与宿主的上限同一单位 | 数字比"字数"大得多，中文尤其明显；但按字符计会把一份宿主必拒的文档说成"还放得下" |
| E2 | 何时提醒体积 | 超过预算 **85%** 时尺寸读数变警告色 | 85% 之前的数字不警告；阈值是提醒，不是限制（真正的限制在存储时） |
| E3 | Tab 的语义 | Tab **缩进两空格**、Shift+Tab 反缩进；**Escape 之后 Tab 才离开字段** | 想用 Tab 走出编辑区的人要多按一个键；不这么做的代价是困住键盘用户 |
| E4 | 违例的位置精度 | 文本扫描给**精确 `offset`**；五个内容策略码给**近似位置**（该标签名首次出现） | 同一标签出现多次时可能指到第一个；没有位置就不给按钮，不伪造位置 |
| E5 | 声明块怎么写入 | 已有块**按它本来的缩进整块重发**：条目深一级、结束分隔符与开头对齐 | 用户手调的块内空白会被规整；换来"每加一条不会漂一点" |
| E6 | 缺失目标 | **告警不阻塞保存** | 声明一个永远不存在的目标也能存盘，错误推迟到点击时才成为错误 |
| E7 | 删除的确认 | **两次按下**：第一次只问，第二次才删；取消与 Escape 都不删；**没有对话框** | 删除多一次点击；共享原语没有对话框，确认只能在页脚里就地完成 |
| E8 | 预览的标签怎么写 | 「**骨架预览，区间尚未填充**」 | 比「使用示例数据」长，但后者是假话：预览渲染的是真实骨架 + 空区间，本产品不提供示例值 |
| E9 | 并排还是切换 | **1100px**：之上并排且隐藏标签条，之下用标签选择、隐藏标题 | 断点是"两块可读的窗格不再放得下"的位置，不是设备判断；上下都只有一条实现路径 |
| E10 | 保存失败写在哪 | `role="alert"` 的失败行放在**粘性页脚内部** | 页脚高一点；换来"失败不会随内容滚出视野" |
| E11 | 位置报什么 | 状态行报**行号**，不报字符偏移 | 用户在自己的文档里数的是行；偏移只用于把光标放到位置（E4） |
| E12 | 面板标题还在不在卡片页上 | **在**：网格、结果页、配置页都在「工作台」+ 副标题之下，卡片页自己的头部在它下面（第九版，**推翻第七版**） | 卡片页顶部多一行标题；换来"这里仍是工作台"的连续感，以及内容需要的顶部留白。第七版拿掉它的理由是"三层标题带"，但叠三层的是卡片名被重复，不是面板标题（FR-43） |

### 17.4 功能需求（FR-24～FR-36、FR-43）

#### FR-24 编辑器的结构

- 编辑器在**配置页**里（FR-33），不在卡片体内、也不是浮层：它与正式渲染、结果页共用同一个整栏表面。
- 模板段内部自上而下：**状态行** → （缺失目标告警 / 声明构建器）→ **行号栏 + 文本区** → **违例清单**。
- 预览段是**自有边框表面**上的影子根渲染（FR-32 决定它与编辑并排还是互斥）。

#### FR-25 行号栏

- **一行一个元素**，不是拼成一整段的数字：染色只能落在属于它的那些行上，一整段文字做不到。
- **与文本区同步滚动**：固定不动的行号栏配一个可滚动的文本区，标出来的行号是错的。
- **两处染色且可区分**：区间（含两个标记行）用强调色并带强调色左边框；`dsh-actions` 块的行用更淡的一层。**两处重叠时区间胜**——声明写在区间里本身就是一条违例，而区间是读者必须先看到的事实。
- **点击行号选中该行**，焦点回到文本区。
- 行号栏对读屏是隐藏的（`aria-hidden`），每个行号不是 Tab 停靠点：它是文本区上的一个鼠标便利，不是一串新的键盘负担。

#### FR-26 状态行

- 一行给出三件事：`区间 42–58`、`动作声明 3 条`、`12,480 / 32,768 字节`；有未保存改动时追加 `· 有未保存的改动`。
- **行号，不是偏移**（E11）。
- **字节，不是字符**（E1）：宿主的上限是 UTF-8 字节，按字符计会把一份中文文档报告成"放得下"，而宿主会拒绝它。
- 超过预算 85% 时尺寸读数变警告色（E2）。
- **区间缺失时整行变警告**，并给一个「插入标记」：写入成对标记、光标落在两标记之间——模板缺了它就完全不能运行，与其让用户回忆注释语法，不如把唯一缺的东西写下去。

#### FR-27 键盘

- Tab **缩进两个空格**；Shift+Tab **反缩进**：
  - 裸光标时删除它**前面**的至多两个空格（`<p>  a` 把光标放在空格之后是常见形态）；
  - 选区跨行时把覆盖的**每一行**移动一级，块的相对形状不变。
- **Escape 之后 Tab 离开字段**（E3）：Tab 被编辑器占用的那一刻，不给出出口就等于把键盘用户关在里面。
- Ctrl/Cmd+S **保存**并**阻止浏览器自己的保存**；保存与按钮走同一个门（FR-30 的缺失目标不在门内）。

#### FR-28 违例清单与定位

- 每条违例带一个**可选** `offset`：
  - **精确**：文本扫描类（区间标记、占位符残留、声明块里的每一行），扫描时手里就有匹配的位置；
  - **近似**：五个内容策略码（`script`、`event-attribute`、`unsafe-url`、`external-element`、`external-css`）来自**解析后的 DOM**，没有源码区间，只能给"该标签名首次出现的位置"。
- **点击一条有位置的违例**：选中那一段并滚到它，焦点回到文本区。
- **没有位置的违例保持纯文本**：一个点了不动的按钮比一行字更糟。
- 违例的**文案与位置**照旧：一条本地化原因 + 一个能在自己文档里找到的位置。

#### FR-29 动作声明构建器

- 面板给三件选择：**动作键**（按 `WORKBENCH_ACTION_KEY_PATTERN` 校验，已被占用的键直接拒绝并说明）、**类型**（card / skill）、**目标**（卡片取自**已存卡片的标题**，skill 取自**人类可调用的 skill**）。
- 写入**已有**块：**整块按它本来的缩进重发**——条目深一级、结束分隔符与开头对齐，**块外内容一字不动**（E5）。
  - 只拼接字符会让块里留下的空行与多余缩进**每加一条就漂一点**；
  - 从标记而不是行首开始替换，会把旧的缩进留在新的标记前面，于是分隔符与它自己的条目不在同一层。
- 没有块时**新建一个**，位置在 `<!-- template-begin -->` 之前：区间每次运行会被整体重写，写进区间只能活一次。
- 面板关闭**只在写入之后**：一次被拒绝的插入不能看起来像成功。

#### FR-30 缺失目标告警

- 声明的目标不存在（卡片改名或删除、skill 未安装或不可被人类调用）时，在状态行下方以**违例样式**逐条列出。
- **永不阻塞保存**（E6）：卡片可以后建，skill 可以后装。
- **读不出来的东西不报缺失**：目录读失败、配置尚未读到时，不把"读不到"说成"不存在"。

#### FR-31 骨架插入

- 模板为空时提供「插入骨架」（模板非空时不提供，以免覆盖已写的内容）。
- 骨架是一份**完整文档**：`<style>`、**空的** `dsh-actions` 块、区间标记对；区间里是一段注释，说明要生成什么、给一行示例按钮、写明 `&#39;` 的转义规则。
- **文案本地化，标记与示例是字面量**：注释是给人读、给子代理执行的说明，标记是语法。
- 骨架**必须零违例**通过分析：一个打开就报错的起手样例比空框更糟。

#### FR-32 并排与切换

- **≥1100px**：编辑与预览**并排**，标签条隐藏。
- **<1100px**：**标签**选择显示哪一个，标题隐藏（标签已经说了窗格的名字）。
- 断点是"两块可读的窗格不再放得下"的位置（E9），不是设备判断。
- 测试只断言 CSS 所依据的状态（`data-pane` 与 `aria-selected`），不断言响应式结果：测试环境不计算媒体查询。

#### FR-33 配置页布局

- **卡片页自己的头部只有 `← 返回`**（这一页的头部；上面还有面板自己的「工作台」标题，见 FR-43）：卡片名称在它自己的字段里，在这一页的头部再重复一遍才会叠出三层标题带——**问题一直是那份重复且不可编辑的卡片名，不是面板标题**（E12）。
- **三段**：基本信息 / 模板 / 预览，用间距与细线分隔，**不做嵌套卡片**（卡片套卡片读起来是第二层框）。
- 两个字段（名称、skill）**同一行**，各约 340px：整行宽的输入框只是一行标签旁边的空白。
- 预览在自己的**带边框表面**上，标签写「骨架预览，区间尚未填充」（E8）——预览渲染真实骨架，本产品**不提供示例数据**。
- **粘性页脚**承载保存 / 关闭，最右是危险色的「删除卡片」：保存不能依赖"滚过一段可能任意高的预览"。
- **写入失败**以 `role="alert"` 渲染在**粘性页脚内部**（E10），不随内容滚出视野。
- **每个标签都用 `for`/`id` 与它的控件配对**；模板字段由自己的可访问名命名，而不是再加一个可见标签。

#### FR-34 两段式删除

- 第一次按下**只进入确认态**：`确认删除` / `取消`，并把"删除后无法撤销"**经 `aria-live="polite"` 播报**。
- 第二次按下（`确认删除`）才真正删除；`取消` 与 **Escape** 都回到未确认态且**不删除**。
- **没有对话框**（E7）：共享原语不提供对话框原语，确认就地完成。

#### FR-35 卡片正面：排序手柄

- 重新排序的手柄 ⇅ 是头部动作里**最后一个**控件：它是"卡片已经拥有的位置"的抓手，不是对卡片的动作。
- 手柄走**三级色**，并与其它图标按钮一样**只在悬浮 / 聚焦时显现**：一个常显的控件不是被弱化的控件。
- 手柄仍是键盘移动卡片的唯一入口（方向键移动、Escape 取消），因此"弱化"不能变成"消失"。

#### FR-36 持久化完整性

- 一次保存写入的**每个字段都必须能被下次加载读回**。卡片名称与 skill 存在同一条记录里，两者都要在存储 schema 里声明。
- 反例（已修）：store 写了 `name`，写入也成功了，但存储 schema 只声明了 `skill`，于是加载时名字被丢掉——重启后卡片退回 id，而 skill 名还在。这条现在有专门的包级测试（验收 48）。

#### FR-43 面板标题与卡片页头部（第九版，推翻第七版）

- **每个视图都带面板标题**：网格、某张卡的结果页、某张卡的配置页，都在「工作台」标题 + 副标题这一块之下。面板标题由页面（`WorkbenchPage`）渲染，不由卡片页渲染——卡片页是**这个面板的一个视图**，不是另一个去处。
- **卡片页自己的头部排在面板标题下面**，依次是：返回、卡片名（结果页有，配置页没有）、skill、运行控件。
- **配置页自己的头部仍然只有「返回」**：卡片名与 skill 在下面的字段里，在这一页的头部再写一遍才是那个"叠三层"的问题（FR-33、E12）。
- **这一条推翻第七版的决定，明说在此。** 第七版为了让卡片页不叠出三层标题带，把**面板标题**从卡片页上拿掉，只留卡片页头部；结果是点开一张卡就像离开了工作台，而且卡片页的内容从顶边开始、没有上方的留白。第九版把面板标题装回来，并第一次把"叠三层"归因到正确的地方：**重复的是卡片名，不是面板标题**。
- 代价：卡片页顶部多一行标题；收益是位置感与留白。这条取舍由 E12 记录。

### 18.1 需求陈述

结果页要回答三件事：

1. **结果是什么？** —— 模板渲染出的那份文档。
2. **这次运行到底跑了什么？** —— 调试信息：结束原因、起止时间、结构化值、原始输出、诊断。
3. **不对的话，我怎么把它改成对的？** —— 这是本节真正新增的部分。

前两件当时各有一个毛病：**调试区读不了**（`html` 被当成一段 JSON 字符串打印，真实换行变成字面的 `\n`，整段无法阅读；缺失的字段还占着一行说"没有输出"），以及**结果没有归属**（渲染出来的文档浮在页面上，没有任何东西说这是这张卡的内容、它从哪里开始）。

第三件是新的能力诉求：**改一次结果不等于重跑一次**。重跑要再花一次模型调用、再读一遍 skill 与工作区，而用户想说的往往只有一句"按时间倒序"。对话式微调就是这句话：**在结果下面写一句要求，让子代理只改这一处，其余照旧**。

**第九版在这一节上做了一批打磨**，都是"已经能用、但还难用"的地方：那句话原本写在一个**单行文本框**里，一句真实的要求（例如"只显示待启动的任务，按时间倒序，状态列改成中文"）会直接冲出可见宽度；说得长一点要滚、要按方向键找回开头。运行期间那个按钮是**禁用的「重新生成」**，而长任务的取消在页面顶部的头部——结果把页面撑高之后它滚出了视野。运行详情的折叠开关写着「原始输出」，可里面是结束原因、开始时间、结构化值和原始输出四行；代码块还带着模板区间的缩进，从四百多像素的地方才开始；结束原因是 `completed` 这种英文枚举混在中文标签里。修改记录则把时间推到整行最右，退一步的链接单独占一行，三样东西一个重量。这四件事分别落在 FR-41（编辑区）、FR-44（停止控制）、FR-37（运行详情）与 FR-42（记录）：**形状、中断、可读、层级**。

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 微调 | refine / refinement | 让子代理在**已有结果**的基础上按一句要求改一次，而不是从零再跑一次 |
| 修改要求 | instruction | 用户写下的那句话，原样进入提示词 |
| 上一版 | previous | 最近一次微调替换掉的那份结果 HTML，只留一份，用于回退一步 |
| 修改记录 | revision log | 本次会话里每条已生效的修改要求及其生效时间；头部行给出条数，最后一行说明它只在本次会话 |
| 结果表面 | result surface | 承载渲染文档的有边框表层：边界来自边框、圆角与内边距，里面就是文档本身（**没有标题行**，第十一版移除） |
| 运行详情 | run detail | 默认折叠的调试区：结束原因、起止时间、结构化值、原始输出、诊断；折叠开关写「运行详情」 |
| 编辑区 | composer | 写那句修改要求的**多行输入区**：与应用的聊天输入区同形，一到四行随内容长高，`Enter` 提交、`Shift+Enter` 换行 |
| 停止 | stop | 运行期间占据「重新生成」那个位置的控件：按下就中断这次运行，与页面头部的取消是同一个动作 |

### 18.3 决策汇总（本功能）

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| R1 | 微调与重跑的关系 | **微调是一种运行模式**（`refine`），与卡片运行共用输出契约、解析、清洗、拼接与落盘 | 请求里多两个字段；运行表里多一种输入形状 |
| R2 | 模板从哪来 | **仍来自卡片存盘的选择**，请求不带模板 | 改了模板要先保存才能微调（与重跑一致） |
| R3 | 输出契约 | **不变**：仍是 `{html}` | 微调不能返回"字段补丁"，只能整段重发区间 |
| R4 | 上一版留几份 | **一份**，回退一次即用完 | 想退两步做不到 |
| R5 | 修改记录与上一版存在哪 | **只在内存里**，从不落盘，重新加载即消失 | 换视图/刷新就丢；因此必须写在用户眼前（FR-42） |
| R6 | 回退是否写盘 | **不写**：回退只改变屏幕上显示的结果，存盘的仍是最新一次运行 | 刷新后又回到最新一版，这是 R5 的直接后果 |
| R7 | 失败时的处置 | 结果**保持不动**，失败报在**编辑区**下方（`role="alert"`），不另开对话框 | 失败原因出现在发起处，而不是页面顶部 |
| R8 | 调试区的默认状态 | **默认折叠** | 想看原始输出要点一下 |
| R9 | 编辑区长什么样 | **与应用的聊天输入区同形**，一到四行、随内容长高；`Enter` 提交、`Shift+Enter` 换行；组字中的 `Enter` 不提交 | 尺寸不是自己挑的：它抄自 `@deepseek-ai/dsh-client-ui-conversation` 的 `InputBar.module.css`，所以两处输入区的圆角、字号、行高、内边距是同一套数字（FR-41） |
| R10 | 运行期间那块主控件 | **变成「停止」**，不是禁用的「重新生成」 | 少了一个"看得见但按不动"的状态；换来长任务随时可中断，且中断就在用户正看的地方（FR-44） |
| R11 | 代码块的缩进 | **显示时去掉模板区间的公共缩进**，存盘的值一个字节不动 | 两个"同一段 HTML"的形态（屏幕上的、拼回模板的）必须靠一句注释说清，否则下一个人会以为去缩进是归一化（FR-37） |

### 18.4 功能需求（FR-37～FR-42、FR-44；其中 FR-38 已撤回）

#### FR-37 运行详情的可读性

- 折叠开关的文案是**「运行详情」**，因为它说明的是整块。它一度写作「原始输出」——那是块内四行里的一行，用它当开关的名字等于只描述了四分之一；`原始输出` 现在只留给它自己那一行，两个含义不共用一个键。
- 结构化值里的 `html` **按 HTML 原样呈现**：等宽、可滚动、不折行，换行就是换行。
- 代码块**去掉模板区间带来的公共缩进**（非空行的最长公共前导空白；空行不参与、也不留缩进；没有公共前缀时原样）。模型回填的是模板里那段区间的内容，于是每一行都继承了区间在模板里的缩进——一份缩进在表格深层的模板，其代码块从四百多像素的地方才开始。**这只影响显示**（R11）：存盘的仍是带缩进的原值，它要被原样拼回模板。
- **结束原因本地化**：`completed` / `error` / `aborted` 分别写作 `正常结束` / `出错` / `已中止`（中英各一份）。**不认识的值原样打印**——上游的结束原因是可合并扩展的联合类型，编一个"看起来合理"的标签会说出一件这次运行没做过的事。
- 其余字段仍是 JSON，且**值本身不重排**：这是这次运行的原始记录。
- **缺失的字段整行不出现**；没有内容时不再用一句"没有输出"占位。
- 详情**默认折叠**：它是调试信息，结果才是内容。
- **没有代码块的「复制」按钮**：那段 `html` 是程序的产物，复制它没有用途（§13）。

#### FR-38 状态行（已撤回）

- **这一条已撤回，结果页没有状态行。** 产品负责人判定它是噪音：第十一版把结果面上方那行 `✓ 已完成 · 14:28:36 · 用时 42s` 整行移除，也没有用别的东西替代。它曾规定：一行给出状态、开始时间与用时，用时由运行的 `startedAt` 与结果的 `executedAt` 得出、两端缺一就不出现，运行中保持每秒计时。
- **状态与时间去哪读**：仍然可读，只是不再有一行概述——结束原因与开始时间在「运行详情」里（FR-37），运行中的状态由正文那块提示（`skillCardRunningBody`）说明。
- **不要恢复它**：这是产品决定，不是回归。验收标准 52 同样已撤回、编号保留（§14.4）；`data-run-status` 这个钩子随那一行一起删掉了。

#### FR-39 结果表面

- 渲染的文档放在**有边框、圆角的表层**里。
- 表层**不改渲染文档自己的样式**：那是用户模板的内容，在影子根里；容器的边界靠**边框、圆角与内边距**，渲染文档自带的阴影与圆角因此落在内边距之内，不会压在边框上。
- 表层里**没有标题行**：那一行（「结果」标题加它下面那条细线）是第八版为了让容器的上边界读得出来而加的，第十一版按产品决定整行移除。边界于是只由边框与内边距承担。
- 权限说明（`skillCardPermission`）**降为页面最下方的小号三级脚注**，不重复、不放进表层。
- 结果表面与运行详情之间用**一条细线**分开。

#### FR-40 微调运行（契约）

- 运行模式新增第三种：`{ kind: 'refine'; instruction: string; previous: string }`。
- `instruction` 必须**去空白后非空**且有长度上限；`previous` 是一个字符串且有字节上限；不合法按既有错误体拒绝。
- 提示词依次给出 `<output_document>`（存盘模板）、`<previous_result>`（上一版 HTML 逐字）、`<revision_request>`（用户那句话逐字），再一句面向模型的说明：按请求改、只回区间内容、其余照旧。带行数据时照旧带 `<row_data>`。
- 运行结果**与卡片运行完全一样**：捕获 `{html}`、失败可重试一次、以 `saveResult` 落盘。

#### FR-41 微调交互

结果下方是一块编辑器：一个**多行编辑区**、一个「重新生成」按钮（运行期间这个位置是「停止」，见 FR-44），下面是「修改记录」。

**编辑区就是应用自己的聊天输入区**：它和会话里打字的那个框一样高、一样圆、一样的内边距与字号。这不是"设计上像"，而是**同一批数字**——它们从应用里读出来，不是挑出来的（R9）：

| 项 | 值 | 出处 |
| --- | --- | --- |
| `min-height` | `36px` | `@deepseek-ai/dsh-client-ui-conversation` 的 `InputBar.module.css`，`.input` |
| `padding` | `4px 8px 0 14px` | 同上，`.input`（占位符的 `inset` 与它对齐） |
| 圆角 | `--dsw-radius-panel`（`28px`） | 同文件 `.card`；令牌由安装的主题定义 |
| 字号 | `var(--dsh-content-font-size, 14px)` | 同文件 `.card`；用户设置的内容字号，缺省 14px |
| 行高 | `calc(24px + var(--dsh-content-font-delta, 0px))`（缺省 24px） | 同文件 `.card`；主题定义 `--dsh-content-font-delta` |

同一个来源还借来了**底色与描边**（`--dsw-specific-input-major`、`--dsw-elevation-soft` 加 `--dsw-elevation-stroke-color: var(--dsw-alias-border-l2)`）、字体（`--dsw-font-family`）、占位符颜色（`--dsw-alias-label-caption`）与禁用态的颜色和光标。

**一处刻意的不一致**：`padding` 的**下边**是 `4px`，不是聊天输入区的 `0`。聊天输入区的底部留白来自它下面那条工具栏行（`padding: 2px 8px 6px`），而这块编辑区到底就是自己的下边缘（描边是阴影、不占布局），用 `0` 会让第四行压在那条线上。**这是记录在案的偏差，不是抄漏**。

**长高**：一到四行，随内容长高；超过四行在框内滚动。实现是两条：`rows` 由内容里的换行数得出（1–4，量不到时的兜底），以及一次布局后的测量——把高度先置 `auto`、再写成 `scrollHeight`（所以折行的长句也会长高），上限由 CSS 的 `max-height` 封住（四行的行高 + 上下内边距，另留 2px 余量；框本身没有边框，描边是阴影）。**量不到高度时不塌**：`scrollHeight` 为 0（无布局环境、隐藏挂载）时保留 `rows` 的高度。

| 情形 | 行为 |
| --- | --- |
| 输入为空 | 「重新生成」不可按（空白也算空） |
| `Enter` | 提交（输入法正在组字时不提交：那一下是在确认候选词） |
| `Shift+Enter` | 换行，编辑区跟着长一行 |
| 运行中 | 结果表面显示忙碌态，编辑区不可用，那块主控件变成「停止」（FR-44） |
| 成功 | 结果就地替换；上一版保留；记录追加一条 |
| 失败 | 结果不变；失败显示在编辑区下方（`role="alert"`） |
| 微调过的结果再微调 | 允许 |
| 回到上一版 | 把上一版放回屏幕并清掉它（只一步） |

- 「重新生成」与编辑区之间留有**一小段间距**：紧贴在一起时，它禁用着的样子读起来像"坏了"，而不是"还没有写任何东西"。
- 发送之后清空编辑区，否则那句话留在框里读起来像"还没生效"。

#### FR-42 说清楚"只在本次会话"

- 修改记录与上一版**只在内存里**：重新加载即消失。这句话必须写在记录旁边，不能留给用户自己发现。
- 记录按"说的话 → 生效时间"排列，读起来是一段对话，而不是一张日志表：**每条自成一行**，那句话在前，时间**紧跟在它后面**（小一号的三级色），而不是被推到整行的最右端——推到边缘之后，时间和那句话成了两列，读起来像一张表。
- **整块有一个头部行**：左边是 `修改记录 · N 次`（一个计数，不是一句话），右边是「回到上一版」——它在头部，而不是列表下面单独占一行；**没有上一版时它不出现**（没有可退的东西）。
- **"只在本次会话"是整块的最后一行**（三级色），而且它的措辞要同时盖住**记录与回退**：消失的不只是这张清单，还有「回到上一版」能退回去的那一版。

#### FR-44 运行中的停止控制

- 一块运行占住这张卡时，编辑区旁边那块主控件**变成「停止」**：不是把「重新生成」禁用了事。
- 为什么：**长任务必须能在用户正看着的地方中断**。页面头部那个「取消」在结果把页面撑高之后会滚出视野，而用户此时正盯着结果与编辑区。
- 它调用的是**与头部同一个取消动作**，因此两条路径不会各自实现一套取消。
- **取消不是"没有发生"**：一次被取消的运行记为 `aborted`（运行详情里可见），微调路径把它当成失败处理——结果留在屏幕上，失败报在编辑区下方（R7）。这是既有的语义，本条不改它，只是让它在看得见的位置可用。

### 18.6 已知限制（写清楚，不留给读者猜）

- **回退不写盘**（R6）：刷新之后屏幕上又是最新一次运行的结果。这是 R5 的直接后果，不是缺陷。
- **重跑会清掉「上一版」**：一次重跑不是一次微调，它的"上一版"没有意义；修改记录保留——它记的是"问过什么"，不是"显示什么"。
- **样式类结果无法自动断言**：边框、圆角、细线、折叠动画、忙碌态的外观、以及**编辑区量出来的高度**都由 CSS 与浏览器渲染决定，jsdom 只能断言 DOM 结构与状态。编辑区这条尤其要说明：`rows` 可以断言（1 到 4），但真正的高度是布局后写进内联样式的一串像素，jsdom 里 `scrollHeight` 恒为 0，所以"它看起来有多高"没有自动化证据。附录 A.4 与 A.5 对每一条都标了这一句。
- **编辑区底部的 `4px` 与聊天输入区不同**（FR-41）：这是有理由的偏差（那块的下方留白来自工具栏行），但它确实不是"同一批数字"，所以写在这里而不是留在代码里。
- **停止与取消是同一个动作，但入口有两个**：头部与编辑区各一个。测试断言的是编辑区那个会调用取消，以及两者共用同一个 `actions.cancel`（源码事实）；"两个入口永远同步"不是独立断言出来的东西。
- **代码块去缩进只发生在显示层**（R11）：屏幕上与拼回模板的是同一段 HTML 的两个形态，靠测试钉住"存盘值没被改写"，而不是靠在两处各写一遍格式化。
- **微调不校验返回内容**：契约只有 `html`，模型改错地方不会被拦下——与 §9.3、§9.4 是同一类限制。
- **面板标题在卡片页上没有 DOM 断言**（FR-43）：`WorkbenchPage.spec.tsx` 的每个用例都停在网格视图，要覆盖卡片页得先加一个打开卡片的用例，本版没有加（源码与测试在本轮冻结）。
- **结果编辑器里"行号与行对齐"没有被断言**（§19）：行号栏与文本区共用 `font-family: monospace`、`font-size: 12px`、`line-height: 18px` 与相同的垂直内边距，但 jsdom 不排版，能断言的只有"每行一个元素、数量与行数一致、点行号能选中该行"。对齐与否只能人工看。
- **结果编辑器没有打开/关闭动画**：它是**就地切换**（同一块结果表面的内容槽从渲染文档换成编辑器），不是浮层，因此没有可断言的过渡——这一点与"折叠动画不可测"不同，是**本来就没有**。
- **编辑器里显示的是存盘的那个片段，运行详情里显示的是去缩进后的投影**（§19.3 E18）：两处是同一段 HTML 的两个形态，编辑器必须拿着**原值**去保存（它要被原样拼回模板）。同一次保存前后比对两处文本时，缩进差异是设计，不是缺陷。

### 19.1 需求陈述

结果页已经能**看**结果、能**说一句话让子代理改**，但改不动**它自己看得见的那一行**。于是有三件具体的事做不了：

- 模型回填的一个数字错了、一个单位漏了、一行多余的空行——要修它必须再付一次模型调用，而这次调用还可能顺手改掉别的行；
- 页面上的**渲染文档**（模板 + 片段）看起来可以直接改，实际不能：那是影子根里的成品，改它没有任何东西会记住；
- 卡片的结果既然是"这张卡现在显示的东西"，它就应该像模板一样**可以被人写**：模板是人写的，片段是模型写的，而人应该能改模型写的那一半。

所以这一节要的东西只有一句：**让用户就地把结果里那段区间 HTML 改成对的，保存后它就是这张卡的结果。**

三个边界同时成立：

1. **只改片段，不改模板。** 模板是文档（`template` 表，按 card+skill 存），片段是结果（`result` 表，按 card 存）。手改结果不能变成改模板——那会让"下次运行"用一份被人改过的骨架。
2. **不伪造一次运行。** 结果是"哪一次运行、用什么 skill、为什么结束"的记录。手工编辑只换了其中的 HTML，它没有跑过任何东西，所以不能刷新成一次新的运行，也不能改掉 skill 与结束原因。
3. **改完要能退。** 手滑改坏了要能回退一步——用既有的「回到上一版」，而不是再造一套撤销。

### 19.2 术语

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 结果片段 | region fragment | 结果里那段区间 HTML（`stored.result.structured.html`）。它是**结果**，不是模板 |
| 结果编辑器 | result editor | 结果表面里就地打开的编辑器：等宽、逐行行号、与模板编辑器同一套键盘 |
| 手工编辑 | hand edit | 用户亲手替换结果片段这一次写；与一次运行、一次微调都不是同一件事 |
| 手工编辑时间 | editedAt | 记录上的一行时间戳：这份结果**被人**改过。缺席表示每个字节都来自一次运行 |
| 内容策略 | content policy | 渲染器会静默剥掉的五类构造：`script`、事件属性、危险 URL、外链元素、外部 CSS |

### 19.3 决策汇总（本功能）

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| E13 | 编辑什么 | **只有区间片段**（`structured.html`）；模板与结构化值里的其余字段都不动 | 想改外观要回配置页改模板（那是另一件事）；换来"结果编辑器不会悄悄改掉下次运行的骨架" |
| E14 | 存到哪、怎么存 | **覆盖这张卡的结果记录**：保留 `skill`、`stopReason`、原始输出、诊断，只换 `structured.html`，刷新 `executedAt`，并写 `editedAt` | 下一次运行会覆盖这次编辑（这是"运行一张卡"的既有语义，已接受）；换来记录仍然只有一条、没有并行版本 |
| E15 | 校验放在哪 | **内容策略 + 空 + 体积**都在编辑器里拒绝并说明；**空与体积**在路由与存储边界**再拒一次**；内容策略**不搬到宿主** | 宿主不重写用户的 HTML，它是存盘边界而不是编辑器：绕过编辑器的调用（今天的客户端里没有第二条路径）不会被内容策略拦下，这是已接受的限制（§19.5） |
| E16 | 编辑器长什么样 | 与模板编辑器**同一套键盘与外观**（等宽、逐行行号、Tab/Shift+Tab、Escape 后 Tab 离开、Ctrl/Cmd+S）；**没有**区间染色、动作声明构建器、骨架插入 | 少三样"文档级"的帮助，因为片段里没有区间标记、也不能声明动作 |
| E17 | 回退 | 复用**已有的**「回到上一版」：保存把编辑前那份记录放进 `previous`，回退是**一步**、只在内存里、用掉即消失、**不写盘** | 与微调的回退共用同一层；换来"两套撤销机制"不会各自漂移 |
| E18 | 编辑器里显示哪个形态 | **存盘的原值**（带模板区间的缩进），运行详情的代码块仍是**去缩进后的投影** | 同一段 HTML 在屏幕上有两个形态；合并它们就会在保存时把原值改掉（§18.3 R11） |

### 19.4 功能需求（FR-45）

#### FR-45 手工编辑结果

**(a) 入口。** 结果页头部、**「运行」控件的左边**，一个**次级**「编辑」控件。它只在**有结果**、且**没有运行占住这张卡**时出现（含 skill 目标的裸运行）。编辑器打开期间它消失，「运行」不可按——一次运行会替换掉草稿所依据的那份结果，而这是没有确认的破坏。

**(b) 编辑对象。** 只编辑 `stored.result.structured.html`。**从不从 DOM 读**：页面上的那份是"模板拼上片段"之后的成品，它的文本不是能把片段拼回模板的那个值。字段初值逐字等于记录里的片段。

**(c) 编辑器。** 等宽、**每行一个行号**、行号拦不是 Tab 停靠点、点行号选中该行；**Tab 缩进两空格、Shift+Tab 反缩进**（裸光标删它前面的至多两空格，跨行选区整块移动一级）；**Escape 之后 Tab 离开字段**；**Ctrl/Cmd+S 保存**并阻止浏览器自己的保存，保存与按钮走**同一个门**。状态行一行给出**已用字节 / `WORKBENCH_RESULT_MAX_BYTES`**，有未保存改动时追加标记。**没有**区间染色、动作声明构建器、骨架插入——片段里没有这些东西。

**(d) 拒绝保存的三种情形。**

| 情形 | 为什么拒绝 | 用户看到什么 |
| --- | --- | --- |
| 五个内容策略构造 | 渲染器会**静默剥掉**它们，存进去读起来就是"存了却没生效" | 逐条"本地化原因 · 位置"，有位置的还能点过去；保存不可按 |
| 空内容（含全空白） | 空区间渲染出来像一张坏卡 | 一句"结果为空"，并指出这张卡**可以再运行一次** |
| 超过 `WORKBENCH_RESULT_MAX_BYTES` | **拒绝，绝不截断**：截断就是存一份、显示另一份 | 读数变警告色 + 一句"多少字节 / 上限多少，未保存"；字段里的内容保持完整 |

**(e) 保存。** 把编辑后的 HTML 作为这张卡的结果写下去：**保留**记录的 `skill`、`stopReason`、原始输出与诊断，**替换** `structured.html`（结构化值里的其余字段一并保留），**刷新** `executedAt`，**写入** `editedAt`（与 `executedAt` 同一时刻）。宿主把**新记录连同新 revision** 一起返回，页面据此更新并回到渲染视图，**不再读一遍**配置。下一次运行覆盖这次编辑。

**(f) 取消。** 不写任何东西（不写存储、不发起运行、不改卡片状态），视图原样返回。

**(g) 溯源。** 结果记录新增 `editedAt?: number`，**并在存储 schema 里声明**（§17.5 第 1 条）。运行详情里多一行「手工编辑」+ 该时刻；没有编辑过的结果**没有这一行**。它**刻意不是**一条修改记录：那份记录记的是用户提出的指令，手工编辑不是指令。

**(h) 回退。** 保存把编辑前那份结果放进 `previous`，「回到上一版」把它放回屏幕（一步、用掉即消失、不写盘）。修改记录仍是 0 条——它记的是"问过什么"，不是"显示什么"。

**(i) 线。** 一条**独立**的结果写操作：`PUT /api/workbench/skill-card/result`，体是 `{ cardId, html }`。不复用运行路由——手工编辑不是一次运行，它没有阶段可轮询，也不该让运行的前置条件替一个不跑任何东西的操作作答。校验 `cardId`（命名空间 slug）与 `html`（字符串、在字节预算内），回 `{ apiVersion, revision, result }`。

### 19.5 本节的验收标准与已知限制

见 §14 中**验收标准 61～70**（**已实现并验收**），逐条覆盖见[附录 A.6](#a6-已实现并验收6170)。

- **内容策略只在编辑器里拦**（E15）：宿主存盘时不重写用户的 HTML，所以一个绕过编辑器的调用可以把 `script` 存进结果——渲染器仍会在渲染时剥掉它，结果是"看得到不该有的东西没生效"，而不是被执行。今天的客户端没有第二条写结果的路径；这条限制写在这里，是为了它以后也不会被误认为"宿主会拦"。
- **行号与行的对齐、以及编辑器的视觉密度**由 CSS 决定，jsdom 不排版，只有"每行一个元素、数量对、点行号能选中"是可断言的（§18.6）。
- **就地切换没有动画**：结果表面的内容槽从渲染文档换成编辑器，是同一块 DOM 的重渲染，不是浮层（本产品没有对话框原语）。
- **编辑器显示原值、运行详情显示去缩进的投影**（E18）：两处文本的缩进不同是设计，不是缺陷。
