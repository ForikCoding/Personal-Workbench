# 工作台工作流卡片需求方案

[工作台概要设计](workbench-design.md)确定了卡片式工作台的位置、展示与存储归属，[工作台卡片需求方案](workbench-card-requirements.md)把「技能卡」从需求落到实现并逐批验收（108 条验收标准），[工作台技能卡详细设计](workbench-skill-card-detailed-design.md)与[技能卡按钮触发执行 · 详细设计](workbench-skill-card-actions-design.md)给出实现级拆解。本文处理下一层诉求：**在技能卡之外新增第二类卡片「工作流卡片」，把工作台上已有的技能卡串成可执行的工作流，并让技能卡能够触发工作流卡**。

本文是需求方案，不是实现设计。它只回答"要什么、为什么、什么算做完了"；实现级拆分留给后续的详细设计续篇，与既有工作台文档的分工保持一致。

> **修订说明。** 本文初版，验收标准使用独立编号 **WF-1～WF-N**（与[工作台卡片需求方案](workbench-card-requirements.md)的 1～108 不共用编号，避免两文交叉引用时歧义）。
>
> - **第二版**：需求沟通第四轮确认初版全部 6 个待确认项（§12）——单卡并发上限 **3**、节点卡运行**互斥**（运行中不可被手动运行/被其他工作流引用，推翻初版建议的"默认允许"）、历史保留 **50 条**、节点**拖拽排序**、触发空节点列表**确认面板即不可运行**、确认面板**展示节点数与名称列表**。对应新增决策 **W16–W21**，更新 FR-W2 / W4 / W8 / W11 / W13 与 §4 / §6 / §7 / §10，并新增验收标准 **WF-26～WF-30**。

## 1. 需求陈述

一句话：

> 工作台上新增第二类卡片 **工作流卡片**。用户在它的配置页里，把工作台上**已有的技能卡**依次选成**节点**，组成一条**顺序工作流**。点「运行」，宿主按节点顺序逐个启动对应技能卡的运行：每个节点复用那张技能卡自己的模型、工作目录与权限模式，前一个节点结算后才启动下一个；运行到非首节点时，宿主把**上一个节点的结果**（HTML 片段）作为只读上下文附进该节点的提示词。任一节点失败，整个工作流**立即停止**。工作流独立保存每次运行的记录（逐节点状态 + 最终输出 + 运行历史）。同时，技能卡通过既有的 `dsh-actions` 动作机制**新增一种目标类型 `workflow`**：模板里的按钮可以点名一张工作流卡，点击后在**后台启动**一次该工作流的运行，并把按钮所在行的数据作为首个节点的输入。

它能解决的原问题是：**技能卡是一张卡、一次运行，而真实工作往往是"先 A 后 B、B 用 A 的结果"**。单个技能卡把 skill 和模板钉在一起，只能表达一步；用户想要的是把已经配置好的技能卡按顺序接起来，让一个流程在多张卡之间流动。

**典型场景（用户在需求沟通中给出的示例）：**

- 「需求设计卡片」先跑，产出**需求详细设计文档**（一段 HTML）；
- 「详细设计卡片」后跑，把上一张卡产出**作为输入**，在此基础上产出下一层设计；
- 后续可以继续接「编码说明卡」「测试要点卡」等任意已有技能卡。

上游卡的结果**既可能是一段数据，也可能是整份设计文档**——都是技能卡固定的 `{ html }` 输出，所以 v1 的传递载体统一为 **HTML 片段**。

## 2. 术语

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 工作流卡片 | workflow card | 本方案的新卡片类型：由用户创建的、把若干技能卡串成顺序工作流的一张工作台卡 |
| 节点 | node | 工作流里的一个步骤：**引用一张工作台上已有的技能卡**；一个工作流由 1..N 个节点按顺序组成 |
| 节点引用 | node reference | 节点保存的不是 skill/模板，而是被引用技能卡的**卡 id**；运行时就是"让那张卡跑一次" |
| 提示词级注入 | prompt-level injection | 节点间传递的实现方式：宿主把上一节点的结果 HTML 作为**只读上下文**附进下一节点运行的提示词；不改模板、不需要新语法 |
| 行数据 | row data | 技能卡按钮 `data-dsh-row` 携带的整行原始字段 JSON；触发工作流时它成为首节点的输入上下文 |
| 运行实例 | run instance | 一次工作流运行；同一张工作流卡**允许多个运行实例并发**，各自独立记录 |
| 最终输出 | final output | 一次运行的最后一个节点产出的结果 HTML；它是运行记录里唯一保存的节点内容 |
| 运行历史 | run history | 一张工作流卡名下按时间倒序可翻看的所有运行实例记录 |

## 3. 决策汇总（本方案）

以下决策均已通过与需求提出人的逐轮确认，构成方案的约束面。**「代价」一栏是接受该选择时同时接受的东西，不是待办。**

| # | 决策点 | 选择 | 代价 / 影响 |
| --- | --- | --- | --- |
| W1 | 执行模型 | **宿主串行编排**：每个节点 = 被引用技能卡独立跑一次（完全复用现有技能卡运行链路与每卡配置），前一个结算后再启动下一个 | 无并行；总时长 = 各节点之和；单节点可取消 |
| W2 | 节点定义 | **引用工作台上已有的技能卡实例**（按卡 id），不内联 skill/模板 | 节点随被引用卡变化；被引用卡被删/未配置时工作流不可运行 |
| W3 | 节点间数据传递 | **传递**：非首节点运行时，宿主把上一个节点的结果 HTML 注入其提示词 | 需要明确注入机制（见 W7）；不能相邻节点也共享全部上游时需重新设计 |
| W4 | 失败策略 | **任一节点失败 → 整个工作流立即停止**，后续节点不执行；失败节点标红 | 一次失败即放弃后续节点 |
| W5 | 技能卡触发工作流 | **后台运行、不跳转**：技能卡按钮触发后不做界面跳转，运行状态体现在工作流卡的正面与结果页 | 用户需要自己打开工作流卡才能看到进度 |
| W6 | 嵌套与环 | **v1 不做工作流嵌套**；节点只能引用技能卡（不能引用工作流卡）；定义层面因此不存在环 | 无法复用已有工作流作为步骤 |
| W7 | 注入机制 | **提示词级注入，不改模板**：宿主在节点提示词里追加一段「上一节点输出」（只读上下文，带边界与体积上限）；不引入模板新语法 | 注入内容对模型是上下文而非强制字段；模型可能忽略或误用——与"模板即规格"的哲学存在张力（见 §10） |
| W8 | 工作流卡配置 | **仅名称 + 节点列表**（增 / 删 / 排序）；模型、工作目录、权限模式**全部沿用节点自己的技能卡**，工作流卡自身没有这些字段 | 工作流卡无法覆盖单个节点的执行参数 |
| W9 | 失效节点 | **启动前校验**：所有节点引用的技能卡存在且可运行（已选 skill、有模板、有工作目录），任一不合格则整次运行被拒绝并点名节点，不启动 | 不能部分运行 |
| W10 | 并发 | **同一张工作流卡允许多个运行实例并发**（**单卡上限 3**，见 W16），互不干扰，各自入历史 | 并发 = 模型调用成本叠加；上限只在单卡内生效，全局无配额（见 §10） |
| W11 | 结果归属 | **工作流独立存结果**：每次运行的节点结果**不写回**被引用的技能卡 | 从技能卡结果页看不到"经工作流跑出的最新结果"；两处结果可能不同（见 §10） |
| W12 | 传递载体 | **v1 只传 HTML 片段**（沿用技能卡固定契约 `{ html }`）；"一段数据"表达为 HTML 表格/文本 | 下游拿到的是 HTML 而非结构化字段 |
| W13 | 结果记录内容 | 每次运行记录 = **逐节点状态（状态/耗时/成败） + 最终节点输出 HTML + 运行历史** | 中间节点的输出只用于注入、不落盘，运行结束后不可回看（见 §10） |
| W14 | 触发参数 | **带行数据触发**：技能卡按钮触发时，把 `data-dsh-row` 整行数据作为**首节点**的输入上下文（注入首节点提示词） | 触发行为依赖按钮所在的模板行，需要确认面板展示载荷 |
| W15 | 触发并发语义 | 技能卡触发工作流**不因已有实例在运行而被拒**，但仍受**单卡并发上限 3**（W16）约束，达到上限被拒 | 与既有"卡片目标运行中立即报错"的占用规则不同，需要在动作层分目标类型区别对待 |
| W16 | 单卡并发上限 | **默认 3 个并发实例**（可配置，沿用 `Config` 预算机制），达到上限后直接「运行」与技能卡触发都被拒（`run-in-progress`，消息注明已有实例数） | 上限以内并发照常叠加成本 |
| W17 | 节点卡运行互斥 | **互斥**：工作流节点运行期间，被引用技能卡**不可被手动运行、不可被其他工作流/运行引用**——跨卡运行锁，节点结算（成功 / 失败 / 被取消）后释放；同一工作流内同一张卡多次出现仍允许（串行执行，前一个节点释放锁后再跑后一个） | 需要跨卡锁登记（runner 内按卡 id 记录占用）；锁冲突一律 `run-in-progress` 拒绝、不排队 |
| W18 | 运行历史保留 | 每卡保留最近 **50 条**运行记录，超出删除最旧 | 存储增长有界 |
| W19 | 节点排序交互 | **拖拽排序**（与网格重排同一交互语言） | 实现较重（复用网格拖拽思路） |
| W20 | 触发空节点列表 | 技能卡触发时若目标工作流**无节点**：确认面板**即显示不可运行并禁止确认**（与直接运行时 WF-5 同一校验） | 触发路径多一次状态读取 |
| W21 | 触发确认面板摘要 | 展示目标工作流的**节点数与名称列表** | 字段固定，不展示各节点参数 |

## 4. 使用流程

**创建。** 用户在工作台网格末尾的「创建卡片」磁贴里选「工作流卡片」——这是网格里新增的第四种类型条目（技能卡片可用、工作流卡片**可用**、测试卡片与记忆卡片仍列出但禁用）。选类型就是全部交互，生成一张「工作流卡片 N」，用户在自己的配置页里命名。

**配置。** 打开工作流卡的配置页，只有两段：「基本信息」里是**名称**；「工作流」里是**节点列表**——从工作台上已有的技能卡里挑卡加入（按卡名/编号列出），可删除节点、可**拖拽调整顺序**（顺序即执行顺序）。同一步骤出现 2 次允许（同一张卡可以在流程里出现多次）。配置不触发任何模型调用。

**运行。** 打开工作流卡的结果页，点「运行」。宿主先做启动前校验（W9），不合格则拒绝并点名节点；合格则从第一个节点开始依次执行。运行中，结果页显示当前进行到第几个节点、每个节点的状态；主控件是「停止」——停止当前正在跑的节点，后续节点不启动，已完成的节点结果保留。

**观察。** 运行中的工作流卡正面显示运行中状态（聚合：只要有一个实例在运行即显示）。结果页下方是**运行历史**：每次运行一条，可点开查看该次的逐节点状态与最终输出。

**触发。** 任意技能卡的模板里声明 `key: workflow "工作流卡名称"` 的动作，结果区出现按钮；点击后弹出确认面板（展示目标工作流、节点摘要与整行数据），确认后**后台启动**该工作流一次，不做界面跳转；行数据注入首节点提示词。被点名的工作流卡若不存在或同名（查询到多个），点按钮即在确认面板报错，不执行（与既有 card 目标同一套规则）。

## 5. 功能需求

### FR-W1 工作流卡注册与创建

- `workbench.cards` 槽注册第二个类型条目（`workflow-card`），与技能卡条目并列。
- 「创建卡片」磁贴的类型清单新增第四项：**工作流卡片（可用）**，插在技能卡片之后、测试卡片之前（显式列出计划中但禁用的类型，规则沿用现有实现）。
- 创建即为新实例分配稳定且唯一的 id（沿用 `isWorkbenchCardId` 规则，如 `workflow-card-N`），默认名「工作流卡片 N」，用户在配置页改名；磁贴只做类型选择，不收集更多信息。

### FR-W2 配置：仅名称 + 节点列表

- 配置页两个字段：**名称**（沿用 `isWorkbenchCardName` 规则）与**节点列表**。
- 节点来源：**工作台上已创建的技能卡实例**（含默认技能卡），按卡名列出；选定后记录被引用卡的 **id**（不是名称，名称可改、id 稳定）。
- 节点操作：加入、删除，**拖拽排序**（W19，顺序即执行顺序）；同一技能卡可加入多次。
- 节点列表为空时：结果页「运行」不可用，给出引导去配置页添加节点。
- 保存节点列表不做引用解析——引用是否有效属于运行前校验（W9），配置期不拦截、不产生模型调用。
- 配置页改动通过工作流自己的存储域持久化，写入失败在页脚给出可读错误（与技能卡配置页同一套交互纪律）。

### FR-W3 节点引用完整性校验（启动前校验）

- 「运行」按下时，宿主校验每个节点：被引用技能卡**存在**、已**选择 skill**、有**模板**、有**工作目录**。
- 任一不合格：整次运行被拒绝，错误点名**所缺的节点与被引用卡**（机器码入错误码封闭联合，见 FR-W13），不启动任何节点。
- 运行控件与校验结果读同一个值：不合格时按钮禁用并说明原因，而不是"按下才报"。

### FR-W4 串行执行与节点运行语义

- 宿主按节点顺序逐个启动；**前一个节点结算（成功）后才启动下一个**。
- 每个节点 = 对被引用技能卡发起一次 **card 模式运行**：完全复用现有技能卡运行链路——提示词构建、`{ html }` 捕获、清洗、一次重试、取消与 `agent/error` 归因；运行使用**被引用卡自己的模型 / 工作目录 / 权限模式**（工作流卡不覆盖）。
- 节点的运行**不写回**被引用技能卡的存储（W11）：运行记录只进工作流的存储域。
- 节点执行对被引用技能卡**加运行锁**（W17）：节点运行期间，该卡**不可被手动运行、不可被其他工作流/运行引用**；锁在节点结算（成功 / 失败 / 被取消）后释放。锁冲突一律以 `run-in-progress` 拒绝、不排队——包括技能卡自己的手动运行入口。锁不写回被引用卡，其正面不显示"被工作流占用"，锁只影响启动判定。同一工作流内同一张卡多次出现仍允许：串行执行，前一个节点结算释放锁后再跑后一个。
- 运行能力依赖宿主提供 `subagents.startActivation` / 一次性 `start`：两条入口都没有时，「运行」不可用并写明原因，与技能卡同一降级（FR-W13 降级矩阵）。

### FR-W5 节点间传递：提示词级注入

- 非首节点启动时，宿主把**上一个节点结算后的结果 HTML**（清洗后的区间片段）追加为该节点提示词中的一段**只读上下文**（如 `上一节点输出（只读参考）：…`），并带明确边界。
- **不改模板**：不新增模板语法、不要求模板写标记；一条既有的、没写过任何提示语的模板照常可用（它只是不会主动利用这段上下文）。
- 注入体积上限 = 既有 `WORKBENCH_RESULT_MAX_BYTES`（64 KiB）——上一节点输出本身就是被该预算约束的存储值，注入不放大。
- 首节点没有上一节点：不注入；若本次运行由技能卡按钮触发且带行数据，则注入行数据（FR-W6）。

### FR-W6 触发参数：行数据注入首节点

- 技能卡按钮触发工作流时，把该按钮 `data-dsh-row` 的整行字段 JSON 作为**首节点**的输入上下文注入其提示词（只读，与 FR-W5 同一注入机制和边界）。
- 确认面板展示的载荷与运行收到的载荷逐字节相同（继承"参数全文展示"的既有纪律）。
- 非触发启动（用户直接在工作流卡上点「运行」）没有行数据可注入：首节点不注入。

### FR-W7 失败即停

- 任一节点失败（运行失败、被取消、校验通过但运行时被拒）：
  - 当前节点标失败，后续节点**不再启动**；
  - 已完成的节点状态与最终输出保留在本次运行记录里；
  - 工作流整体标记为失败/取消（区分：失败 vs 用户停止），结果页问题行说明原因。
- 「停止」= 取消当前正在运行的节点 + 放弃后续节点；已结束节点保留。

### FR-W8 运行实例与并发

- 同一张工作流卡**允许多个运行实例并发，单卡上限 3**（W16，可配置）：各自独立执行、独立记录、独立取消，互不干扰。
- 达到单卡上限后，直接「运行」与技能卡触发都被拒（`run-in-progress`，消息注明"该工作流已有 N 个实例在运行"）。
- 卡片正面状态为聚合语义：任一实例运行中即显示运行中。
- 节点卡的**互斥锁**见 FR-W4（W17）。

### FR-W9 结果记录与运行历史

- 每次运行独立落一条运行记录，含：运行卡 id、开始时间、结束时间/停止原因、逐节点条目（节点序号、被引用卡 id 与名称快照、开始/结束时间、状态：进行中/成功/失败/被取消、失败时的原因码）、**最终输出**（最后一个节点的结果 HTML，仅在成功时存在）。
- 中间节点的输出 HTML **不落盘**（W13）；运行记录同时保留**启动前校验结论**（哪一次运行因哪个节点被拒）。
- 结果页：当前运行实时视图（进行中：节点进度与状态）+ **运行历史列表**（按时间倒序，可点开查看该次运行的逐节点状态与最终输出）。
- 运行中实例的历史条目即时出现在历史里并随轮询更新。

### FR-W10 卡片正面

- 正面是索引（与技能卡同一外壳纪律）：卡片名称、节点摘要（如「N 个节点」）、运行中状态点（聚合、可选）、「配置」按钮。
- 点卡片本体进**结果页**（运行/停止在主控件位置、历史在其下）；点「配置」进**配置页**；X 是物理删除（连同配置与全部运行历史），任何位置不提供隐藏。

### FR-W11 技能卡动作触发工作流（新目标类型）

- `WorkbenchActionTarget` 扩展第三种目标：`{ kind: 'workflow'; name: string }`。
- 模板声明语法沿用现样式：`键: workflow "工作流卡名称"`；动作键文法、载荷体积上限、声明块位置与校验沿用既有规则。
- 目标解析与存在性检查：按**工作流卡名称**从工作流实例中查找——缺失列候选（已安装的工作流卡清单，此处为已创建的工作流实例）、**重名报错**（与既有 card 目标同一套规则）。
- 占用检查：**不**因目标工作流卡已有运行实例而拒绝（W15，区别于 card 目标"运行中立即报错"），但受**单卡并发上限 3** 约束（W16），达到上限被拒；目标工作流**无节点**（W20）或首个节点被其他运行占用（W17）时，确认面板**显示不可运行并禁止确认**。
- 执行：确认后**后台启动**该工作流一次（W5），不跳转界面；把按钮行数据作为首节点输入（W6）。
- 失败语义沿用动作层纪律：未声明的键不执行、解析失败报错不执行、确认面板取消无副作用。

### FR-W12 持久化与新鲜度

- 工作流卡的配置（名称、节点列表）与运行记录（W9）持久化在工作流自己的存储域；坏记录 `backup-and-skip`，不阻塞工作台启动。
- 打开工作台 / 打开工作流卡 / 翻历史：**纯存储读，零模型调用**；只有「运行」、技能卡按钮触发会启动节点运行并产生模型调用。

### FR-W13 错误码与降级矩阵

- 新增错误码进既有封闭联合，供路由状态表、客户端本地化表与卡片文案表各自表态（"漏一个编译不过"由 `Record<码, …>` 类型保证）：
  - `workflow-node-invalid`：启动前校验发现节点不可运行（点名节点与被引用卡）；
  - `workflow-no-nodes`：工作流没有节点；
  - `workflow-target-not-found` / `workflow-target-ambiguous`：技能卡触发的目标工作流缺失或重名；
  - 复用：`run-unavailable`（无 run seam）、`run-in-progress`（达到单卡并发上限 3、或节点卡被其他运行占用）、`session-not-live`、`provider-unavailable` 等。
- 降级矩阵（与技能卡一致的精神，逐条列出见验收标准）：坏记录不拖垮工作台、单节点失败只影响该次运行、双 run seam 都没有时工作流照常可编辑但「运行」不可用、被引用卡运行中被手动删除（配置期不拦截，运行前校验拦截）。

### FR-W14 删除语义

- 删除工作流卡 = 物理删除该卡的配置与**全部运行历史**。
- 删除被引用的技能卡：**不**阻止删除工作流卡（配置保留，引用悬空）；触发运行前校验失败并点名节点（W9）。配置页给出节点失效提示（可读、不拦截保存）。

## 6. 明确不做

- **不做并行节点、条件分支、循环重试**：v1 只有顺序执行，每个节点恰好跑一次。
- **不做工作流嵌套**：节点只能引用技能卡，不能引用工作流卡；定义层面因此不存在环，也不需要运行期环检测。**运行时递归防护同样不做**：技能卡按钮触发工作流、该工作流又包含那张技能卡时，只受单卡并发上限 3 与节点卡互斥锁（W16/W17）两道闸约束，无人做递归检测（见 §10）。
- **不传结构化字段**：v1 传递载体只有 HTML 片段；"一段数据"用 HTML 表格/文本表达。
- **不改模板语法**：节点间传递是提示词级注入；不引入模板内标记（如 `<!-- dsh-input -->`），不复活占位符语法。
- **不做节点级参数覆盖**：工作流卡不覆盖节点卡的模型/目录/权限；也没有节点级"传给下一节点的字段名"配置。
- **不做节点结果的自动写回**：工作流独立存结果；被引用技能卡的存储不被工作流运行触碰。
- **不做定时执行 / 自动触发 / 跨工作流编排**。

## 7. 非功能需求

| 项目 | 要求 |
| --- | --- |
| 成本 | 一次工作流运行的成本 = 各节点模型调用之和；打开工作台 / 打开卡片 / 翻历史零模型调用 |
| 性能 | 串行执行，总时长 = 各节点之和；节点运行的活动流水照常上总线（复用技能卡链路）；不做全局轮询，运行状态随既有轮询返回 |
| 容量 | 每个节点输出受 `WORKBENCH_RESULT_MAX_BYTES`（64 KiB）约束，注入不放大；工作流记录体积受整体预算约束；单卡并发上限 3（W16）、节点卡互斥锁（W17）、运行历史每卡保留最近 50 条（W18），成本与存储增长均有界 |
| 隔离 | 注入内容为只读上下文，向上游的技能卡注入时不携带可执行内容（注入发生在提示词层，不改变清洗与渲染路径） |
| 权限 | 节点运行完全沿用被引用技能卡自己的权限模式与工作目录；工作流不提供新的运行入口或权限绕过 |

## 8. 失败与降级矩阵（要点）

| 情形 | 行为 | 兜底 |
| --- | --- | --- |
| 节点引用的技能卡被删除 / 未配置模板 / 无工作目录 | 运行前校验拒绝，点名节点，不启动 | 配置页显示失效提示（不阻塞保存） |
| 工作流无节点 | 运行控件禁用并引导去配置 | — |
| 双 run seam 均不可用 | 工作流可编辑可读，运行控件禁用并写明所需版本 | 绕过界面调运行路由返回 `run-unavailable` 说明 |
| 某一节点运行失败 | 该节点标失败，后续节点不执行，整体终止 | 已完成节点状态保留 |
| 用户停止 | 取消当前节点，后续不执行 | 已完成节点保留 |
| 触发目标工作流缺失 / 重名 | 按钮点击在确认面板报错，不执行 | — |
| 本卡单条坏记录 | 存储域 `backup-and-skip`，不影响工作台与其他卡片 | 可读错误，不白屏 |

## 10. 风险与已知限制

- **提示词级注入的不可预期性**（W7 的代价）：上一节点的输出进的是上下文，模型可能忽略、截断或误用它；"模板决定呈现"的契约无法约束注入结果。缓解：注入带明确边界与只读标注、结果仍由各节点模板的区间承载；若实测达不到可用性，后续版本再引入模板内标记（v2 候选，不在本文承诺内）。
- **中间产物不可回看**（W13 的代价）：只存逐节点状态与最终输出，需求设计卡的产出在运行结束后只能从"再跑一次"或该卡自身手动运行获得。若需要"每个节点输出都可回看"，属后续版本增量。
- **并发以内有成本、跨卡串行**（W10/W15/W16/W17 的代价）：单卡上限 3 与节点卡互斥锁避免了"同一张卡被同时多跑"，但**不同工作流卡的并发叠加、以及上限 3 以内的叠加**仍无全局配额；运行时"技能卡触发含它的工作流"类循环只受上限与互斥闸约束，无人做递归检测。均为本版明确接受，见 §6。
- **结果双份不一致**（W11 的代价）：同一张技能卡手动跑出的结果与经工作流跑出的最终输出相互独立，用户需理解二者不自动同步。

## 12. 待确认项（已全部确认）

初版列出的 6 个待确认项已在需求沟通第四轮全部确认，结论收进决策汇总 **W16–W21** 与相应 FR；此处留档原始问题与最终结论，防止后续误当作开放项。

| # | 原始问题 | 最终结论 | 落点 |
| --- | --- | --- | --- |
