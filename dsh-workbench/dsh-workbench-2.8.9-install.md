# dsh-workbench 2.8.9

## 这一版修的是「改了技能，模板就被清空了」

现象：在流水线某一步把「技能」从 A 改成 B，下面「模板」立刻变成
「这张卡片还没有模板。先给它写一个 HTML 模板。」——原来的模板看起来没了。

### 原因

模板是按「卡片 + 技能」两段存的（`template` 表的主键是 `卡片ID_技能名`，
`skill-card-5_manim-explainer.json` 这种文件名就是它）。读取时只取「当前技能」那一行：

```ts
const template = selected === undefined ? undefined : bySkill?.get(selected)
```

于是技能一换，当前技能还没有属于自己的一行，卡片读出来就是「没有模板」。
旧模板其实还在库里（`templateSkills` 里列着），只是**界面不给你看**，所以观感就是被清空。
改动本身的意图是好的——换回原技能能拿回自己那一份——但它让「改技能」变成了破坏性操作。

### 这一版的做法（都在存储层，两处客户端入口都自动受益）

1. **换技能时把模板带过去**：一次写入里，先给新技能写一份当前模板的副本，再改选中技能
   （顺序和「模板先落、选中后落」的既有约定一致，中途失败也不会出现「选中了技能但模板空着」）。
   新技能**本来就有**自己模板时不覆盖；显式写模板（用户在源码框里编辑）永远优先，不会被带过去的副本盖掉；
   卡片模板数已达上限时不新增，选中照常生效。
2. **读取时不再因为「这一对没有」而装作没有**：当前技能的行走第一，没有就按技能名取这张卡片
   已有的第一行显示。卡片已经因为上一版被「换空」的，重开页面就恢复原样，不用再切回去切回来。

两条规则相同：**模板属于卡片，技能只是它当前服务的那一份历史。** `templateSkills` 继续记录
哪些技能各有一份，切回去仍拿到自己那份。

### 验证

- `skill-card-store.spec.ts` 新增 5 个用例：换技能带走模板（含写入顺序）、新技能已有模板不被覆盖、
  清空选中后再选新技能仍能带过去、从未有过模板的卡片不多写一行、达到模板上限时不新增。
- 两个旧用例按新语义更新（「无选中时也显示卡片持有的模板」）。
- 全量 gate：**1047 passed / 3 skipped（1050）**，构建与产物校验通过。

## 安装

```
profile: %APPDATA%\dsh-desktop\harness\profiles\web
pin:     file:F:/git/Personal-Workbench/dsh-workbench/dsh-workbench-2.8.9.tgz
```

已解包覆盖 profile 的 `node_modules\dsh-workbench`，pin 指向 2.8.9。**完全退出应用再打开**。
打开后那张「技能已改成 xiaoneng-task-detail、模板空着」的卡片，模板会自己回来；
之后再换技能，模板都跟着走。
