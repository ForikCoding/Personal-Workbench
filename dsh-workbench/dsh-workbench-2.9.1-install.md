# dsh-workbench 2.9.1

## 这一版改的是「你点的单步执行，界面上不算数」

两处都出在同一个地方：**谁来决定「这是整条跑的，还是这一步单独跑的」**。

### 一、一步的流水线，单步跑完被读成了整条跑完

`需求到交付` 只有 1 个步骤。点「单独运行」跑完以后，代码按「这次运行盖住了几步」判断它是不是
整条运行——1 个步骤的流水线，单步运行当然盖住了全部 1 步，于是它被当成整条跑完，胶囊会说
`已完成`。原型里根本不是这么判的：原型看的是**这次运行被要求跑什么**，不是它碰到了几步。

现在链自己带着这件事：`整条` / `单步` / `重新生成` 三个值之一，标题旁的胶囊、运行条、步骤脚注
都读它。1 个步骤的流水线，单步跑就是 `单步跑过`（描边），点「运行」才是 `已完成`（实心）。

### 二、重开面板以后，跑过的步骤变成「已有结果」

运行记录只活在当前页面里（这是原来的限制）。页面一重开，记录没了，面板只剩「这一步有结果」，
于是说 `已有结果`——你明明刚点过单步执行，它却像在说「我不知道这是怎么来的」。

现在**产物自己记着自己是怎么来的**：运行请求把 `单步 / 整条` 一起发过去，Host 存进这一步的结果记录里
（`pipeline: { id, step, scope }`）。重开面板后，即使运行记录不在了，结论照样能读出来：

- 这一步的产物来自单步运行 → `单步跑过`，脚注写 `单步`（拿不到运行号就不编一个）；
- 每个步骤的产物都来自整条运行 → `已完成`；
- 整条运行里失败的那一步 → `失败`；
- 什么都没有、也没有出处（比如这一步是在卡片自己的页面里跑的） → 才说 `已有结果`。

也就是说 `已有结果` 不再是「记录丢了」的代名词，只剩「确实不知道」。

### 验证

- `pipeline-view.spec.ts` +4：1 个步骤的流水线单步跑过是 `solo` 不是 `done`；产物都说整条跑过才是
  `done`；整条运行里失败的那步算 `failed`；整条之后又单独重新生成过一步时不冒充 `done`。
- `WorkbenchPage.spec.tsx` +1：只有结果、没有运行记录的面板，产物写着 `scope:'single'` 时胶囊是
  `单步跑过`、段是描边、脚注是 `单步`、运行条报从第 1 步重跑；另外 3 个原有断言更新为请求里带上 scope。
- `skill-card-runner.spec.ts` +2：单步运行的记录里带 `{id, step, scope:'single'}`；重新生成的记录带
  `scope:'refine'`（不能冒充整条）。
- `skill-card-spec.spec.ts` +1：schema 声明了 `pipeline`，存取一轮不丢。
- `skill-card-route.spec.ts` +1：`scope` 只接受 `full` / `single`，别的值 400。
- 全量 gate：**1073 passed / 3 skipped（1076）**，类型检查、构建、产物校验通过。

### 一处要说清楚

你截图里那个已有的结果，是在这一版之前跑出来的，它的记录里没有出处，所以打开还是 `已有结果`。
再点一次「单独运行」（或「运行」），这一步的产物就带上出处了，之后无论怎么重开都是对的。

## 安装

```
profile: %APPDATA%\dsh-desktop\harness\profiles\web
pin:     file:F:/git/Personal-Workbench/dsh-workbench/dsh-workbench-2.9.1.tgz
```

已解包覆盖 profile 的 `node_modules\dsh-workbench`，pin 指向 2.9.1。**完全退出应用再打开**。

打开后：`需求到交付` 里点「单独运行」，跑完胶囊应是描边的 `单步跑过`，脚注 `单步 #1`；
关掉面板再打开，它还是 `单步跑过`（脚注变成 `单步`）。
