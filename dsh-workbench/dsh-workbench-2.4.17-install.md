# dsh-workbench 2.4.17 — 编辑取消后，回到你原来站的地方

## 为什么跳到最上面

文档是几千像素的模板输出，编辑器只有一个固定高度的窗格。点「编辑」的时候，React 把整篇文档换成那个窗格，**页面高度从几千像素掉到一屏**，浏览器只能把滚动位置夹到还能存在的地方——顶部。等你取消，文档又长回来了，可滚动位置还停在顶部，于是你要重新滑过整篇文档才有运行按钮。

另外还有一个同类的丢失：从「从头跑」点进「编辑」，取消后回到的是「在上一版上改」——你刚才选的那一种没了。

## 改了什么

**1. 记住你在看哪里，回来还给你。**

进编辑之前（在点击的那个瞬间，文档还在的时候）记下**操作区在屏幕上的位置**；编辑结束、文档回到布局里之后，按这个位置把滚动条放回去。

记位置而不是记数字，是因为编辑可能改变文档高度：文档高了 400px，就必须多滚 400px，操作区才会回到原来的位置。恢复算的是「这个块应该在哪」，不是「上次滚了多少」。

具体做法：

- `src/client/skill-card/scroll-hold.ts`（新）
  - `scrollBoxOf`：从页面往上找真正在滚的那个容器（不是 window，是外壳的滚动容器），找不到就退到文档本身。
  - `holdScroll`：记下滚动偏移 + 锚点在屏幕上的位置。
  - `releaseScroll`：按锚点算出该滚到哪，夹在 `[0, max]` 之内写回去。**幂等**——同一份 hold 跑两次结果一样，因为页面的第二帧还会再校正一次（防止文档是分帧长出来的）。
- 结果页在 `setEditing(true)` 时取 hold，在 `editing` 真→假的那次提交里恢复（`useLayoutEffect`，画之前就位，不会闪一下），下一帧再补一次；页面一旦变化就取消那一帧，免得你已经自己滚走了还被拽回来。

**2. 取消后回到你刚才选的那一种。** 进编辑时记住是「在上一版上改」还是「从头跑」，出来还给它。

## 边界

- 进编辑的时候仍然会跳到顶部——编辑器就在那儿，这是想要的。
- 没有结果、或者正在跑的时候没有编辑入口，所以不会取 hold。
- 文档高度变了（保存过一次编辑）也能对齐：锚点法按新高度算。

## 验收

1. 把结果页滚到底，点「编辑」→ 页面到顶（正常，编辑器在那儿）。
2. 点「取消」→ 回到你刚才的位置，操作区还在眼前，不用再滑。
3. 先切到「从头跑」，再点「编辑」，取消 → 回来还是「从头跑」。
4. 编辑里改点东西保存（让文档变高或变矮）→ 操作区仍在原来的屏幕位置。
