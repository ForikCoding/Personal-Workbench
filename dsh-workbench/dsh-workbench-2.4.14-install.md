# dsh-workbench 2.4.14 — 跳转没滚动，是因为那块编辑区从来没滚动过

你看到的现象是对的：跳转只把光标移过去、选中那一行，滚动条一动不动。原因不在跳转，在编辑区本身。

## 根因

模板面板是个 grid，第一行写的是 `minmax(0, 1fr)`。在一个**高度由内容决定**的 grid 里，`1fr` 没有东西可分，这一行就长到了内容的完整高度：

```
clientHeight = 5556   ← 编辑框自己就是 5556px 高
scrollHeight = 5556
可滚范围     = 0
```

也就是说：**编辑框不是滚动容器，整页才是。** 三百行的模板把编辑框撑成五千多像素，页面上那条滚动条是页面的。`scrollTop` 设上去被夹到 0，所以「跳转」只能移动光标与选区，没有任何盒子可以滚。同一份测量也解释了别的怪现象：行号栏同样被撑到五千像素（`overflow: hidden` 但它自己也不需要滚），所以行号和代码在长文档里其实一直是对齐的、只是整页一起滚。

## 改法

1. **把那一行的高度写出来**：`grid-template-rows: clamp(280px, 44vh, 560px) auto`。编辑框和行号栏从此填满这一行，内容超出就在**框内**滚动，页面回归页面。
   - 行号栏与代码同步滚动（本来就有同步代码，只是一直没有可滚的东西）。
   - 折叠视图用同一行高：两个视图一样大，才像一个面板。
   - 「详细设计 / 结果文档」用的也是这个面板，同样受益。
   - 顺带去掉 `resize: vertical`：它只把高度写到自己身上、被面板裁掉，是个会破坏自己布局的把手。
2. **跳转落点**：目标行放在**编辑框顶部往下两行**，而不是居中——编辑框可能比窗口里可见的那部分更高（保存条压在它脚上），居中的行会落在没人看的地方。落点在下一次重绘后再设一遍，防止浏览器的「把光标带进视野」把我们挪开；若编辑框本身没有可滚范围（它长到装下了全文），则改为滚动窗口。

改后同一份测量：

```
clientHeight = 334    scrollHeight = 5566
scrollTop    = 1818   行号栏 scrollTop = 1818
目标行 104 落在编辑框顶部第 3 行，整行选中
```

## 验收

1. 模板编辑框现在是一个固定高度的框（大约窗口高度的 44%），**它有自己那条滚动条**；页面不再变成一条五千像素的长带子。
2. 把编辑框滚到别处，点「跳转到模板」：框内滚动到区间标记那一行，并把它选中、停在框顶往下第三行的位置。
3. 行号栏跟着一起滚动，行号与代码始终对齐。
4. 折叠视图和编辑框一样高，各自在框内滚动。
