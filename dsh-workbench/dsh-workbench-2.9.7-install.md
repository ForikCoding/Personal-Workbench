# dsh-workbench 2.9.7 安装说明

本版加一件事：**跑起来之后能停下来**。

## 为什么

原型上「运行」按钮在跑起来之后就是「停止」，代码里一直没落地：

- 面板头上那颗「运行」跑起来之后只是变灰，停不下来。
- 步骤的「单独运行」同样，只能看着它跑完。
- 运行条右下角原来有个「停止」，但它只做到**不再看这一跑**：把轮询的等待放弃掉，子 agent 还在跑，跑完照样把产物写进结果。也就是说按了停止，活没停。

Host 那边其实早就齐了：runner 有 `cancel(cardId, runId)`，路由有 `DELETE`，客户端 api 有 `cancel()`。缺的是前端那颗按钮从来没调过它。

## 改了什么

**停的是活，不是眼睛。** `pipeline-run.ts` 的 `stop()` 现在：

1. 记住的「正在跑的那次运行」（卡号 + 运行号，start 被 Host 接受的那一刻记下）。
2. 调 `api.cancel(cardId, runId)` —— 请 Host 取消这一次运行。
3. 链子**不**再自己 abort：被取消的运行会在下一次轮询里报 `cancelled`，链子就是从这里知道它结束了。这样「停下来了」这句话是运行说的，不是前端替它说的。
4. 一次运行只停一次；Host 一直不认账时（5 秒）才放弃等待，免得面板永远停在「正在停止」。

**正在停止** 是新增的一档 `ChainPhase`：按下到落地之间，按钮和运行条都说「正在停止」，因为那一跑确实还在跑。

**一个运行只有一个停止键，而且就在启动它的那颗按钮上**：

| 跑的是什么 | 停在哪 |
| --- | --- |
| 整条流水线 | 面板头那颗「运行」变成「停止」 |
| 单独一步 | 这一步的「单独运行」变成「停止」 |

两颗都是同一位置、同一宽度（「运行」和「停止」都是两个字），只换记号（三角 → 方块）和描边。整条在跑时，步骤那颗是灰的、title 写着「整条正在运行 · 停止在右上角」；单独一步在跑时，面板头是灰的、title 写着「这一步正在单独运行 · 停止在它自己的按钮上」。**运行条右下角那个停止删了**，那条只说跑到哪了。

颜色只描一圈红（`color-mix(危险色 42%, 分隔线)`），不填实心：跑着是正常状态，不是错误。任务是错误。

**停下之后的语法**：被打断的那一步是「已停止」，它后面没轮到的步骤退回「待运行」（原来是「排队中」——排队是「有人会来启动我」的承诺，停了之后没人会来）。运行条说「第 N 步停在半路 · 点「运行」从第 N 步接着跑」，N 和重跑的起点是同一处算出来的，两句话不会互相矛盾。

## 安装

1. **完全退出 DSH Desktop**。
2. 解包覆盖（robocopy 返回 1 正常，最后那句 copy 不能省）：

```
tar -xf dsh-workbench-2.9.7.tgz -C %TEMP%\wb-stage-2.9.7
robocopy %TEMP%\wb-stage-2.9.7\package "C:\Users\hspcadmin\AppData\Roaming\dsh-desktop\harness\profiles\web\node_modules\dsh-workbench" /MIR
copy /Y %TEMP%\wb-stage-2.9.7\package\package.json "C:\Users\hspcadmin\AppData\Roaming\dsh-desktop\harness\profiles\web\node_modules\dsh-workbench\package.json"
```

3. profile 的 pin 指向 `dsh-workbench-2.9.7.tgz`。
4. 重新打开 DSH Desktop。

## 怎么验

进流水线 → 点「运行」→ 面板头那颗应该变成描一圈红的「停止」（记号是方块）→ 点它 → 按钮先变「正在停止」，一秒左右变回「运行」，运行条说「第 N 步停在半路 · 点「运行」从第 N 步接着跑」，被打断那一步写「已停止」，后面的写「待运行」。

再验一次「真的停了」：停完之后去活动面板，子 agent 不应该再往下写新的活动；等一会儿刷新，那一步也不应该突然多出产物。
