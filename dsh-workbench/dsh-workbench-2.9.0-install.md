# dsh-workbench 2.9.0

## 这一版改的是「整条流水线的状态」——按原型实现

原型 `docs/prototypes/workbench-pipeline-v2.html` 已经把这件事写清楚了，这一版把代码改成
同一个说法。原来的问题就是你在截图里画红框的那处：一个步骤「单独运行」跑完了，卡片上写
`已完成`，而标题旁写着 `0 待运行`、下面一行写「还没整体跑过」——同一条流水线在三处说了三种话。

### 一条规则

**整条的状态只有一个来源**（这一次面板里跑的那条链，以及它的运行记录），
运行记录只负责把「没整条跑过」分成两档。步骤的状态还是步骤自己的事。

| 标题旁的字 | 什么意思 |
| --- | --- |
| `未整体运行` | 一步都没启动过 |
| `单步跑过` | 跑过的那几步都是**单独**跑的，整条没跑过 |
| `已有结果` | 步骤上有结果，但这次打开面板没有任何运行记录（比如重开应用后）——不去猜「整条跑没跑过」 |
| `运行中` / `已完成` / `失败` / `已停止` | 整条在跑、整条跑完、整条失败、整条被停 |

**实心 = 整条跑过，描边 = 只单独跑过其中几步。** 这条形状规则用在四个地方：标题旁的小点、
状态胶囊、运行条的每一段、步骤卡脚注上的运行号（`#4` 是整条跑的，`单步 #4` 是单独跑的）。

### 运行条不猜，它说的就是引擎会做的

- 一步都没跑：`未整体运行 · 3 步都还没启动 · 点右上角「运行」按顺序跑完`
- 只单独跑过第 1 步：`整条还没跑过 · 第 1 步单独跑过 · 点「运行」从第 2 步接着跑`
- 每一步都有结果：`… · 点「运行」会从头再跑一遍`
- 跑完：`2 步全部完成 · 用时 1m 08s`

「从第几步接着跑」这句话不再由界面自己算：**按「运行」真的从第一步没结果的那一步开始**，
而且这一步会接上它前一步那次运行的会话（同一个面板里跑过的话）。原型的这条承诺和引擎用的是
同一个函数，所以两处不会再说两套。

### 顺带修掉的三处

- 标题旁那枚状态胶囊一直没带 `data-s`，所有按状态上色的规则其实是死样式——它永远是灰的。
  现在它有了，`单步跑过` 才真的是描边绿，`已有结果` 是描边灰。
- 运行记录里每行的状态原先直接印着引擎内部词 `settled`。现在写 `成功` / `失败` / `运行中` / `已停止`，
  并且一行就能看出这次跑的是整条还是某一步（`仅 A card` / `A card → B card`）。
  打开某次运行，抬头一行是 `时间 · 跑了什么 · 用时 · 结果`。
- 标题下面那行在没有任何运行记录时不再重复状态（原来是「… · 还没跑过」，和胶囊打架），
  只说 `N 个步骤 · 串行执行，失败即停`。

### 验证

  只有结果没有记录时胶囊是 `已有结果`。

## 安装

```
profile: %APPDATA%\dsh-desktop\harness\profiles\web
pin:     file:F:/git/Personal-Workbench/dsh-workbench/dsh-workbench-2.9.0.tgz
```

已解包覆盖 profile 的 `node_modules\dsh-workbench`，pin 指向 2.9.0。**完全退出应用再打开**。

打开后：先「单独运行」某一步，标题旁应是 `单步跑过`（描边），运行条会说从第几步接着跑；
再点「运行」，它从那一一步之后接着跑，跑完标题旁变成 `已完成`（实心，绿）。
点标题下面那行打开运行记录，每条都写清跑了什么、用时多久、成没成。
